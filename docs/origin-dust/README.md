# ORIGIN DUST

웹툰 프로젝트. **이 디렉터리가 프로젝트 루트다.**

앱을 구현하는 프로젝트가 아니므로 `projects/` 아래로 가지 않는다. `projects/*`는 런처가 빌드해 배포하는
정적 아티팩트 전용이라 `app/` 빌드를 강제하고(`scripts/build-project.ts`), `project.json`이 없으면
`pnpm sync:registry`가 ENOENT로 죽는다(`scripts/project-utils.ts`의 `readAllProjects`가 모든 하위
디렉터리에서 `project.json`을 읽는다). 둘 다 `pnpm build:vercel`을 깨뜨린다.

## 평가 자산의 성격

`00-rubric.md`는 ORIGIN DUST를 첫 소비처로 삼지만 작품 설정에 묶여 있지 않다. 한국어 서사 원고면 무엇이든 잰다.
다른 작품이 생겨 공유할 필요가 서면 그때 `docs/kb/`로 올린다 — 쓰는 곳이 하나인 동안은 여기 둔다.

컨셉 단계를 다루는 [`../kb/concept-planning/`](../kb/concept-planning/)이 "이 기획이 될 물건인가"를 묻는다면,
이 자산은 "이 원고가 독자를 다음 화로 데려가는가"를 묻는다.

## 상속과 차이

상위 자산은 `buildon99x/omc-ws` → `.claude/skills/max-writing/`이다(설득문 14축 루브릭·한국어 문장 위생·골드셋 12종).
거기서 **문장 위생 축과 블라인드 채점 절차를 그대로 가져왔고**, 설득문 전용 축인 `제목·소제목의 힘`과 `스캔성`은 버렸다.

버린 근거는 max-writing 자신의 실측이다. 그 저장소의 `examples/12-fiction-opening-draft/review-pass1.md`에서
현진건 「운수 좋은 날」은 평균 4.00, 김유정 「동백꽃」은 3.86을 받아 AI 초안(4.29)에 밀렸다.
소제목이 없고 문단 분절이 없다는 이유였다. **스캔되는 소설은 실패한 소설이다.**
같은 텍스트가 `00-rubric.md`에서는 4.67·4.50을 받고, 같은 AI 초안은 4.21로 미수렴 판정을 받는다
(`03-example-novel-blind.md` §8).

## 운용 규칙

- 평가 도구는 `00-rubric.md` 하나다. 다른 기준으로 원고를 판정하지 않는다.
- **작성 ≠ 리뷰.** 자기가 쓴 원고를 자기가 채점하지 않는다. 결정 점수는 원고를 쓰지 않은 별도 컨텍스트에서 나온다.
- 채점 전에 §2의 M1(회수 문장)·M2(이탈 표시)·M3(화자 가리기)를 먼저 측정한다. 점수보다 이 셋이 먼저다.
- 판단할 근거가 원고에 없는 축은 점수 대신 `–`를 쓰고 평균에서 뺀다. 짐작으로 3점을 주면 평균이 거짓말을 한다.
- 고치는 순서는 구조(축1·3·4·6) → 연출(축11~14) → 문장(축9·12)이다. 뒤집으면 다듬은 문장을 버리게 된다.
- 모든 패스를 `05-loop-ledger.md`에 기록한다.

## 예시를 늘릴 때

- 소설 good 예시는 **공개도메인 원문 verbatim**만 쓴다. 출처 URL과 저작권 상태를 반드시 적는다.
- 연재 중인 웹툰·웹소설의 본문을 나쁜 예로 인용하지 않는다. 웹툰 예시는 창작 콘티로 쓰고 그 사실을 명시한다.
- 예시를 추가하면 어느 축을 시연하는지 태그를 달고, 짝이 되는 bad 예시를 같이 넣는다.
