# Space Waves

입력 하나에서 중립 상태를 제거해 33레벨 분량의 난이도 공간을 만든, 추출형 원버튼 회피 아케이드. Optimization 축이 완전히 비어 있고, 그 공백이 로그라이크 접목의 정확한 표적이다.

## 전제 — 분석 대상 확정

`space wave`는 동명 게임이 여럿이라 먼저 대상을 못 박는다.

- **본 분석 대상:** Space Waves — Xelluf 개발, do.games 배급, 2024년 4월 웹 출시. 원버튼 사이드스크롤 회피 게임. 웹 33레벨 / 모바일 80+ 레벨. `[해석:합의·T3]`
- **동명이인 주의:** Steam app 1808140의 `Space Waves`는 별개 게임(프로시저럴 2D 아케이드 슈터)이다. 검색 시 두 게임이 뒤섞여 나오므로 인용 전 확인이 필요하다. `[체감·T4]`
- **또 하나의 혼동:** "space wave"를 *웨이브 단위로 적 편대가 몰려오는 우주 슈팅*으로 읽는 관용도 있다. 그 해석을 택할 경우 본 문서의 Mechanics·Interface 절은 적용되지 않지만, [순설계 이식](#순설계-이식--로그라이크-접목) 절의 루프 설계와 Contract 분석은 그대로 유효하다. 비교군에 Nova Drift·Brotato를 넣어둔 이유다.

시점은 **2026년 9월 기준**이다.

## Core info

- **출시:** 2024.04 웹(브라우저) → 2025.09 모바일 앱(CrazyGames 배급) `[해석:합의·T3]`
- **개발·배급:** Xelluf(개발) / do.games·CrazyGames(배급) `[해석:합의·T3]`
- **규모:** CrazyGames 평점 8.6/10, 투표 120만+ `[집계-B]` · 구글플레이 다운로드 500만+ `[집계-B]` · 앱스토어 4.65/5, 평가 2.6만 `[집계-B]`
- **가격 모델:** 무료. 포털 광고 + 앱 배포. 유료 판매 없음
- **게임 유형:** 웹 F2P-광고형 (패키지도 라이브 서비스도 아님)
- **장르:** 원버튼 정밀 회피 아케이드. Geometry Dash의 Wave 게임모드를 단독 게임으로 추출한 파생 장르 `[해석:개인]`
- **플레이 유형:** Solo · 비동기 경쟁 거의 없음 · 웹/모바일 · 1회 시도 10~60초의 초단기 세션
- **Design pattern:** **극도 집중형** — Challenge·Submission 2축에 전부 투자

> **수치 정의 주의:** CrazyGames의 "투표 120만"은 플레이 수가 아니라 평점 투표 수이고, 구글플레이 "다운로드 500만+"는 MAU가 아니다. 플랫폼과 정의가 달라 두 수치는 합산할 수 없다. 규모의 하한을 보여줄 뿐이다.

## MDA layers

### Blueprint

네온 기하 추상. 서사 0, 캐릭터 0, 세계관 0. 플레이어 아바타는 화살표 하나다. "space"라는 명명과 별 배경이 있을 뿐, 체감되는 것은 우주가 아니라 **기하학과 리듬**이다 — 브랜딩과 체감이 어긋나는 철학 역전의 사례다.

이 비어 있음은 결함이 아니라 선택이다. 회피 게임에서 서사는 시선을 뺏는 비용이고, 이 게임의 숙련은 *시선을 어디에 두느냐*에 달려 있다.

### Mechanics

| 메커닉 | 속성 |
|---|---|
| 단일 입력 | 홀드 = 대각 상승, 릴리스 = 대각 하강. 마우스 좌클릭 / W / Space |
| **중립 부재** | 손을 떼도 정지가 아니라 하강. 모든 프레임이 입력 결정 |
| 자동 전진 | 수평 속도 고정. 플레이어가 제어할 수 없음 |
| 1히트 즉사 | 벽·스파이크·회전 기어 접촉 시 즉시 사망 |
| 즉시 재시도 | 사망 → 재시작 약 0.5초. 로딩·점수 요약·메뉴 전환 없음 |
| 수제 레벨 | 웹 33 / 모바일 80+. 절차적 생성 아님 |
| 전면 해금 | 모든 레벨이 처음부터 열려 있음. 순차 강제 없음 |
| 와일드 모드 | 규칙 변형 모드 |

**이 게임의 단 하나의 설계 결정은 "중립 상태를 주지 않는다"이다.** 홀드하면 올라가고 놓으면 내려간다 — 가만히 있는 선택지가 없다. 그래서 입력이 하나뿐인데도 플레이어는 매 순간 결정을 강요당하고, 갭의 높이·폭·간격만 바꿔도 난이도가 무한히 확장된다. 입력 개수를 늘리지 않고 난이도 공간을 얻는 메커닉 경제성의 모범이다.

### Interface

HUD가 거의 없다. 진행 표시 정도이고 체력도 점수도 화면에 상주하지 않는다. 오디오가 장애물 배치와 동기화되어 있어 **음악이 사실상 두 번째 UI**로 기능한다 `[체감·T4]`.

화면 정보량이 적은 것은 취향이 아니라 요구사항이다. 숙련된 플레이는 아바타가 아니라 2~3개 앞 갭을 보는 데서 나오므로, 시선을 끄는 요소를 추가하는 순간 난이도가 의도치 않게 올라간다.

## Dynamics

### 시간 스케일 루프

**초 스케일 — 갭 통과 루프 (0.2~1초)**
```
갭 진입 각도 판단 → 홀드 길이 결정 → 통과 또는 접촉
```
이 게임의 실질 전부. 결정 주기가 1초 미만이라 의식적 계산이 아니라 패턴 인식으로 처리된다.

**시도 스케일 — 재시도 루프 (10~60초)**
```
레벨 시작 → 주행 → 사망 → 0.5초 후 재시작
```
실패의 감정 비용을 0에 가깝게 만든 구간. 즉사 장르의 고질적 이탈 문제를 "벌을 줄이는" 방식이 아니라 "벌을 없애는" 방식으로 해결했다.

**레벨 스케일 (5~30분)**
한 레벨 클리어까지 수십~수백 시도. 여기서 근육 기억이 형성된다.

**세션 스케일**
레벨이 전부 열려 있어 막히면 다른 레벨로 이동할 수 있다. 좌절 이탈은 줄지만, *막힌 레벨을 끝내 깨는 서사*는 약해진다.

**메타 스케일 — 부재**
레벨 클리어 기록 외에 계정에 축적되는 것이 없다. **이 공백이 본 분석의 핵심 발견이다.** 실력이 늘어도 남는 것이 없으므로 이탈 후 복귀 동기가 구조적으로 0이다.

### 창발 현상

1. **짧은 탭으로 중립 합성** — 긴 홀드 대신 짧게 연타하면 지그재그 진폭이 작아져 사실상 직진에 근접한다. 디자이너가 제거한 중립 상태를 플레이어가 입력 기술로 재발명한 것이다. 이걸 막지 않은 것이 이 게임 숙련 곡선의 실질적 상단을 만든다. `[체감·T4]`
2. **시선 선행** — 아바타를 보면 못 깨고, 2~3 갭 앞을 보면 깨진다. 숙련의 본체가 손이 아니라 **시선 배치**에 있다. `[체감·T4]`
3. **리듬 주법** — 장애물이 BGM에 동기화되어 있어 시각 대신 청각으로 입력하면 처리 부하가 준다. 회피 게임이 리듬 게임으로 전환되는 창발. `[체감·T4]`

### 역전 현상

**역전 1 — 장르 정의 역전의 역방향(추출형).** 통상 장르 정의 역전은 후발주자가 장르를 재정의하는 형태다(Vampire Survivors, Factorio). Space Waves는 반대로, **기존 게임의 서브모드 하나를 통째로 뜯어내 단독 장르로 세웠다.** 원본은 RobTop의 Geometry Dash Wave 모드다 `[해석:합의·T3]`. 새 메커닉을 발명하지 않고 이미 검증된 30초짜리 서브루프만 남긴 저위험 전략이며, 1인 개발 규모에 정확히 맞는다.

**역전 2 — 디커플링: 시도 길이 vs 총 플레이.** 1회 시도가 10~60초인데 누적 플레이는 수십 시간에 이른다. Vampire Survivors의 "30분 세션 / 100시간 누적"과 같은 패턴이되 한 자릿수 더 극단이다.

**역전 3 — 경제 역전.** 유료 판매 0. 웹 무료 + 광고 + 포털 배포만으로 평점 투표 120만, 다운로드 500만+ 규모에 도달했다 `[집계-B]`. 프리미엄 인디 경로(Steam 유료 출시)를 완전히 우회한 사례다.

**역전 4 — 마케팅 역전.** 자체 마케팅 흔적이 거의 없고, 대신 수십 개의 미러·SEO 클론 사이트 생태계가 유통을 대행했다 `[체감·T4]`. **브랜드 통제를 포기하는 대가로 도달을 얻은** 구조다. 이 거래가 이득인지는 아래 약점 절에서 다시 본다.

**역전 5 — 철학 역전.** 우주 브랜딩이지만 체감은 기하학·리듬이다. Fantasy 축이 사실상 0인데도 우주 테마를 유지하는 이유는 몰입이 아니라 **검색어 확보**에 가깝다 `[해석:개인]`.

역전 4개 이상이므로 이 분석은 2차 검증 대상이다(아래 [한계와 정합률](#한계와-정합률) 참조).

### 축군 확인

**Mastery 축군 = 미성립.** 구성 축은 Mastery + Catharsis + Optimization인데, 앞의 둘은 ★★★★인 반면 Optimization이 ☆다. 로그라이트로 분류되는 게임들(Balatro, Vampire Survivors, Nova Drift)은 예외 없이 이 축군이 성립한다.

**이것이 `space wave + 로그라이크` 기획의 정확한 논거다.** 이 프로젝트는 "재미있으니까 로그라이크를 붙인다"가 아니라, **이미 ★★★★인 두 축에 비어 있는 한 축을 채워 축군을 완성한다**는 구조적 목표를 갖는다. 붙일 이유가 프레임워크 수준에서 특정된다.

## 약점·성취 양면

### 약점

1. **메타 진행 부재 (치명적)** — 실력이 늘어도 계정에 남는 것이 없다. 하루 이탈하면 복귀할 이유가 구조적으로 없다. Progression ★★는 이 규모의 게임이 감당할 수 있는 최저치에 가깝다.
2. **Optimization 축 전무** — 선택지가 없으니 "내 빌드"가 없고, 그래서 **공유할 것도 자랑할 것도 없다.** 바이럴이 플레이 영상 한 종류로 제한되며, 커뮤니티가 형성될 표면적이 없다.
3. **난이도 자유 선택의 양날** — 막히면 다른 레벨로 도피할 수 있어 좌절 이탈은 줄지만, "이 벽을 끝내 넘었다"는 개인 서사가 희석된다. Catharsis ★★★★가 ★★★★★로 못 가는 이유다.
4. **브랜드 통제 상실** — 미러·클론 사이트가 트래픽을 나눠 갖는다. 도달은 얻었으나 수익화·유저 데이터·업데이트 전달 경로를 전부 포털에 의존하게 됐다. 후속작 출시 시 축적된 유저 기반을 상속받지 못한다.
5. **표현·수익화 여지 없음** — 스킨도 커스터마이즈도 없어 광고 외 수익 모델을 얹을 자리가 없다.

### 성취

1. **단일 결정으로 난이도 공간 전체를 만든 설계** — "중립 상태를 주지 않는다"는 결정 하나가 33레벨 분량의 난이도 변주를 낳았다. 입력 개수를 늘리지 않고 깊이를 얻는 방법의 교과서적 사례다.
2. **마찰 0의 재시도 루프** — 0.5초 재시작은 즉사 장르의 최대 이탈 요인인 "실패의 감정 비용"을 사실상 제거했다. 난이도를 낮추지 않고 이탈을 막은 것이 핵심이다.
3. **검증된 모듈의 추출이라는 저위험 전략** — Geometry Dash Wave라는 이미 수년간 검증된 서브루프를 독립시켰다. 1인 개발이 신규 메커닉 발명 리스크를 지지 않고 완성도를 확보하는 경로를 보여준다.
4. **웹 우선 배포의 실증** — 설치 마찰 0으로 먼저 규모를 확보하고(평점 투표 120만), 그 검증 위에서 모바일로 역진출했다. 인디 게임의 순서를 뒤집은 유통 전략이다.
5. **수제 레벨 고수** — 절차적 생성을 쓰지 않았다. 원버튼 정밀 회피에서 무작위 배치는 곧 불공정한 죽음이 되므로, 이 장르에서 수제는 비용이 아니라 요구사항이다.

## Design Contract

| Contract | 준수 수준 | 근거 |
|---|---|---|
| Performance Reliability | ★★★★★ | 0.5초 재시작, 프레임·입력 지연이 곧 게임 본체 |
| Save System Integrity | ★★ | 레벨 진행도만. 브라우저 로컬 저장 의존 추정 `[해석:개인]` |
| Content Delivery | ★★★ | 레벨 추가로 이행 중 |
| Competitive Integrity | N/A | 경쟁 구조 없음 |
| Community Standard | N/A | 멀티·채팅 없음 |
| Fair Progression | N/A | 현재 판매 요소 없음 |

**이 장르의 유일한 필수 Contract는 Performance Reliability다.** 있으면 쾌감인가 없으면 이탈인가 — 60fps가 흔들리거나 입력 지연이 체감되는 순간 이 게임은 재미없어지는 게 아니라 **성립하지 않는다.** 1히트 즉사 + 0.2초 판단 주기 조합에서 프레임 드랍은 곧 불공정한 죽음이다.

Save System Integrity가 지금 ★★로도 문제되지 않는 이유는 **잃을 것이 거의 없기 때문**이다. 진행도가 날아가도 레벨은 다시 깨면 된다. 이 관용은 메타 진행을 도입하는 순간 사라진다.

## 순설계 이식 — 로그라이크 접목

여기부터는 역설계가 아니라 **신규 프로젝트를 위한 변주 설계**다. 위 분석에서 도출된 것만 근거로 쓴다.

### 핵심 명제

> **Space Waves에 로그라이크를 붙인다는 것은 Optimization 축을 여는 일이고, 그 대가로 반드시 지켜야 할 것은 Performance Reliability와 0.5초 재시도 루프다.**

로그라이크를 "재미 요소 추가"로 이해하면 실패한다. 추가되는 것은 선택지이고, 선택지는 **정지 시간과 화면 정보량**을 비용으로 요구한다. 그 둘이 이 게임의 두 기둥(Submission·Challenge)을 직접 깎는다.

### 무엇을 빌드로 만들 것인가

회피 게임에는 무기도 스탯도 없다. 접목 지점은 셋뿐이다.

**(a) 아바타 물성 개조** — 상승·하강 각도, 가속도, 히트박스 크기, 관성. "내 웨이브의 조종감 자체"를 빌드로 만든다.
**(b) 규칙 개조** — 1회 무적, 시간 감속, 되감기, 자동 정렬 구간. 실패 처리 방식을 빌드로 만든다.
**(c) 코스 개조** — 장애물 밀도·속도·유형을 플레이어가 선택한다. 리스크-리워드 라우팅.

**권장: (a)를 중심에 두고 (c)로 라우팅을 만들며, (b)는 희소 유물로만 제한한다.**

근거는 이렇다. (a)는 이 게임의 **유일한 감각인 조종감**을 직접 건드리므로 선택의 결과가 다음 1초 안에 손끝에서 체감된다. 로그라이크 선택 설계의 제1원칙은 "선택 직후 달라진 것이 느껴질 것"이고, 스탯 증가형 업그레이드가 이 장르에서 밋밋한 이유가 여기 있다. (c)는 Brotato식 웨이브-분기 구조를 그대로 이식할 수 있는 뼈대를 제공한다. (b)는 강력하지만 **1히트 즉사의 긴장을 직접 해체**하므로 Challenge ★★★★★를 무너뜨린다 — 런당 1~2개로 제한하고, 흔하게 풀면 게임이 물러진다.

**(a)의 위험도 정직하게 본다.** 조종감을 바꾸면 수백 시도로 쌓은 근육 기억이 매 런 리셋된다. Mastery ★★★★가 손상될 수 있고, 이건 이 프로젝트의 최대 설계 리스크다. 완화책은 **기본 조종 곡선을 고정하고 변형은 조건부 층으로만 쌓는 것**이다 — 예: "상승 홀드가 0.3초를 넘으면 그때부터 각도 +15%". 기본기는 이전되고 모듈은 그 위에 얹힌다.

### 루프 설계

```
[웨이브 i 주행 20~40초] → [생존 시 분기 3택] → [모듈 장착] → [웨이브 i+1]
                        ↓ 사망
                   [런 종료] → [코어 획득] → [영구 해금] → [다음 런]
```

| 스케일 | 주기 | 내용 | 원본 대비 |
|---|---|---|---|
| 초 | 0.2~1초 | 갭 통과 | **그대로. 손대지 말 것** |
| 분 | 20~40초 + 선택 | 웨이브 주행 → 3택 | 신규 |
| 런 | 6~10분 | 8~12 웨이브 | 신규 |
| 메타 | 세션 간 | 코어 → 영구 해금 | 신규 |

**런 길이 6~10분은 상한이자 설계 제약이다.** 원본의 1회 시도가 10~60초였다는 점을 기억해야 한다. Vampire Survivors의 30분을 그대로 가져오면 이 장르의 유입층(브라우저에서 30초 만에 시작하는 사람)을 잃는다. Brotato가 웨이브 단위 20~60초를 유지한 이유와 같다.

### 목표 축 프로필

| 축 | Space Waves | 목표 | 의도 |
|---|---|---|---|
| Challenge | ★★★★★ | ★★★★ | 런 길이 확대의 대가로 약간 완화 |
| Submission | ★★★★★ | ★★★★★ | **유지. 재시작 지연 사수** |
| Mastery | ★★★★ | ★★★★ | 기본 조종 곡선 고정으로 방어 |
| **Optimization** | ☆ | **★★★★** | **신규 개방 — 축군 성립 목표** |
| Progression | ★★ | ★★★★ | 영구 해금 도입 |
| Discovery | ★ | ★★★ | 모듈 조합 발견 |
| Expression | ☆ | ★★ | 빌드 = 약한 자기표현 |
| Catharsis | ★★★★ | ★★★★ | 유지 |

성공 판정: **Mastery 축군(Mastery + Catharsis + Optimization 모두 ★★★+)이 성립하면** 이 프로젝트는 로그라이트로서 정체성을 확보한 것이다. 성립하지 않으면 "회피 게임에 메뉴가 붙은 것"에 그친다.

### Contract 변화

- **Save System Integrity ★★ → ★★★★ (필수 승격).** 영구 진행이 생기는 순간, 진행도 소실은 불편이 아니라 이탈 사유가 된다. 브라우저 로컬 저장 단독은 계약 위반 수준이다. 최소한 내보내기/가져오기, 가능하면 계정 동기화.
- **Performance Reliability ★★★★★ 유지 — 타협 금지.** 모듈·이펙트가 늘면서 프레임이 깎이면 코어가 죽는다. 예산을 숫자로 못 박는다: **60fps 고정, 입력→반응 2프레임 이내.** 이펙트 추가는 이 예산을 통과할 때만 허용한다.
- **Fair Progression — 광고 부활 판매 금지 권고.** 즉사 회피 장르에서 부활을 팔면 Challenge와 Catharsis가 **동시에** 붕괴한다. 수백 시도 끝의 클리어가 주는 해방감은 "죽으면 끝"이라는 전제 위에만 성립한다. 광고를 붙이려면 런 사이(메타 화폐 가산)에 붙이고 런 안에는 넣지 않는다.

### 레드플래그 3개

1. **런이 길어진다** — 6~10분 상한을 넘기는 순간 원본의 유입 강점이 사라진다. 웨이브 수를 늘리고 싶어지면 늘리지 말고 분기 깊이를 늘린다.
2. **HUD가 늘어난다** — 화면 정보 추가는 곧 난이도 상승이다. 2~3 갭 앞을 보는 시선 배치가 이 게임의 숙련이기 때문이다. **모듈 상태는 별도 UI가 아니라 아바타 자체의 형태·색·궤적 변화로만 표현한다.**
3. **선택지가 3개를 넘는다** — 웨이브 간 정지가 길어지면 Submission 루프가 끊긴다. 3택 고정, 선택 제한 시간 도입을 검토한다.

### eval로 넘길 검증 질문

`projects/{slug}/eval.md`에 그대로 옮겨 쓸 수 있는 형태로 남긴다.

1. 첫 런 90초 안에 플레이어가 "내 조종감이 달라졌다"를 체감하는가?
2. 사망 후 다음 시도 시작까지 **1.5초 이내**인가? (원본 0.5초 + 런 결과 표시 여유)
3. 서로 다른 두 런의 빌드를 **스크린샷 한 장으로 구분**할 수 있는가? (Expression·Optimization 가시성 검사)
4. 30번째 런의 시작이 1번째 런의 시작보다 강한가? (메타 진행 체감)
5. 모듈을 전부 제거한 상태로 플레이해도 갭 통과 자체가 여전히 재미있는가? (코어 무손상 검사 — 이게 깨졌으면 로그라이크가 원본을 먹은 것)

## 인사이트

1. **입력을 늘리지 말고 중립을 제거하라.** 난이도 공간은 입력 개수가 아니라 "쉬는 상태의 유무"에서 나온다. Space Waves의 33레벨은 버튼 하나에서 나왔다.
2. **실패의 비용은 난이도가 아니라 대기 시간이다.** 0.5초 재시작이 즉사 장르의 이탈을 해결했다. 어려워서 떠나는 게 아니라 기다려서 떠난다.
3. **로그라이크는 축을 추가하는 장치가 아니라 특정 축을 여는 장치다.** 붙이기 전에 "어느 축이 비었는가"를 먼저 확정해야 한다. 여기서는 Optimization이었다.
4. **회피 게임의 빌드는 스탯이 아니라 조종감이어야 한다.** 선택의 결과가 손끝에서 1초 안에 체감되지 않으면 로그라이크 선택은 메뉴 조작으로 전락한다.
5. **메타 진행을 도입하는 순간 저장 Contract가 승격된다.** 잃을 것이 없을 때는 로컬 저장으로 충분하지만, 영구 진행은 소실이 곧 이탈이다. 기능 추가와 함께 인프라 요구가 올라간다.
6. **추출 전략은 1인 개발의 유효한 저위험 경로다.** 검증된 서브모드를 독립시키는 것은 표절이 아니라 장르 분화의 통상 경로이며, Space Waves는 그 상업적 실증이다 — 단, 브랜드 통제 상실이라는 대가가 따른다.
7. **웹 무료 배포는 도달을 사고 통제를 판다.** 규모 검증에는 최적이지만 유저 기반이 상속되지 않는다. 후속작을 염두에 둔다면 초기부터 자체 진행 저장·복귀 경로를 확보해야 한다.

## 한국 시장 관점

타겟이 한국인지 확정되지 않았으므로 짧게만 둔다. 한국 유저의 Contract 민감도 3축 중 이 프로젝트에 걸리는 것은 **Fair Progression 하나**다. 한국 모바일 시장은 광고 시청 자체에는 관용적이지만, **실력으로 얻어야 할 것을 돈·광고로 사는 구조**에는 강하게 반응한다. 즉사 회피 장르에서 부활 판매는 정확히 그 지점을 건드리므로, 위 Contract 절의 금지 권고는 한국 타겟일 때 더 강해진다.

Competitive Integrity·Content Delivery는 솔로·비경쟁 구조상 해당 없다.

## 한계와 정합률

**시나리오 1(Tier 1 소스 부족) + 시나리오 2(게임 정보 부족) + 시나리오 6(새 장르)이 동시에 발동한 분석이다.** 투명하게 적는다.

- **Space Waves 자체의 Tier 1~2 소스: 0건.** Xelluf 또는 do.games의 설계 의도에 관한 공개 발언을 확인하지 못했다. 개발 블로그·강연·본인 인터뷰가 검색되지 않는다.
- **정합률 0%** — 디자이너 의도와 대조할 수 있는 문장이 없다. 본 문서의 Mechanics·Interface 서술은 3자 매체·포털 설명 기반(`[해석:합의·T3]`, `[체감·T4]`)이고, Dynamics·Experience·인사이트는 **전부 `[해석:개인]`**이다.
- **분석가 직접 플레이 없음.** 조작 감각·난이도 곡선 서술은 포털 가이드와 커뮤니티 설명에 의존했다. 특히 "짧은 탭으로 중립 합성" 창발은 커뮤니티 팁 기반 추론이며, 실측이 필요하다.
- **Tier 1이 확보된 것은 비교군뿐이다.** Nova Drift 개발 블로그의 "15~30분 경험에 업그레이드를 압축" `[공식·T1]`, Vampire Survivors 제작자 Luca Galante의 슬롯 업계 경력 관련 발언 `[공식·T2, PC Gamer·The Verge]`. 비교 논거는 이 둘에 기대고 있다.
- **수치 정의 차이 명시:** CrazyGames 투표 수(120만)와 구글플레이 다운로드(500만+)는 플랫폼·정의가 달라 합산 불가. 둘 다 `[집계-B]`.

- [x] Tier 3~4를 `[공식]`으로 오용했는가 — 없음. 포털 설명은 `[체감·T4]`로 강등
- [x] 실패·약점 사례를 포함했는가 — 약점 5개, 그중 브랜드 통제 상실은 성취(도달 확보)의 이면으로 함께 기술

### 후속 조사가 필요한 영역

1. 원본의 실제 재시작 지연 실측 (0.5초는 3자 설명 기반)
