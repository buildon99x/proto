# Harbor Diorama Gallery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Launch a dynamic boxed miniature harbor from its own gallery thumbnail.
**Architecture:** Project-local static Three.js scene and gallery, bundled with esbuild; CPU motion functions isolated from rendering. Standard monorepo metadata and artifact pipeline, no root launcher specialization.
**Tech Stack:** Three 0.186.1, esbuild 0.28.2, Playwright 1.64.1, pngjs 7.0.0.
**Spec:** ../../../spec.md

## Global Constraints
All spec constraints apply, including branch-only publication and scoped pinned installation.

## Review Focus
- WebGL unavailable: useful fallback, no false render claims.
- Repeated launch/back: one canvas, resources disposed.
- Hidden tab and pause: no runaway animation or resume jump.
- Narrow screen and reduced motion: controls remain usable and motion opt-in.
- Loop boundaries: ships/cranes return continuously without visible teleports.
