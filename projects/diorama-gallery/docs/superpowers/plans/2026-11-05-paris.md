# Paris Timelapse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** A reference-informed Paris miniature forming into illuminated night, with four weather modes and day/night controls.
**Architecture:** Separate Paris world, landscape/architecture helpers, deterministic bounded construction batches, Paris atmosphere wrapper and optional world-specific shared weather selector.
**Tech Stack:** Existing pinned Three.js/esbuild runtime, Node tests, Blender only for labeled offline inspection.
**Spec:** ../specs/2026-11-05-paris-design.md

## Global Constraints
- Preserve all existing worlds, main and production; branch codex/paris-city-timelapse.
- No external artwork or unsafe browser flags. No invented fidelity or performance score.
- World uses absolute time; all resources owned and disposed.

## Review Focus
- Reverse seeking must restore emissive night intensity and construction transforms without resource growth.
- Night/snow controls must never change playback position/rate.
- Scene objects and river craft must remain supported and bounded.
- Standalone and gallery must expose identical snow choices.
- Literal aggregate build failures must not be called passes.

## Execution rulings
- The requested goal-level autonomy replaces repeated approval gates; native inline implementation with separate landmark and offline-review workers, then fresh whole-branch code review.
- Actual source-geometry review is used only as offline evidence because ordinary WebGL2 is unavailable. 95% reference fidelity is not met and is not claimed.
- Reviewer foundation gaps were treated as important for visual physical support. A RED→GREEN ground-contact test preceded foundations; the cost is modest extra geometry, not changed building silhouettes.
- Shared smooth river sampling fixes support alignment and also prevents boat heading snaps and repeated per-frame route allocation.
