## 규칙 검사 — 시뮬레이션 (`tests/rules/check.ts`)

브라우저 없이 엔진만 돌려 확정적으로 확인한다. 플레이어가 스폰 직후부터 자동으로
움직이기 때문에 브라우저 시나리오로는 같은 상황을 매번 재현할 수 없다.

| 묶음 | 확인 내용 |
| --- | --- |
| 사망 | 벽 충돌 사망, 사망 시 영토 중립화, 자기 꼬리 사망 |
| 킬 | 남의 꼬리를 밟으면 그 상대가 죽고 밟은 쪽은 살아남으며 킬이 기록된다 |
| 점령 | 고리를 닫으면 안쪽이 내 땅이 되고 꼬리가 비워진다 |
| 점령 예외 | 상대가 안에 있으면 그 영역은 넘어오지 않는다 (splix 구멍 막기 규칙) |
| 조작 | 180° 전환 무시, 한 칸에서 두 번째 전환 무시 |
| 스폰 | 가장 가까운 벽의 반대쪽을 향한다, 각자 `5 × 5` = 25칸으로 시작 |
| 실험 규칙 | 물막이 배율 구간, 폐허 잠금의 점령 차단·만료, 킬 이벤트의 보상 금액 |
| 멀티 | 인원별 구성(사람+AI=4), 목숨 제한 없음, 자리 이름 P1~P4, 네 자리 키가 겹치지 않음, 사람이 죽어도 판이 안 끝남 |
| 월드 | 보드 600×600, 봇 40기, 끝없음, 목숨 없음, 죽으면 판 종료, 카메라가 보드보다 좁음, 증분 집계가 전체 합과 일치 |

## 수동 확인

- 1440×900 데스크톱과 390×844 모바일 뷰포트 양쪽에서 보드가 잘리지 않는다.
- 2~4인 로컬 멀티에서 자리별 키가 각자에게만 먹히고, 보드 위 `P1`~`P4` 배지로 구분된다.
- 월드 모드에서 미니맵의 내 위치·시야 상자가 실제 화면과 맞는다.
- 터치 스와이프로 4방향 전환이 모두 동작한다.
- 90초 한 판에서 프레임 드랍이 눈에 띄지 않는다(체감 60fps).
- 색맹 대비: 4색이 명도로도 구분된다(영토 경계선이 항상 그려진다).

## 마지막 실행 결과 (2026-09-14, v0.2.0)

- `pnpm --filter land-grab test` — 타입 오류 0, 규칙 검사 18건 전부 통과.
- `pnpm playtest --project land-grab` — A2~A4 통과. page error 0, console error 0, 스크린샷 8장.
  - R1 시작 점유율 0.74% (`5 × 5` = 25칸 / 3,364칸).
  - R2 왕복 1회로 0.74% → 1.46%.
  - R3 자기 꼬리를 밟아 목숨 3 → 2.
  - R4 21초 시점 플레이어 2.53%, AI 4.67% / 4.99% / 0.74%.
  - R5 결과 화면 전환 확인. R6 일시정지 중 `elapsedMs` 고정 확인.

## 균형 — 규칙 문제가 아니었다 (정정)

이 자리에 원래 "얕은 왕복만 하면 플레이어 1~2.5%, AI 5% — AI 가 너무 앞선다"고 적어 두었다.
그 관찰을 근거로 규칙 세 가지를 만들어 측정했고 **셋 다 기각**했다.
전말과 데이터는 `docs/design/differentiation.md` §8~§10.

마지막에 넣은 대조군이 원인을 밝혔다. 측정에 쓰던 플레이어 봇은 **사냥을 하지 않는** 설정이었고,
AI 3인은 사냥하고 있었다. 봇에게 사냥만 켜 주자 규칙을 하나도 안 바꾸고
플레이어 점수가 **2.1배**(774 → 1,641), 플레이어/AI 점수비가 0.31 → 0.64 가 됐다.

킬 500점은 양쪽에 똑같이 열려 있다. 안 먹는 쪽만 손해를 본다.
즉 "AI 가 앞선다"는 것은 **측정에 쓴 플레이어가 얌전했다**는 뜻이었다.

남은 진짜 과제는 밸런스가 아니라 전달이다 — 킬이 점수의 대부분이라는 사실이
인게임에서 읽히지 않았다. v0.5.0 에서 네 가지를 고쳤다(킬 `+500` 팝업, HUD 킬 수,
순위표 킬 수, 타이틀 규칙 명시). 규칙은 바뀌지 않았다.

**이 변경은 아직 검증되지 않았다.** 봇은 화면을 읽지 않으므로 벤치로는 잴 수 없다.
사람이 잡았을 때 킬이 1.2 → 3 근처로, 점수비가 0.31 → 0.6 근처로 움직이는지 봐야 한다.

## 서버 검사 (`server/src/check.ts`, 56건)

소켓 없이 `Session` 을 직접 돌린다. 브라우저를 띄우지 않고 규약과 시야 동기화를 본다.

| 묶음 | 확인하는 것 |
| --- | --- |
| 시야 조각 나누기 | 사각형 빼기가 겹치지 않고 넓이가 맞는지, 처음/제자리/먼 곳 |
| 이름 | 빈 값·제어 문자·UTF-8 경계에서 안 깨지고 잘리는지 |
| 접속 | 자리·보드 크기·시작 영토 25칸이 그대로 도착하는지, 안 받은 칸은 안 그리는지 |
| 조작 | 방향이 반영되는지, **클라이언트 꼬리가 서버 꼬리와 한 칸도 안 어긋나는지** |
| 시야 | 60칸 이동 뒤에도 발밑을 알고 있는지, **전체 재전송이 아닌지** |
| 동시 접속 | 서로 보이는지, 끊으면 영토가 중립으로 돌아가고 **번호가 재사용되는지** |
| 사망 | `GameOver` 가 오고 자리가 비는지, `Respawn` 이 새 자리를 주는지 |
| 규약 | 버전 불일치 거절, 모르는 메시지 무시, 잘린 메시지는 예외 |
| 부하 | 16명 10초가 실시간보다 빠른지, 1인당 대역폭이 20KB/s 아래인지 |

## 서버 소켓 확인 (`server/src/smoke.ts`, 14건)

Render 에서 도는 것과 **같은 경로**를 밟는다 — `npm run build` 로 만든
`dist/main.mjs` 를 `node` 로 띄우고, 헬스 체크를 치고, 진짜 WebSocket 3개로 붙어
움직이고, 끊었을 때 자리가 비는지까지 본다.

## 온라인 브라우저 확인 (12건)

서버를 로컬에 띄우고 `VITE_LAND_GRAB_SERVER` 로 앱을 그쪽에 붙인 뒤, 진짜 브라우저로
타이틀부터 점령까지 밟는다. `window.__landGrabNet` 훅을 읽어 **방향을 보고** 조작한다 —
눈감고 방향키를 넣으면 자기 꼬리를 밟고 죽어서 무엇을 확인했는지 알 수 없다.

| 묶음 | 확인하는 것 |
| --- | --- |
| 타이틀 | 온라인 칩, 이름 입력칸 |
| 접속 | 자리를 받고 `playing` 으로 들어가는지 |
| 첫 상태 | 시작 영토 25칸, 순위표, 순위가 매겨지는지 |
| 조작 | 영토를 벗어나면 꼬리가 생기고, **고리를 닫으면 영토가 늘어나는지** |
| 서버 | 접속 수가 1로 잡히는지 |
| 위생 | 콘솔·네트워크 오류 0 (favicon 404 은 제외 — 이 앱에 파비콘이 없다) |

마지막 실행: 자리 #41, 스폰 (515,248), **25칸 → 44칸** 점령 확인.

## 서버 실측 (2026-09-15)

| 잰 것 | 값 |
| --- | --- |
| 기동 직후 RSS (빌드 산출물) | 76 MB |
| 사람 56명 + 봇 40기 접속 시 | 약 107 MB |
| 60초 시뮬레이션 + 64명 방송 | 327 ms (실시간의 183배) |
| 1인당 대역폭 | 1.6 KB/s |

Render Free 는 512 MB / 0.1 CPU 다. 메모리는 4배 이상 남고, CPU 는 0.1 코어 기준으로도
실시간의 18배쯤 남는다(추정 — Render 코어 성능을 직접 재지 못했다).
자세한 내용은 `docs/design/render-deploy.md` §3.

## 알려진 한계

- AI는 경로 탐색을 하지 않는다. 좁은 통로에서 비효율적으로 움직일 수 있다.
- 리스폰 위치는 빈 영역 무작위 선택이라, 혼잡할 때 상대 근처에 나올 수 있다.
- 플레이테스트 시나리오의 조작은 사람의 플레이와 다르다. R3(자기 꼬리 충돌)은
  다른 유닛에게 죽어도 `deaths`가 늘어 통과할 수 있다. 사망 원인까지는 구분하지 않는다.
- 온라인 화면에는 **연출이 덜 붙어 있다.** 규약이 점령·사망의 칸 목록을 보내지 않아
  점령 쐐기와 파편이 없고, 킬 점수 팝업도 없다 — 점수를 클라이언트가 지어내면
  규칙이 둘이 된다. 넣으려면 규약 v2 가 필요하다.
- 온라인에는 **미니맵이 없다.** 미니맵은 판 전체의 소유권을 읽는데, 온라인 클라이언트는
  시야 밖을 모른다. 서버가 주기적으로 축소본을 보내야 한다(splix 가 그렇게 한다).
- 접속이 끊기면 **자동으로 다시 붙지 않는다.** 안내를 띄우고 타이틀로 돌려보낸다.
- 온라인 확인은 **로컬 서버 기준**이다. 실제 왕복 지연에서의 체감은 아직 재지 않았다.
- 서버에 **지연 보정(되돌리기)이 없다.** splix 의 600ms / 5칸을 아직 넣지 않았다.
  한 지역 한 세계로 시작하므로 먼저 재고 필요하면 넣는다.
- 서버 검사의 부하 절은 **한 프로세스에서 세션을 직접 돌린 값**이다. 실제 소켓·TLS·
  네트워크 비용은 빠져 있다. 대역폭 수치는 하한으로 읽어야 한다.
