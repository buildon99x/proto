# Spec — 땅따먹기

규칙의 출처와 splix.io 대비 차이는 [docs/design/splix-analysis.md](docs/design/splix-analysis.md)에 정리했다.

## 0. 참가자

| 모드 | 사람 | AI | 목숨 |
| --- | --- | --- | --- |
| 혼자 | 1 | 난이도가 정함 (2~3) | 3개, 다 잃으면 판이 끝난다 |
| 여럿 | 2~4 | `4 − 사람 수` | 제한 없음, 90초를 끝까지 간다 |

여럿이 할 때 목숨을 없앤 이유는, 한 사람이 탈락해서 판이 끝나면
나머지 사람들의 90초가 사라지기 때문이다. 자세한 내용은
[docs/design/multiplayer.md](docs/design/multiplayer.md).

## 1. 게임 규칙

### 격자와 소유권

- 보드는 `60 × 60` 셀 격자다. 각 셀의 소유자는 `0`(중립) 또는 플레이어 번호 `1..4`.
- 격자의 가장 바깥 한 줄은 **벽**이다. 벽에 닿으면 죽는다. 소유할 수 없다.
- 게임 시작 시 각 플레이어는 서로 떨어진 지점에 `5 × 5` 시작 영토를 받는다.

### 이동

- 유닛은 셀 단위로 이동한다. 기본 속도는 **초당 6칸**(한 칸 `167ms`)이고, 렌더는 칸 사이를 보간한다.
- 방향은 상하좌우 4방향. 진행 방향의 정반대로는 전환할 수 없다.
- 입력은 큐에 들어갔다가 다음 칸 경계에서 반영된다.
- **한 칸에서는 한 번만 방향을 바꿀 수 있다.** 같은 자리에서 두 번째로 누른 입력은 버려진다
  (splix 규칙). 결과적으로 한 칸 안에서는 먼저 누른 쪽이 이긴다.
- 스폰·리스폰 시에는 가장 가까운 벽의 반대쪽을 향해 출발한다.

### 꼬리와 점령

- 내 영토 밖의 셀로 이동하면 그 셀에 내 **꼬리**가 남는다.
- 꼬리를 가진 상태로 내 영토에 다시 들어오면 점령이 일어난다.
  1. 꼬리 셀 전부를 내 소유로 바꾼다.
  2. 꼬리 전체와 내 영토를 감싸는 **경계 상자를 한 칸 넓혀** 잡는다
     (보드 전체가 아니라 이 범위만 훑는다).
  3. 경계 상자 테두리에서 시작해 "내 소유가 아닌 셀"을 flood fill 한다.
  4. **살아 있는 다른 유닛의 상하좌우 셀도 시작점으로 추가한다.** 그래서 상대가 들어 있는
     영역은 "바깥"으로 취급돼 한 칸도 넘어오지 않는다. 상대를 크게 둘러싸는 것만으로
     넓은 땅을 먹는 구멍을 막는 규칙이다. 상대가 내 영토 위에 서 있으면 효과가 없다.
  5. 끝까지 채워지지 않은 셀을 전부 내 소유로 바꾼다.
- 점령 영역 안에 있던 남의 꼬리는 그대로 남는다. 소유권만 바뀐다.
- 점령으로 빼앗긴 셀의 원래 주인은 그만큼 영토를 잃는다.

### 사망

| 상황 | 결과 |
| --- | --- |
| 벽에 닿음 | 자기 자신 사망 |
| 자기 꼬리를 밟음 | 자기 자신 사망. 단 **가장 최근 꼬리 2칸은 예외** |
| 남의 꼬리를 밟음 | 꼬리 주인 사망 (밟은 쪽은 무사, 킬 1) |
| 두 유닛이 같은 셀에 진입 | 꼬리를 물고 있던 쪽이 사망, 둘 다 꼬리가 있으면 둘 다 사망 |

- 자기 영토 안에 있어도 안전이 보장되지는 않는다. 꼬리가 없을 뿐, 남의 꼬리를 밟을 수는 있다.
- 사망하면 꼬리는 사라지고 그 플레이어의 영토는 전부 중립이 된다.
- 플레이어는 목숨 3개. 사망 후 `1.2초` 뒤 빈 영역에 새 `5 × 5` 영토로 리스폰한다.
- AI는 목숨 제한 없이 계속 리스폰한다(경쟁 압력 유지).
- 플레이어 목숨이 0이 되면 즉시 게임 종료.

### 점수와 승패

- 제한 시간 `90초`.
- 점수 = 소유 셀 수 × 1 + 킬 수 × 500.
### 켜고 끌 수 있는 실험 규칙 (`MatchRules`)

세 가지 모두 **기본은 꺼져 있다.** 밸런스 가설로 만들어 측정했고 전부 기각했다.
재현할 수 있게 코드·검사·벤치는 남겨 두었다. 전말은
`docs/design/differentiation.md` §8~§10.

| 규칙 | 내용 | 기본값 |
| --- | --- | --- |
| `captureBonus` | 한 번에 넓게 막을수록 점수 배율 (25칸↑ ×1.5, 60칸↑ ×2) | 꺼짐 |
| `rubbleLockMs` | 사망한 영토를 그 시간만큼 아무도 못 먹는 폐허로 잠금 | `0` (꺼짐) |
| `killScore` | 킬 1회의 점수 | `500` (splix 값 유지) |
- 순위는 점수 기준. 결과 화면에는 점유율·킬·최대 점유율을 함께 보여준다.
- 플레이어 목숨이 0이면 `패배`, 시간 종료 시 1위면 `승리`, 그 외는 순위 표시.

## 2. 난이도

| 난이도 | AI 수 | AI 한 칸 시간 | AI 목표 사각형 | 플레이어 사냥 |
| --- | --- | --- | --- | --- |
| 쉬움 | 2 | 220ms | 3~5칸 | 안 함 |
| 보통 | 3 | 180ms | 4~7칸 | 적 꼬리가 6칸 넘게 노출되면 |
| 어려움 | 3 | 150ms | 5~9칸 | 적 꼬리가 3칸 넘게 노출되면 |

플레이어는 항상 `167ms`로, 모든 난이도에서 AI보다 빠르거나 같다.

## 3. AI

상태 머신 4개.

- `EXPAND` — 내 영토 경계에서 밖으로 나가 `w × h` 직사각형 경로를 그리고 복귀한다.
- `RETURN` — 내 영토 중 가장 가까운 셀로 맨해튼 경로 복귀.
- `HUNT` — 사정거리 안에 노출된 적 꼬리가 있으면 그 셀로 접근.
- `RESPAWN` — 리스폰 대기.

안전 규칙(모든 상태에 우선):

1. 다음 칸이 벽이거나 자기 꼬리면 그 방향을 버린다.
2. 꼬리 길이가 난이도별 한도를 넘으면 `RETURN`.
3. 적 유닛이 3칸 안에 있고 내 꼬리가 노출돼 있으면 `RETURN`.
4. 갈 곳이 전부 막히면 자기 영토 방향을 우선한다.

## 4. 화면

- `title` — 제목, 규칙, **사람 수 선택(1~4)**, 난이도 선택, `게임 시작`.
  2인 이상을 고르면 자리별 키 안내가 함께 뜬다.
- `playing` — 상단 HUD(남은 시간, 내 점유율, 목숨, 점수), 캔버스 보드, 우측 순위표, 모바일에서는 하단 방향 패드.
- `paused` — `Esc`/`P` 또는 버튼. 싱글이므로 완전 정지한다. `계속하기` / `다시 시작` / `타이틀로`.
- `result` — 여럿이면 `P2 승리` 처럼 승자 이름을 띄운다. 혼자면 승/패 문구.
  최종 순위표(점수·점유율·킬), 최고 점유율과
  **한 번에 가장 넓게 막은 땅**, `다시 하기` / `타이틀로`.

## 5. 조작

혼자 할 때는 1번 자리가 방향키와 `WASD` 를 같이 받는다. 여럿이면 자리마다 하나씩 나눠 쓴다.

| 자리 | 키 |
| --- | --- |
| P1 | `←↑→↓` · 숫자패드 |
| P2 | `W A S D` |
| P3 | `I J K L` |
| P4 | `T F G H` |

| 입력 | 동작 |
| --- | --- |
| `Esc` / `P` | 일시정지 토글 (누구든) |
| 스와이프 · 화면 방향 패드(터치) | 이동 방향 전환. 혼자일 때만 |

## 6. 상태 모델

```ts
type Owner = 0 | 1 | 2 | 3 | 4;          // 0 = 중립

type Runner = {
  id: Exclude<Owner, 0>;
  kind: "human" | "ai";
  alive: boolean;
  respawnAt: number;                      // ms, alive=false일 때만 유효
  x: number; y: number;                   // 격자 좌표
  prevX: number; prevY: number;           // 보간용 직전 좌표
  dir: Direction;
  queuedDir: Direction | null;
  trail: Array<{ x: number; y: number }>;
  lives: number;                          // AI는 Infinity
  kills: number;
  peakTiles: number;
};

type Match = {
  phase: "playing" | "paused" | "result";
  owner: Uint8Array;                      // size * size
  trailOwner: Uint8Array;                 // size * size, 0 = 꼬리 없음
  runners: Runner[];
  elapsedMs: number;
  durationMs: number;
};
```

- `owner`/`trailOwner`는 `Uint8Array` 평면 배열. 인덱스는 `y * size + x`.
- flood fill은 명시적 스택으로 구현한다. 스크래치 버퍼는 매 점령마다 재사용한다.

## 7. 렌더링

- `<canvas>` 2D. 보드는 항상 정사각형이며 컨테이너에 맞춰 셀 크기를 계산한다.
- `devicePixelRatio`를 반영해 백버퍼를 확대한다.
- 레이어 순서: 벽 → 영토 → 폐허 → 점령 쐐기 → 꼬리(반투명) → 파편 → 충격파 → 유닛 → 킬 점수.
- 팔레트 4색(청록/주황/보라/연두). 꼬리는 같은 색 알파 `0.45`, 영토 경계선은 항상 그린다.

## 8. 테스트 훅

`window.__landGrab`에 노출한다.

```ts
{
  phase: "title" | "playing" | "paused" | "result";
  difficulty: DifficultyId;
  tiles: number[];         // 플레이어 1..N 소유 셀 수
  shares: number[];        // 플레이어 1..N 점유율(0~1)
  scores: number[];
  elapsedMs: number;
  remainingMs: number;
  lives: number;          // -1이면 제한 없음(여럿이 할 때)
  kills: number;
  humans: number;
  deaths: number;          // 플레이어 사망 누적
  trailLength: number;
  x: number;               // 플레이어 격자 좌표
  y: number;
  dir: Direction;
  alive: boolean;          // false면 리스폰 대기 중
  onOwnLand: boolean;
}
```

위치·방향·생존 여부까지 내보내는 이유는, 플레이어가 스폰 직후부터 자동으로 달려서
시나리오가 고정된 키 순서로는 같은 상황을 재현할 수 없기 때문이다. 시나리오는 매번
현재 상태에서 다음 조작을 다시 계산한다.
