# Spec — 땅따먹기

규칙의 출처와 splix.io 대비 차이는 [docs/design/splix-analysis.md](docs/design/splix-analysis.md)에 정리했다.

## 0. 모드

| | 월드 | 파티 |
| --- | --- | --- |
| 보드 | `600 × 600` (360,000칸) | `60 × 60` |
| 화면 | 카메라가 내 말을 따라간다 (가로 44칸) + 미니맵 | 보드 전체가 한 화면에 |
| 참가자 | 나 1명 + 봇 40기 | 사람 1~4명 + AI |
| 길이 | 끝이 없다 | 90초 |
| 목숨 | 없다. 죽으면 그 판이 끝난다 | 혼자 3개 / 여럿 제한 없음 |
| 순위표 | 상위 10 + 내 자리 | 참가자 전원 |

큰 맵과 한 화면 멀티는 양립하지 않는다 — 600칸을 한 화면에 넣으면 말이 점 하나가 된다.
그래서 둘을 나눴다. 월드가 기본이다.

파티 모드에서 여럿일 때 목숨을 없앤 이유는, 한 사람이 탈락해서 판이 끝나면
나머지 사람들의 90초가 사라지기 때문이다.
[docs/design/multiplayer.md](docs/design/multiplayer.md) 참고.

### 큰 맵이 강제한 것

`60 × 60` 에서는 전면 스캔이 통했지만 `600 × 600` 에서는 아니다(36만 칸). 세 곳을 고쳤다.

- **경계 상자 추적** — 플레이어마다 소유 영역의 상자를 들고 있다가 점령·사망 때 그 안만 훑는다.
  splix 의 `PlayerBoundsTracker` 와 같은 방식이고, 상자는 늘어나기만 한다.
- **증분 집계** — 소유권이 바뀔 때마다 칸 수를 더하고 뺀다. 세려고 판을 훑지 않는다.
- **시야 렌더링** — 화면에 들어오는 칸만 그린다. 빈 격자는 한 번 그려 두고 밀어서 붙인다.
- **AI 의 복귀 지점** — 마지막으로 자기 땅을 밟은 칸을 기억한다. 가장 가까운 내 땅을 찾으려고
  판 전체를 훑지 않는다.

측정: `600 × 600` · 41명 기준 60초 시뮬레이션에 158ms(실시간의 380배), 브라우저에서 59fps.

## 0-1. 참가자 (파티 모드)

| | 사람 | AI | 목숨 |
| --- | --- | --- | --- |
| 혼자 | 1 | 난이도가 정함 (2~3) | 3개, 다 잃으면 판이 끝난다 |
| 여럿 | 2~4 | `4 − 사람 수` | 제한 없음, 90초를 끝까지 간다 |

## 1. 게임 규칙

### 격자와 소유권

- 보드는 모드에 따라 `60 × 60` 또는 `600 × 600` 셀 격자다. 각 셀의 소유자는 `0`(중립) 또는 플레이어 번호 `1..4`.
- 격자의 가장 바깥 한 줄은 **벽**이다. 벽에 닿으면 죽는다. 소유할 수 없다.
- 게임 시작 시 각 플레이어는 서로 떨어진 지점에 `5 × 5` 시작 영토를 받는다.

### 이동

- 유닛은 셀 단위로 이동한다. 기본 속도는 **초당 6칸**(한 칸 `167ms`)이고, 렌더는 칸 사이를 보간한다.
- 방향은 상하좌우 4방향. 진행 방향의 정반대로는 전환할 수 없다.
- 입력은 큐에 들어갔다가 다음 칸 경계에서 반영된다.
- **한 칸에서는 한 번만 방향을 바꿀 수 있다.** 같은 자리에서 두 번째로 누른 입력은 버려진다
  (splix 규칙). 결과적으로 한 칸 안에서는 먼저 누른 쪽이 이긴다.
- 스폰·리스폰 시에는 가장 가까운 벽의 반대쪽을 향해 출발한다.

### 꼬리와 점령

- 내 영토 밖의 셀로 이동하면 그 셀에 내 **꼬리**가 남는다.
- 꼬리를 가진 상태로 내 영토에 다시 들어오면 점령이 일어난다.
  1. 꼬리 셀 전부를 내 소유로 바꾼다.
  2. 꼬리 전체와 내 영토를 감싸는 **경계 상자를 한 칸 넓혀** 잡는다
     (보드 전체가 아니라 이 범위만 훑는다).
  3. 경계 상자 테두리에서 시작해 "내 소유가 아닌 셀"을 flood fill 한다.
  4. **살아 있는 다른 유닛의 상하좌우 셀도 시작점으로 추가한다.** 그래서 상대가 들어 있는
     영역은 "바깥"으로 취급돼 한 칸도 넘어오지 않는다. 상대를 크게 둘러싸는 것만으로
     넓은 땅을 먹는 구멍을 막는 규칙이다. 상대가 내 영토 위에 서 있으면 효과가 없다.
  5. 끝까지 채워지지 않은 셀을 전부 내 소유로 바꾼다.
- 점령 영역 안에 있던 남의 꼬리는 그대로 남는다. 소유권만 바뀐다.
- 점령으로 빼앗긴 셀의 원래 주인은 그만큼 영토를 잃는다.

### 사망

| 상황 | 결과 |
| --- | --- |
| 벽에 닿음 | 자기 자신 사망 |
| 자기 꼬리를 밟음 | 자기 자신 사망. 단 **가장 최근 꼬리 2칸은 예외** |
| 남의 꼬리를 밟음 | 꼬리 주인 사망 (밟은 쪽은 무사, 킬 1) |
| 두 유닛이 같은 셀에 진입 | 꼬리를 물고 있던 쪽이 사망, 둘 다 꼬리가 있으면 둘 다 사망 |

- 자기 영토 안에 있어도 안전이 보장되지는 않는다. 꼬리가 없을 뿐, 남의 꼬리를 밟을 수는 있다.
- 사망하면 꼬리는 사라지고 그 플레이어의 영토는 전부 중립이 된다.
- 플레이어는 목숨 3개. 사망 후 `1.2초` 뒤 빈 영역에 새 `5 × 5` 영토로 리스폰한다.
- AI는 목숨 제한 없이 계속 리스폰한다(경쟁 압력 유지).
- 플레이어 목숨이 0이 되면 즉시 게임 종료.

### 점수와 승패

- 제한 시간 `90초`.
- 점수 = 소유 셀 수 × 1 + 킬 수 × 500.
### 켜고 끌 수 있는 실험 규칙 (`MatchRules`)

세 가지 모두 **기본은 꺼져 있다.** 밸런스 가설로 만들어 측정했고 전부 기각했다.
재현할 수 있게 코드·검사·벤치는 남겨 두었다. 전말은
`docs/design/differentiation.md` §8~§10.

| 규칙 | 내용 | 기본값 |
| --- | --- | --- |
| `captureBonus` | 한 번에 넓게 막을수록 점수 배율 (25칸↑ ×1.5, 60칸↑ ×2) | 꺼짐 |
| `rubbleLockMs` | 사망한 영토를 그 시간만큼 아무도 못 먹는 폐허로 잠금 | `0` (꺼짐) |
| `killScore` | 킬 1회의 점수 | `500` (splix 값 유지) |
- 순위는 점수 기준. 결과 화면에는 점유율·킬·최대 점유율을 함께 보여준다.
- 플레이어 목숨이 0이면 `패배`, 시간 종료 시 1위면 `승리`, 그 외는 순위 표시.

## 2. 난이도

| 난이도 | AI 수 | AI 한 칸 시간 | AI 목표 사각형 | 플레이어 사냥 |
| --- | --- | --- | --- | --- |
| 쉬움 | 2 | 220ms | 3~5칸 | 안 함 |
| 보통 | 3 | 180ms | 4~7칸 | 적 꼬리가 6칸 넘게 노출되면 |
| 어려움 | 3 | 150ms | 5~9칸 | 적 꼬리가 3칸 넘게 노출되면 |

플레이어는 항상 `167ms`로, 모든 난이도에서 AI보다 빠르거나 같다.

## 3. AI

상태 머신 4개.

- `EXPAND` — 내 영토 경계에서 밖으로 나가 `w × h` 직사각형 경로를 그리고 복귀한다.
- `RETURN` — 내 영토 중 가장 가까운 셀로 맨해튼 경로 복귀.
- `HUNT` — 사정거리 안에 노출된 적 꼬리가 있으면 그 셀로 접근.
- `RESPAWN` — 리스폰 대기.

안전 규칙(모든 상태에 우선):

1. 다음 칸이 벽이거나 자기 꼬리면 그 방향을 버린다.
2. 꼬리 길이가 난이도별 한도를 넘으면 `RETURN`.
3. 적 유닛이 3칸 안에 있고 내 꼬리가 노출돼 있으면 `RETURN`.
4. 갈 곳이 전부 막히면 자기 영토 방향을 우선한다.

## 4. 화면

- `title` — 제목, **모드 선택(월드/파티)**, 규칙, 파티일 때 **사람 수 선택(1~4)**,
  난이도(월드에서는 봇 성격), `게임 시작`. 2인 이상을 고르면 자리별 키 안내가 함께 뜬다.
- `playing` — 상단 HUD(남은 시간, 내 점유율, 목숨, 점수), 캔버스 보드, 우측 순위표, 모바일에서는 하단 방향 패드.
- `paused` — `Esc`/`P` 또는 버튼. 싱글이므로 완전 정지한다. `계속하기` / `다시 시작` / `타이틀로`.
- `result` — 월드는 `12위 / 41명` 과 생존 시간을 띄운다.
  파티는 여럿이면 `P2 승리` 처럼 승자 이름을, 혼자면 승/패 문구를 띄운다.
  최종 순위표(점수·점유율·킬), 최고 점유율과
  **한 번에 가장 넓게 막은 땅**, `다시 하기` / `타이틀로`.

## 5. 조작

혼자 할 때는 1번 자리가 방향키와 `WASD` 를 같이 받는다. 여럿이면 자리마다 하나씩 나눠 쓴다.

| 자리 | 키 |
| --- | --- |
| P1 | `←↑→↓` · 숫자패드 |
| P2 | `W A S D` |
| P3 | `I J K L` |
| P4 | `T F G H` |

| 입력 | 동작 |
| --- | --- |
| `Esc` / `P` | 일시정지 토글 (누구든) |
| 스와이프 · 화면 방향 패드(터치) | 이동 방향 전환. 혼자일 때만 |

## 6. 상태 모델

```ts
type Owner = number;                    // 0 = 중립, 255 = 벽, 1~254 = 유닛

type Runner = {
  id: Exclude<Owner, 0>;
  kind: "human" | "ai";
  alive: boolean;
  respawnAt: number;                      // ms, alive=false일 때만 유효
  x: number; y: number;                   // 격자 좌표
  prevX: number; prevY: number;           // 보간용 직전 좌표
  dir: Direction;
  queuedDir: Direction | null;
  trail: Array<{ x: number; y: number }>;
  lives: number;                          // AI는 Infinity
  kills: number;
  peakTiles: number;
};

type Match = {
  phase: "playing" | "paused" | "result";
  owner: Uint8Array;                      // size * size
  trailOwner: Uint8Array;                 // size * size, 0 = 꼬리 없음
  runners: Runner[];
  elapsedMs: number;
  durationMs: number;
};
```

- `owner`/`trailOwner`는 `Uint8Array` 평면 배열. 인덱스는 `y * size + x`.
- flood fill은 명시적 스택으로 구현한다. 스크래치 버퍼는 매 점령마다 재사용한다.
- 소유자 코드가 1바이트라 **동시 참가자는 254명이 상한**이다. 온라인 세계는 자리를
  비우면 그 번호를 재사용한다(`Match.addRunner` 가 비어 있는 가장 작은 값을 고른다).

### 판이 도는 중의 자리 변경

| 호출 | 하는 일 |
| --- | --- |
| `Match.addRunner(kind, tickMs?)` | 빈 번호로 자리를 열고 시작 영토를 깐다. 꽉 찼으면 `null` |
| `Match.removeRunner(id)` | 자리를 빼고 그 영토·꼬리를 중립으로 돌린다 |
| `MatchOptions.shared` | 켜면 사람이 죽어도 판이 끝나지 않는다. 서버 세계용 |

로컬 판은 세 가지를 모두 쓰지 않는다. 생성자가 짠 명단 그대로 끝까지 간다.

## 7. 렌더링

- `<canvas>` 2D. 보드는 항상 정사각형이며 컨테이너에 맞춰 셀 크기를 계산한다.
- `devicePixelRatio`를 반영해 백버퍼를 확대한다.
- 레이어 순서: 벽 → 영토 → 폐허 → 점령 쐐기 → 꼬리(반투명) → 파편 → 충격파 → 유닛 → 킬 점수.
- 팔레트 4색(청록/주황/보라/연두). 꼬리는 같은 색 알파 `0.45`, 영토 경계선은 항상 그린다.

## 8. 테스트 훅

`window.__landGrab`에 노출한다.

```ts
{
  phase: "title" | "playing" | "paused" | "result";
  difficulty: DifficultyId;
  tiles: number[];         // 플레이어 1..N 소유 셀 수
  shares: number[];        // 플레이어 1..N 점유율(0~1)
  scores: number[];
  elapsedMs: number;
  remainingMs: number;
  lives: number;          // -1이면 제한 없음(여럿이 할 때, 그리고 월드 모드)
  kills: number;
  humans: number;
  mode: "party" | "world";
  boardSize: number;
  players: number;
  rank: number;
  deaths: number;          // 플레이어 사망 누적
  trailLength: number;
  x: number;               // 플레이어 격자 좌표
  y: number;
  dir: Direction;
  alive: boolean;          // false면 리스폰 대기 중
  onOwnLand: boolean;
}
```

위치·방향·생존 여부까지 내보내는 이유는, 플레이어가 스폰 직후부터 자동으로 달려서
시나리오가 고정된 키 순서로는 같은 상황을 재현할 수 없기 때문이다. 시나리오는 매번
현재 상태에서 다음 조작을 다시 계산한다.

## 9. 온라인 세계 서버

`server/` 에 있다. 설계 근거는 `docs/design/io-server.md`,
배포 조사는 `docs/design/render-deploy.md`.

### 권위

서버가 전부 정한다. 클라이언트가 보내는 것은 **방향 하나**뿐이고 위치는 받지 않는다.
이 게임은 입력이 칸 경계에서만 반영되므로 검증이 싸다 — 초당 6회, 값은 넷 중 하나.

시뮬레이션은 브라우저와 **같은 코드**(`app/src/game`)를 쓴다. 서버용으로 다시 짜면
두 구현이 갈라지고, 그 순간부터 "클라이언트에서는 산 것 같은데 서버는 죽었다"가 된다.

### 규약 v1 (`app/src/net/protocol.ts`)

전부 바이너리, 리틀 엔디언. 첫 메시지는 반드시 `Hello` 이고 `PROTOCOL_VERSION` 이
다르면 거절한다 — 클라이언트가 캐시되므로 버전 불일치는 반드시 생긴다.

| 방향 | 메시지 |
| --- | --- |
| 클라 → 서버 | `Hello`(버전·이름), `Direction`, `Pong`, `Respawn` |
| 서버 → 클라 | `Welcome`, `Reject`, `Tiles`, `Players`, `Trail`, `Remove`, `Death`, `Score`, `Leaderboard`, `Name`, `Ping`, `GameOver` |

### 시야

`600 × 600` 은 36만 칸이라 통째로 보낼 수 없다. 접속마다 **한 변 96칸**의 사각형을
보내고, 중심이 가장자리 32칸 안으로 들어오면 다시 잡아 **차이 나는 띠만** 덧붙인다
(`ViewportSync`). 타일은 압축하지 않는다 — 조각이 작아 압축이 손해다.

`96` 과 `32` 는 같이 움직인다. **여유(32)가 화면 반폭(22)보다 커야** 사각형을 다시
잡기 전에 화면이 보낸 영역을 넘지 않는다.

바뀐 타일은 서버가 사각형 목록으로 모아 두고(점령·사망·리스폰), 접속별로 잘라 보낸다.

### 꼬리

매 주기 통째로 보내지 않는다. **길이가 줄었을 때만**(점령·사망·시야 진입) 다시 보내고,
늘어나는 동안에는 클라이언트가 위치 갱신으로 이어 붙인다. 방송이 밀려 두 칸이 한 번에
오면 사이를 메운다.

### 사망

io 문법 그대로. 죽으면 `GameOver` 를 받고 **자리가 바로 비워진다.** 다시 하려면
`Respawn` 을 보내 새 번호를 받는다. 로컬의 리스폰(1.2초 뒤 부활)은 봇에게만 적용된다.

### 주기

| 값 | 크기 | 이유 |
| --- | --- | --- |
| 시뮬레이션 한 걸음 | 50 ms | 이동이 167ms 마다라 칸 경계를 충분히 잘게 쪼갠다 |
| 방송 | 100 ms | 위치가 167ms 마다 바뀌니 한 칸도 놓치지 않는다 |
| 핑 | 15 s, 응답 없으면 45초에 끊음 | 죽은 연결 정리 |

### 화면

렌더러는 `Match` 를 모른다. 한 프레임에 필요한 것만 담은 `Scene`(`game/render.ts`)을
받고, 그 모양을 로컬은 `game/scene.ts`, 온라인은 `net/scene.ts` 가 만든다.
그래서 같은 렌더러가 두 경로를 다 그린다.

온라인 화면은 시뮬레이션을 **한 걸음도 돌리지 않는다.** 서버가 보낸 것을 그릴 뿐이고,
파편·충격파 같은 연출만 이쪽에서 굴린다. 그건 규칙이 아니라 화면이다.

`window.__landGrabNet` 이 온라인 쪽 테스트 훅이다. 로컬의 `window.__landGrab` 과
같은 역할을 하고, 방향·위치·내 땅 여부를 읽을 수 있어 조작을 정확히 짤 수 있다.

### 운영 제약

- **인스턴스는 항상 하나.** 세계가 프로세스 메모리에 있다. 늘리면 로드 밸런서가
  접속을 갈라 같은 세계에 있다고 믿는 사람들이 서로 다른 세계에 앉는다.
- **재배포하면 세계가 초기화된다.** 외부 저장소를 쓰지 않는다.
