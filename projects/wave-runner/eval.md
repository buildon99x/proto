# Evaluation — Wave Runner

## 여전히 미수행인 중단 판정 (1단계)

> **제작자 외 3명에게 아무 설명 없이 건넸을 때, 2명 이상이 지시 없이 5회 이상 재시도하는가.**

**아직 수행되지 않았다.** 2단계는 이 판정을 통과한 뒤 착수하는 것이 원래 순서였고, 지시에 따라 먼저 진행했다. 기저 비행이 재미없으면 빌드도 게이트도 구해주지 못하므로 이 판정은 유효하며, 사람 손에 들어가는 즉시 물어야 한다. 시도 횟수는 스테이지 셀에 표시된다.

## 자동 검증

```bash
pnpm --filter wave-runner lint                                          # 타입
node projects/wave-runner/tests/smoke/lookahead.test.mjs                # 선행 가시 시간 상수
pnpm exec tsx projects/wave-runner/tests/verify/sector-probe.ts         # 축이 양날인가
pnpm exec tsx projects/wave-runner/tests/verify/stage-paths.ts          # 전 경로 통과 가능성
pnpm exec tsx projects/wave-runner/tests/verify/endless-ramp.ts         # Endless 난이도 램프
pnpm exec tsx projects/wave-runner/tests/verify/curate-stages.ts        # 스테이지 시드 재선별(표를 다시 굽는다)
```

| 검사 | 현재 결과 |
|---|---|
| 타입·빌드·런처 전체 빌드 | 통과 |
| 선행 가시 1.2초 | 360×640에서 1.34초, 세로 가시 100% |
| **축이 양날인가** | 각도·속도·편향 3축 모두 섹터 유형에 따라 부호가 뒤집힘. 중립 빌드로 12섹터 전부 통과 |
| **전 경로 통과 가능성** | 12개 스테이지, 경로 16가지씩 — 통과율 50~81% |
| **Endless 램프** | 지연 20ms 5036 → 180ms 1068. 모든 지연에서 런이 종료됨 |
| 브라우저 플레이테스트 | Stage 클리어(73초, 게이트 4개 통과, 빌드 변화 확인) · Endless 종료(4268m, 게이트 7개) · 콘솔 오류 0 |

### 통과율 100%가 아니라 50~80%인 이유

전 경로 검증의 목적은 **공정성 바닥**이다 — 눈에 보이지 않는 막다른 길이 없어야 한다. 그런데 100%면 무슨 선택을 해도 통과되어 게이트가 무의미해지고, 20%면 퍼즐이 아니라 시행착오 강요다. 그래서 `curate-stages.ts`가 후보 시드를 훑어 **통과율 45~85% 구간의 시드만 남겨** `stage-seeds.json`에 굽는다. 게임은 그 표만 읽는다.

### 오토파일럿이 증명하는 것과 하지 않는 것

- **증명한다:** 코스가 현재 물리로 통과 가능하다. 불가능한 구간이나 막다른 빌드 경로가 섞여 있지 않다.
- **증명하지 않는다:** 난이도가 적절한가. 오토파일럿은 통로와 셔터 위상을 정확히 알고 달린다.
- **부분적으로 답한다:** 빌드 선택이 사람에게 의미가 있는지는 `sector-probe.ts`가 반응 지연 허용치로 근사한다 — 같은 섹터에서 한 축을 ±2 움직이면 허용 지연이 20ms와 190ms로 갈린다.

## 손으로 확인할 것

- [ ] 조작 설명 없이 첫 10초 안에 버튼의 의미를 파악하는가
- [ ] **게이트를 지난 직후, 무엇과 무엇을 바꿨는지 글자 없이 아는가**
- [ ] **서로 다른 두 빌드의 궤적을 스크린샷 한 장으로 구분할 수 있는가**
- [ ] **두 모드를 각각 해본 사람이 "왜 둘 다 있는지"를 한 문장으로 말할 수 있는가**
- [ ] **Stage 재시도 중 빌드를 바꿔본 비율이 30% 이상인가** (0%면 Stage의 로그라이크 성분이 죽은 것)
- [ ] Endless 사망 후 자기 빌드 선택을 원인으로 지목하는가
- [ ] 섹터 4유형을 이름 없이 실루엣만으로 구분하는가
- [ ] `running` 중 화면에 HUD가 하나도 없는가
- [ ] 세로 화면에서 한 손으로 플레이되는가
- [ ] 60fps가 유지되는가 (T 패널)
- [ ] 새로고침 후 해금과 기록이 남아 있는가

## 3단계로 넘긴 것

런타임 절차 생성과 **정확한 솔버**. 현재 검증은 증인(witness) 기반이라 "통과 가능"은 증명해도 "불가능"은 증명하지 못한다. 회랑 폭을 계측하는 정확한 솔버는 생성 난이도를 목표치로 맞출 때 필요해진다.

또한 **리듬/BPM 제약**([core-loop.md §12 ④](../../docs/kb/mda-analysis/core-loop.md))이 아직 생성기에 없다. 속도 축이 격자 간격을 스케일하므로 튜닝이 아니라 설계 사안이다.
