# Evaluation — Wave Runner

## 1단계 중단 판정 (가장 중요)

> **제작자 외 3명에게 아무 설명 없이 건넸을 때, 2명 이상이 지시 없이 5회 이상 재시도하는가.**

미달이면 프로젝트를 중단한다. 빌드도 게이트도 없는 기저 비행이 재미없으면 로그라이크가 구해줄 수 없기 때문이다. 시도 횟수는 스테이지 목록 화면에 표시되므로 관찰만으로 판정된다.

**현재 상태: 미수행.** 본 저장소 안에서는 측정할 수 없다.

## 자동 검증

| 검사 | 방법 | 현재 |
|---|---|---|
| 타입 | `pnpm --filter wave-runner lint` | 통과 |
| 빌드 | `pnpm build:project -- wave-runner` | 통과 |
| 선행 가시 시간 1.2초 | `node tests/smoke/lookahead.test.mjs` | 통과 (360×640에서 1.34초, 세로 가시 100%) |
| 5개 스테이지 통과 가능성 | `pnpm playtest --project wave-runner` (오토파일럿) | 통과 (5/5, 사망 0) |

### 통과 가능성 검사가 증명하는 것과 하지 않는 것

오토파일럿은 `window.__wave`로 통로 중앙을 정확히 질의하고 0.12초 선행으로 추종한다. 사람보다 훨씬 잘한다.

- **증명한다:** 다섯 코스가 현재 물리로 실제 통과 가능하다. 불가능한 구간이 섞여 있지 않다.
- **증명하지 않는다:** 난이도가 적절한가. 사망 0회는 "쉽다"는 뜻이 아니라 "완전 정보 에이전트에게 풀린다"는 뜻뿐이다. 난이도는 사람이 쳐봐야 안다.

## 손으로 확인할 것

- [ ] 조작 설명을 읽지 않고 첫 10초 안에 버튼의 의미를 파악하는가
- [ ] 사망에서 다음 시도 시작까지 체감 지연이 없는가 (설정 500ms)
- [ ] `running` 중 화면에 HUD가 하나도 없는가
- [ ] 세로 화면에서 한 손으로 플레이되는가 (가로 모드 강제 없음)
- [ ] 회랑(4번)에서 짧은 탭 연타가 실제 해법으로 기능하는가
- [ ] 60fps가 유지되는가 (T 패널의 FPS 표시)
- [ ] 브라우저 새로고침 후 클리어 기록이 남아 있는가

## 다음 단계를 위한 판정 — 부사 3축 중 셋째를 무엇으로 할 것인가

[core-loop.md §12 ①](../../docs/kb/mda-analysis/core-loop.md)의 미해결 쟁점. 크기 축은 작을수록 유리하기만 해서 양날이 아니다. 관성이 대안 후보다.

튜닝 패널(T)로 다음을 비교하고 결론을 `notes/decisions.md`에 남긴다.

- [ ] `radius`를 1.0 ↔ 2.6으로 바꿨을 때, 작은 쪽에 **불리한 점이 실제로 체감되는가**
- [ ] `inertiaMs`를 0 ↔ 120으로 바꿨을 때, 양쪽 모두 **다른 방식으로 유리한 구간이 있는가**
- [ ] 관성이 붙은 상태에서도 회랑(4번)이 통과 가능한가 (오토파일럿 재실행으로 확인)
