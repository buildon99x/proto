# 사용자 흐름 — 진입에서 이탈까지

> 코드에서 읽어 낸 현재(0.6.0) 동작이다. 기획 의도가 아니라 **지금 실제로 도는 것**을 적는다.
> 출처: `app/src/App.tsx`, `app/src/GameCanvas.tsx`, `app/src/game/engine.ts`,
> `app/src/game/meta.ts`, `app/src/game/storage.ts`, `app/src/styles.css`.

## 요약

상태는 두 층이다. **React 셸의 화면 4종**(`Screen`)과 **엔진의 런 페이즈 4종**(`Phase`)이
있고, 둘은 `onPhase` 콜백 하나로만 이어진다. 화면 전환은 전부 사용자의 명시적 클릭이고,
페이즈 전환은 하나(Stage 사망 → 재시작)를 빼면 전부 입력이나 충돌 판정이 일으킨다.

플레이어가 **런 안에서** 내리는 선택은 게이트 2지선다뿐이고, 그 외는 전부 홀드/릴리스의
연속이다. 나머지 선택(기체·모드·스테이지·해금·연습)은 전부 런 밖에 있다.

## 1. 신 전환 — 전체 도식

```
 [런처 카탈로그]
       │ iframe /runs/wave-runner/index.html
       ▼
 ┌─────────────────────────────────────────────────────────────────────┐
 │ 부팅 (App mount)                                                     │
 │  loadMeta()  localStorage "wave-runner/meta/v3"                      │
 │              └ 없고 v2 가 있으면 자동 이관(기록은 전부 표준 기체로)   │
 │  initTelemetry(meta.telemetry)  ← 지난 실행이 못 보낸 배치를 먼저 비움 │
 └─────────────────────────────────────────────────────────────────────┘
       ▼
 ┌──────────────────────────────────────────────────────┐
 │ taught 가 아니면 **홈보다 먼저** 안내                  │
 │  ╔═══════════╗  누른다 → 놓는다(각 0.2초)             │
 │  ║   INTRO   ║  두 동작을 익히면 마지막 누름이         │
 │  ╚═══════════╝  곧 티어 1-1 의 출발이다 ──────────────┼──▶ PLAY
 │   끄는 스위치가 없다. 그 누름이 taught 를 켠다         │
 │   한 신 · 스크롤 없음 · 보이는 글자 45자(6.4~9.0초)    │
 └──────────────────────────────────────────────────────┘
       │ taught 이면 곧장
       ▼
 ╔═══════════╗  코어 줄 클릭       ╔═══════════╗
 ║   HOME    ║ ──────────────────▶ ║   SHOP    ║
 ║           ║ ◀────────────────── ║  (해금)    ║
 ╚═══════════╝     ← 돌아가기       ╚═══════════╝
   │      │
   │      │ "Stage"            ╔════════════╗
   │      └───────────────────▶║  STAGES    ║
   │      ┌────────────────────║ (티어 4×3)  ║
   │      │    ← 돌아가기       ╚════════════╝
   │      ▼                          │ 셀 클릭 (tierUnlocked)
   │  ╔═══════════╗                  │ startStage(tier, no)
   │  ║   HOME    ║                  ▼
   │  ╚═══════════╝            ┌───────────┐
   │ "Endless"                 │           │
   │  (endlessUnlocked)        │   PLAY    │
   └──────────────────────────▶│ (캔버스)   │
        startEndless()         │           │
                               └───────────┘
                                     │
                    exitPlay()       │       advanceFromClear()
                    ① 좌상단 ← 버튼   │       ③ cleared 상태에서 아무 입력
                    ② Escape         │
                         ▼           ▼
                       HOME       STAGES (Stage 일 때)
```

**나가는 문이 둘이고 목적지가 다르다.** `←`/`Esc` 는 그만두기라 홈으로 가고, 클리어에서
누르는 것은 다음이라 목록으로 간다 — 목록에는 방금 채워진 클리어 표시 옆에 다음 칸이
있다. 한 콜백으로 합쳐 두면 같은 입력이 두 뜻을 갖게 되어 어느 한쪽이 반드시 틀린다.

### 화면별 조건과 자물쇠

| 화면 | 진입 조건 | 나가는 길 |
|---|---|---|
| INTRO | `meta.taught` 가 거짓 — 또는 홈의 **조작 안내** | 두 동작을 익힌 뒤의 누름 (첫 실행이면 1-1, 아니면 홈) |
| HOME | 부팅 직후, `taught` 일 때 | 모드 2택 · 코어 줄 · 조작 안내 |
| STAGES | 없음 | ← 돌아가기 · 셀 클릭 |
| SHOP | 없음(코어 0 이어도 열린다) | ← 돌아가기 |
| PLAY(stage) | `tierUnlocked` — 티어 1 은 항상, 이후는 **앞 티어 3칸 중 2칸 클리어** | ←/Esc/클리어 |
| PLAY(endless) | `endlessUnlocked` — **Stage 를 한 번이라도 클리어** | ←/Esc |

티어 해금은 기체를 보지 않고(`clearedByAny`), 기록·시도·클리어 표시는 기체별로 나뉜다.

## 2. 런 안의 페이즈 전환

```
                        press (pointerdown │ Space/W/↑)
        ┌─────────┐    ────────────────────────────▶  ┌─────────┐
        │  ready  │      launch() · attempts+1         │ running │
        │ 오버레이 │      onAttempt() → meta 저장        │ 오버레이 │
        │ (기체·  │      sfx.launch                    │  없음   │
        │  최고)   │                                    │         │
        └─────────┘                                    └─────────┘
                                                        │       │
                        충돌(hitsSector/hitsGate)         │       │ x ≥ finishX
                     ┌──────────────────────────────────┘       │ (Stage 전용)
                     ▼                                          ▼
              ┌─────────────┐                             ┌───────────┐
              │    dead     │                             │  cleared  │
              │ deathGap ·  │                             │ 결과 오버레이│
              │ 흰 X · 초록띠│                             │ (기록/코어) │
              └─────────────┘                             └───────────┘
                │         │                                     │
     Stage      │         │  Endless                            │ press
     500ms 자동 │         │  결과 오버레이 →                      │ (sincePhase>0.5)
     restart()  │         │  press(sincePhase>0.6)               ▼
                ▼         ▼  restart() + 시드 한 칸 전진       exitPlay() → HOME
             running   running
```

- **Stage 사망은 셸까지 올라오지 않는다.** `onRunEnd` 는 Endless 사망에서만 불린다.
  페이즈 자체는 `dead` 로 올라와 `data-phase` 를 바꾸지만(나가기 버튼이 잠깐 진해진다),
  오버레이는 뜨지 않고 0.5초(`retryDelayMs`) 뒤 스스로 처음부터 다시 시작한다.
- **Endless 에는 `cleared` 가 없다** — `finishX = Infinity`.
- **연습 모드**에서는 사망이 처음이 아니라 **마지막 체크포인트**(직전 게이트)로 되돌아간다.
  코스·빌드·경과 시각이 전부 복원된다.
- `restart()` 가 넘겨받는 것은 `attempts · best · holding · checkpoints · hud · record` 뿐이다.
  빌드는 시작 빌드로 되돌아간다 — 재시도는 실행을 다듬을지 해법을 바꿀지 고르는 자리다.

### 런 종료 시 일어나는 기록

| 결말 | 코어 | 기록 | 텔레메트리 |
|---|---|---|---|
| Stage 클리어(첫 클리어) | `80 + 티어×40` | `clearedStages` 추가 · `bestStageSec` 갱신 | `clear` |
| Stage 클리어(반복) | 0 | `bestStageSec` 만 갱신 | `clear` |
| Stage 클리어(연습) | 0 | 없음 | `prac` 플래그 |
| Stage 사망 | — | `attempts` 만 | `death` |
| Endless 사망 | `거리/60` 내림 | `bestDistance` 갱신 | `death` |
| 주행 중 이탈 | — | — | `abort` |

## 3. 사용자 입력 — 전체 표

### 3-1. 런 안 (캔버스)

```
  누름 ────────────▶ 상승          중립 없음. 가만히 있는 선택지가 없다.
  놓음 ────────────▶ 하강          전진은 자동. 1히트 즉사.
```

| 입력 | 장치 | 하는 일 |
|---|---|---|
| `pointerdown` / `Space` / `W` / `↑` | 터치·마우스·키보드 | **홀드 = 상승.** `press()` |
| 떼기 | 〃 | **릴리스 = 하강.** 활성 포인터가 **0개가 될 때만** 풀린다 |
| `Escape` | 키보드 | 즉시 나가기 → HOME |
| `H` | 키보드 | 주행 표시(진행 레일·숫자) 토글, `meta.hud` 에 저장 |
| 좌상단 `←` 버튼 | 터치·마우스 | 나가기. 44px, running 중 `opacity .22` / 그 외 `.75` |
| `T` | 키보드 | 개발 튜닝 패널 토글 (전역, 홈에서도 열린다) |
| `M` | 키보드 | 음소거 토글 (전역) |

**`press()` 는 페이즈마다 뜻이 다르다.** 같은 동작이 네 가지 결과를 낸다:

| 페이즈 | 조건 | 결과 |
|---|---|---|
| `ready` | — | 출발 (`launch`) |
| `running` | — | 상승만 |
| `cleared` | `sincePhase > 0.5` | **목록으로** (`onAdvance` → STAGES) |
| `dead` + Endless | `sincePhase > 0.6` | 다시 시작 (`restart`) |
| `dead` + Stage | — | 아무 일 없음(500ms 뒤 자동 재시작) |

유예 시간(0.5s/0.6s)은 사망·클리어 순간에 눌리고 있던 손가락이 결과 화면을 즉시
넘겨 버리는 것을 막는다.

**멀티터치를 세는 이유.** `pointerup` 하나로 홀드를 풀면 세로 모바일에서 두 엄지를
번갈아 누르는 순간 낙하한다. 활성 포인터를 `Set` 으로 세서 하나라도 닿아 있으면 홀드다.
탭이 포커스를 잃으면(`blur`) 전부 비운다.

### 3-2. 런 안의 유일한 "선택" — 교환 게이트

게임은 멈추지 않는다. **선택 행위가 곧 회피 조작이다.**

```
   ── 리드인(1.5초, 장애물 밀도 0) ──┬── 분기 ──┬── 합류 ──▶
                                    │  ╔═══╗  │
   [표식: 화면 우측 끝에 핀 고정]      │  ║위관║  │   endX 통과 순간
    ▲ 오르는 축의 쐐기                │  ╠═══╣  │   있던 관으로 확정
    ▬ 내리는 축의 막대                │  ║아래║  │   → applyTrade
    (양쪽 오르는 축이 같으면 쐐기 생략) │  ╚═══╝  │   → lanes += "t"/"b"
                                    └─────────┘   → 다음 게이트 armNextGate
                                                  → (연습이면 체크포인트)
```

- **한 축 +1, 다른 축 −1.** 순수 상승이 없어 게이트가 몇 개든 빌드가 포화되지 않는다.
- 제안은 **직전 게이트를 지날 때** 지금 빌드로 확정된다 — 화면에 들어오기 전에 끝난다.
- 칸막이는 0에서 자라났다 게이트가 끝나기 전에 사라진다. 어느 관이었는지는 그 전에 정해진다.
- Stage 한 런에 게이트 4개 = **2지선다 4회**. 이것이 런 안 결정의 전부다.

### 3-3. 런 밖 (React 셸)

| 화면 | 선택 | 즉시 저장 | 런에 미치는 영향 |
|---|---|---|---|
| INTRO | (선택이 아니라 **동작**) 누르기·놓기 | `meta.taught` | 끝나는 누름이 티어 1-1 의 출발이 된다 |
| HOME | 기체 4종(표준·둔각·예봉·환) | `meta.runner` | 시작 빌드와 축 곡선. 기록 키도 바뀐다 |
| HOME | 모드 2택 | — | `RunConfig.mode` |
| HOME | 주행 표시 토글 | `meta.hud` | 런 중에도 `H` 로 바뀜 |
| HOME | 기록 보내기 토글 | `meta.telemetry` | 끄면 **쌓인 큐도 버린다** |
| HOME | 소리 버튼 | 저장 안 됨(메모리) | — |
| STAGES | 티어·스테이지 12칸 | — | `tier`, `stageNo` |
| STAGES | 연습 모드 체크박스 | `meta.practice` | 체크포인트 · 기록/코어/티어 해금 없음 · 주행 내내 파선 테두리 |
| SHOP | 축 상한 ±2→±3 (320) | `meta.axisCap` | 게이트 제안의 폭 |
| SHOP | 확장 섹터 풀 (260) | `meta.fullPool` | **Endless 생성기에만** |
| SHOP | 진행도 내보내기/가져오기 | base64 텍스트 | 전체 교체 |

**확장 섹터 풀은 Stage 코스를 바꾸지 않는다.** 스테이지는 해금과 무관하게 수제 섹터 18개
전부를 쓴다 — 해금이 코스를 바꾸면 같은 번호가 다른 스테이지가 되어 큐레이션한 여유
수치가 그 즉시 무의미해진다.

## 4. 한 판의 시간축 (Stage, 기본 속도)

```
 0s        클릭 → ready 오버레이
 ~0s       press → launch. 오버레이 사라지고 화면에 남는 것은
           맨 위 3px 진행 레일 + 좌상단 경과 초 + 반투명 ← 버튼뿐
 ~13s      섹터 1 끝 → 게이트 1 리드인(1.5s) → 분기 → 교환 · 색 고리 0.6s · 음정
 ~30s      게이트 2
 ~47s      게이트 3
 ~60s      게이트 4
 ~67s      종료선 → cleared 오버레이 (이번/최고/시도 · 티어 3칸 기록 · 코어)
  +0.5s~   press → STAGES (방금 채워진 클리어 표시 옆에 다음 칸이 있다)

 사망하면  흰 X + 초록 띠 0.5초 → 자동으로 0s 부터 다시. 오버레이는 없다.
```

Stage 는 5섹터 + 4게이트 ≈ 2830 월드 단위. 1히트 즉사에서 시도당 비용을 낮추려는
의도적 이탈이다(core-loop 의 3~5분보다 짧다).

## 5. 흐름에서 드러난 마찰

경중 순으로 셋이었고 **0.6.1 에서 셋 다 고쳤다.** 무엇이 왜 틀렸는지를 기록으로 남긴다.

### ① 클리어 후 다음 스테이지로 갈 수 없었다 — 가장 큰 구멍 · 고침

`cleared` 오버레이는 **그 티어 세 스테이지의 최고 기록을 나란히 보여주면서**, 정작
누르면 `exitPlay()` 로 HOME 에 떨어뜨렸다. 다음 칸을 하려면 HOME → Stage → 셀로 세 번
더 눌러야 했다 — 티어 기록표가 "다음은 2번이다" 라고 말해 놓고 길을 끊는 셈이었고,
깨고 또 깨는 것이 주 동선인데 그 동선에만 마찰이 세 번 있었다.

고친 방식은 **콜백을 가르는 것**이다. `onExit` 은 그만두기(`←`·`Esc`)라 홈으로 가고,
새로 뚫은 `onAdvance` 는 클리어에서 누른 것이라 목록으로 간다. 하나로 합쳐 두면 같은
입력이 두 뜻을 갖게 되어 어느 한쪽이 반드시 틀린다 — 그게 정확히 ②가 나온 이유다.

### ② "누르면 계속" 이라 쓰고 나갔다 — 고침

`cleared` 오버레이의 마지막 줄이 `누르면 계속` 인데 실제 동작은 나가기였다. `dead`+Endless
의 `누르면 다시 · Esc 나가기` 는 정확하므로 이 한 줄만 결과와 어긋나 있었다. ①과 같이
고쳐 `누르면 목록으로` 다. **문구가 먼저 틀린 게 아니라 동선이 틀렸고 문구가 그것을
정직하게 못 적었을 뿐이다** — 문구만 고쳤으면 구멍이 그대로 남았다.

### ③ 연습 모드가 저장되지 않고, 켠 표시가 약했다 — 고침

`practice` 가 `useState` 라 새로고침에 사라졌고, 런 안에서는 `ready` 오버레이의
`티어 n · m · 연습` 한 줄이 전부였다. running 중에는 표시가 없어 **켠 채로 달리다가
클리어하고 나서야** "기록에 남지 않는다" 가 나왔다.

두 방향의 위험이 서로 반대라 둘 다 막아야 했다. **꺼진 줄 아는 것**(새로고침에 조용히
꺼지면 "죽었는데 왜 처음으로 가지" 가 되고 그건 조작 실수처럼 보인다)은 `meta.practice`
저장으로, **켠 줄 모르는 것**은 주행 내내 있는 표시로 막는다. 모르는 저장본만은 꺼진
것으로 읽는다(`hud`·`telemetry` 와 반대다) — 연습으로 열면 그 사람의 기록이 사라진다.

표시는 **화면 가장자리의 파선 테두리**다. 통로 위에 글자를 얹으면 시선 예산 조항과
정면으로 부딪히지만, 시선은 아바타(좌측 0.18)에서 오른쪽으로 훑으므로 가장자리는 그
경로 밖이다. **주행 표시(`H`)와 독립인 것이 요점이다** — 잊는 것을 막으려는 표시가
설정에 따라 사라지면 그게 정확히 실패하는 자리다.

**색이 아니라 파선인 이유는 처음에 색으로 했다가 부딪혔기 때문이다.** `--accent` 를
썼는데 그 값(`#ffe66d`)이 렌더의 `player` 와 같은 색이었다 — 아바타와 같은 색을 화면
테두리에 두르는 것은 `wallEdge` 가 각도 축과 같은 청록이던 사고와 같은 종류다. 남은
색을 찾는 게 아니라 애초에 색이 아니어야 한다. 파선은 월드 어디에도 없다.

### 곁가지

- 개발용 튜닝 패널(`T`)이 프로덕션에서도 전역 키로 열린다. 텔레메트리는 `dev` 플래그로
  그 런을 걸러 내므로 집계는 오염되지 않지만, 배포본에 열려 있는 것은 사실이다.
- SHOP 은 코어 0 에서도 열리고 두 항목 다 비활성 버튼으로 보인다 — 목표 제시로 읽히므로
  의도된 것으로 본다.
