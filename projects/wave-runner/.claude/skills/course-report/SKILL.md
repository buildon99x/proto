# 통로 난이도 보고서

무거운 부분(도구 두 개 실행 + 이미지 13장 판독)은 **서브에이전트에 맡기고**, 이 세션은 그림을
사용자에게 보내고 결론을 전하는 일만 한다. 이미지 13장을 본 세션에서 직접 읽으면 컨텍스트가 그대로
날아가고, 서브에이전트는 사용자에게 파일을 보낼 수 없다 — 역할이 갈리는 이유가 이것이다.

## 1. 분석을 위임한다

`Agent` 툴로 `wave-course-analyst` 를 띄운다. 그 정의에 절차와 주의사항이 전부 들어 있으므로
프롬프트에 되풀이하지 않는다. 사용자가 특정 관심사를 말했으면(예: "재큐레이션 후 달라진 점만")
그것만 덧붙인다.

`wave-course-analyst` 타입을 쓸 수 없으면 `general-purpose` 로 띄우되, 프롬프트 첫 줄에
**"`.claude/agents/wave-course-analyst.md` 를 먼저 읽고 그대로 따르라"** 를 넣는다.

기본은 백그라운드다. 그림을 굽는 데만 몇 분 걸리므로 기다리는 동안 다른 요청을 받을 수 있어야 한다.

## 2. 그림을 사용자에게 보낸다

에이전트가 끝나면 `SendUserFile` 로 **한 번의 호출에** 13장을 보낸다. 전체 시트를 맨 앞에 둔다.

```
projects/wave-runner/assets/screenshots/courses/overview.png
projects/wave-runner/assets/screenshots/courses/stage-{1..4}-{1..3}.png
```

읽는 법을 한두 문장으로 덧붙인다 — 회색은 벽, 크림은 들어갈 수는 있지만 끝까지 못 가는 자리,
파랑이 실제로 플레이되는 통로이고 진할수록 여유가 좁다. 아래 선은 최악 경로이고 30ms 아래에서
빨갛게 끊긴다.

## 3. 결론을 전한다

에이전트가 돌려준 결론 섹션을 **그대로 붙여넣지 말고** 이 대화의 맥락에 맞게 줄여 전한다.
보고서 파일 경로를 함께 알린다. 보고서 전문을 채팅에 쏟지 않는다 — 파일이 그 역할을 한다.

이전 보고서가 `projects/wave-runner/notes/course-difficulty/` 에 있으면 **무엇이 달라졌는지**를
먼저 말한다. 이 도구의 값어치는 대부분 전후 비교에서 나온다.

## 커밋

묻지 않고 커밋하지 않는다. 그림과 보고서는 저장소 안에 생기므로, 남길지 여부는 사용자가 정한다.

## 이 스킬이 하지 않는 것

재큐레이션(`curate-stages.ts` 실행)은 별개다. `stage-seeds.json` 이 바뀌면 저장된 `bestStageSec`
기록이 다른 코스의 것이 되므로, 점검과 같은 호흡에 끼워 넣지 않는다. 보고서가 재큐레이션을
권하면 그 말을 전하는 것까지가 이 스킬의 일이다.
