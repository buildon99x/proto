# Spec — Wave Runner

> **현재 구현 범위는 1단계 수직 슬라이스다.** 빌드·게이트·Endless·솔버는 들어 있지 않다.
> 전체 설계는 [core-loop.md](../../docs/kb/mda-analysis/core-loop.md) 참조.

## 개요

캔버스 2D 원버튼 회피 게임. React는 얇은 셸(스테이지 선택 + 개발 패널)이고, 게임 로직·물리·렌더는 순수 TypeScript 모듈(`app/src/game/`)이다.

## 좌표계

- 월드 y는 0(위) ~ `worldHeight`(아래, 기본 100). x는 0에서 스테이지 길이까지.
- 화면 변환은 `camera.ts`가 담당한다. 아바타는 화면 좌측 `cameraAnchor`(0.28) 지점에 고정된다.

### 줌 — 선행 가시 시간이 구조적으로 보장되는 지점

```
fit  = canvasH / worldHeight            // 월드 높이가 화면에 들어가는 배율
cap  = canvasW / (speed × 1.2)          // 선행 1.2초를 보장하는 최대 배율
zoom = min(fit, cap)
```

`cap`이 걸리면 위아래 레터박스가 생기지만, **화면 우측 끝 장애물이 최소 1.2초 뒤에 도달한다**는 설계 상수가 해상도와 무관하게 성립한다. `tests/smoke/lookahead.test.mjs`가 최소 뷰포트(360×640)에서 이를 회귀 검사한다.

## 조작

| 입력 | 의미 |
|---|---|
| Space / W / ↑ / 클릭 / 탭 (누름) | 상승 |
| 뗌 | 하강 |
| T | 개발 튜닝 패널 토글 |
| M | 음소거 |
| Esc | 스테이지 목록 |

중립 상태는 없다. 손을 떼는 것도 입력이다.

## 물리 (`engine.ts`)

고정 스텝 1/240초로 적분한다.

```
target = (holding ? -1 : +1) × slope × speed     // 음수가 위
vy     = inertiaMs <= 0 ? target
                        : vy + (target - vy) × (1 - e^(-dt/τ)),  τ = inertiaMs/1000
x += speed × dt
y += vy × dt
```

`inertiaMs = 0`이 원작의 거동(즉시 반응)이다. 0보다 크면 방향 전환에 관성이 붙는다 — 이 값은 [core-loop.md §12 ①](../../docs/kb/mda-analysis/core-loop.md)의 미해결 쟁점을 손끝으로 판정하기 위해 노출되어 있다.

충돌은 한 스텝의 이동 구간을 반지름의 절반 간격으로 스윕 샘플링해 검사한다. 통로 경계 이탈 또는 블록 원-사각 겹침이면 즉사.

## 코스 (`stages.ts`)

통로는 상/하 경계 폴리라인(`CorridorNode[]`)이고 그 사이를 선형 보간한다. 통로 안의 이빨은 축 정렬 사각형(`Block[]`)이다. 절차적 생성은 3단계 사안이므로 여기서는 전부 수제다.

| # | 이름 | 무엇을 묻는가 | 길이 |
|---|---|---|---|
| 1 | 첫 물결 | 누르면 오르고 놓으면 내려간다 — 그것만 | ~12초 |
| 2 | 좁아지는 길 | 같은 조작을 더 작은 여유에서 | ~14초 |
| 3 | 톱니 | 지나갈 곳을 미리 고르고 진입한다 | ~15초 |
| 4 | 회랑 | 중립이 없는 곳에서 직진을 만들어낸다 | ~17초 |
| 5 | 합류 | 넷을 이어서 | ~18초 |

**4번 회랑이 설계의 회수 지점이다.** 좁고 긴 수평 통로는 짧은 탭 연타로 사실상의 직진을 합성해야 통과된다 — 원작에서 플레이어가 스스로 발명한 기술을 여기서는 의도된 해법으로 요구한다. 메커니즘은 한 줄도 추가하지 않았다.

## 상태 머신 (`Phase`)

- `ready` — 스테이지 진입. 첫 입력이 출발시킨다.
- `running` — 비행.
- `dead` — 접촉. `retryDelayMs`(500ms) 후 **자동으로** 스테이지 처음부터 재시작한다. 확인 입력 없음.
- `cleared` — 종료선 통과. 0.5초 후 입력하면 목록으로.

## 화면

- **스테이지 목록** — 5개. 앞 스테이지를 클리어해야 다음이 열린다. 클리어 기록(초)과 누적 시도 횟수를 표시한다(시도 횟수는 1단계 중단 판정 관찰용).
- **플레이** — 캔버스 전체. `running` 중에는 HUD가 없다. `ready`/`cleared`에서만 오버레이가 뜬다.
- **튜닝 패널(T)** — 개발 전용. 각도·속도·관성·크기를 실시간 조정하고 선행 가시 시간과 FPS를 표시한다. 본 플레이에서는 숨어 있다.

## 사운드 (`audio.ts`)

WebAudio 즉석 합성. 출발·사망·클리어 세 가지뿐이다. 음악과 리듬 동기화는 [core-loop.md §12 ④](../../docs/kb/mda-analysis/core-loop.md)의 미해결 사안이므로 넣지 않았다.

## 영속화 (`storage.ts`)

`localStorage["wave-runner/progress/v1"]`에 클리어 목록·최고 기록·누적 시도를 저장한다. 저장이 불가능한 환경(프라이빗 모드 등)에서도 플레이는 계속된다.

> 빌드와 영구 해금이 들어오는 2단계에서는 이 정도로 부족하다. Save System Integrity가 ★★★★로 승격되므로 내보내기/가져오기가 필요하다.

## 튜닝 상수 (`tuning.json`)

`tuning.json`이 유일한 상수 출처이며, 앱과 스모크 테스트가 같은 파일을 읽는다.

| 키 | 기본 | 의미 |
|---|---|---|
| `worldHeight` | 100 | 월드 세로 크기 |
| `speed` | 42 | 전진 속도(월드 단위/초) |
| `slope` | 1.0 | 대각 기울기. 1.0 = 45° |
| `inertiaMs` | 0 | 방향 전환 관성. 0 = 원작 |
| `radius` | 1.6 | 히트박스 반지름 |
| `lookaheadMinSec` | 1.2 | 선행 가시 시간 하한 |
| `cameraAnchor` | 0.28 | 아바타의 화면 좌측 고정 위치 |
| `retryDelayMs` | 500 | 사망 후 자동 재시작까지 |
| `fixedStepHz` | 240 | 물리 고정 스텝 |

## e2e 훅

`window.__wave = { state, centerAt(x) }`를 노출한다. 자동 플레이테스트가 통로 중앙을 질의해 오토파일럿을 돌린다(`tests/e2e/scenario.mjs`).
