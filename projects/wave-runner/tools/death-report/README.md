# 사망 보고서

수집한 런 결말로 **솔버의 난이도 수치가 사람 체감과 어디서 어긋나는지**를 본다.
솔버는 난이도를 이미 수치로 안다 — 여기서 새로 얻는 것은 그 어긋남뿐이다.

## 세 걸음

```bash
# 1) 내려받기 — 배포본(Vercel Blob)
./pull.sh tele/wave-runner/8f3a91c2/ deaths.ndjson
#    개발 중 .telemetry/ 에 쌓인 것
./pull.sh --local deaths.ndjson

# 2) 보고서 — 표 A~D 를 찍고 그림용 요약을 남긴다
pnpm exec tsx projects/wave-runner/tools/death-report/report.ts deaths.ndjson --json summary.json

# 3) 그림 — 여유 곡선 위에 실측 사망을 겹친다
node projects/wave-runner/tools/death-report/figure.mjs summary.json deaths.png
```

접두사에 **코스 지문**을 넣는 것이 기본이다. 0.5.5 에서 시드표가 통째로 갈렸듯 코스는
버전마다 다른 코스이고, 섞으면 어긋난 티가 나지 않는다. 전부 받았다면 보고서가 가장 큰
지문만 쓰고 나머지는 세어서 알려 준다.

## 무엇을 답하는가

| 표 | 무엇 | 왜 |
|---|---|---|
| A | 섹터별 조건부 사망률 | 분모가 **진입 횟수**다. 사망만 세면 Stage 가 스스로 재시작하는 탓에 언제나 앞 섹터가 가장 어렵게 나온다 |
| B | 여유 구간별 사망률 | **티어 목표치를 데이터로 다시 정하는 근거.** 지금 200/180/150/130ms 는 프로브 추정이다 |
| C | 경로별 사망률 | 큐레이션이 통과 가능성은 보장한다. 여기서 찾는 것은 *가능하지만 사람이 못 하는* 경로다 |
| D | 시도 분포 | brief 의 미수행 중단 판정("지시 없이 5회 이상 재시도")이 직접 읽힌다 |

## 알아 둘 것

- **표본 바닥**: 섹터당 **진입** 30건, 스테이지당 주행 20건. 분모를 사망이 아니라 진입으로
  잡는 것이 중요하다 — 진입 174 에 사망 0 이면 "여기서는 안 죽는다"가 충분히 서지만,
  사망 수로 바닥을 재면 그 행이 영원히 보류로 남는다. 미만이면 표가 `보류` 로 표시하고
  그림은 `표본 부족` 을 적는다. 숫자는 나오지만 판정은 서지 않는다.
- **제외**: 연습 모드 · 튜닝 패널 · 50fps 미만 · Endless. 앞의 셋은 다른 게임이고,
  Endless 는 자리 3번부터 통로 좌표가 재현되지 않는다.
- **이탈 지점 `k*`**: 설계 때는 사망 x 가 원인보다 한참 하류일 것이라 보고 상계를 계산하게
  했는데, 재 보니 **중앙 1.1 · 최대 5.2 월드 단위**였다(섹터 하나가 460). 생존 회랑을 죄는
  쪽 경계가 곧 부딪히는 벽이라 두 자리가 사실상 같다. 그래서 사망 x 로 집계해도 섹터
  단위에서는 틀리지 않고, 실제 이탈 지점을 알려면 궤적 표본(`tail`)이 있어야 한다.
- **그림의 여유 곡선은 코스 전체 회랑**이다. 솔버의 조각별 수치(큐레이션이 쓰는 값)보다
  좁게 나온다 — 후진 훑기가 조각 끝에서 끊기지 않기 때문이다.

## 데이터가 없을 때

`simulate.ts` 가 오토파일럿으로 **합성** 데이터셋을 만든다. 실제 엔진과 실제 이벤트
빌더를 쓰므로 스키마와 좌표는 수집본과 같은 모양이다.

```bash
pnpm exec tsx projects/wave-runner/tools/death-report/simulate.ts synth.ndjson 16
```

**이것은 사람 데이터가 아니다.** 오토파일럿은 시야가 완벽하고 통로 중앙이 아니라 빈 틈을
향하므로 사람이 어디서 죽는지를 말해 주지 않는다. 파이프가 도는지만 본다. 보고서와 그림은
지문이 `synthetic` 이면 그렇게 표시한다.
