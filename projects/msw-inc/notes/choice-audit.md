# 선택 점검 — 선택 하나가 진행을 얼마나 가르는가

> MSW 주식회사 v1.0 · 2026-09-25 · 재현: `pnpm --filter msw-inc run audit` (v1.1·v1.2 나란히), `pnpm --filter msw-inc run audit -- --ablate` (하나씩 빼 보기). 원자료는 [data/](data/)에 있다.

## 1. 결론

**컨셉 v1.1에서는 선택 하나가 진행을 "느리게"가 아니라 "멈추게" 했다.** 봇 8성향 × 체크인 시각을 흔든 5번, 모두 40번을 최대 70일씩 굴린 결과다.

- **40번 중 13번은 즐기는 모험가 0명으로 월드가 멈췄다.** 밤에 진화하고 떠나는 성향은 5번 모두, 체크인이 잦은 성향은 3번, 표준 성향도 1번 멈췄다.
- 진화를 아끼는 성향은 **2장을 영영 넘지 못했다.**
- 엔딩에 닿은 것은 **22번**뿐이다. 닿은 경우에도 표준 성향은 **D11.8에 엔딩**을 봤다. 컨셉이 약속한 5주(D28~35)의 3분의 1이다.

**v1.2에서는 40번 모두 엔딩(D27.4~38.5)에 닿고, 멈춘 월드는 0이다.** 성향별 중앙값은 D27.6~35.9다. 가장 느린 성향도 표준보다 2.6일(8%) 늦을 뿐이다. 고친 것은 두 갈래다.

- **차이 줄이기:** 빈틈 걷기, 결재 ②를 누적 즐거움으로
- **되돌리기와 출구:** 모든 결정 5초 되돌리기, 승진 발령, 본사 전근, 꽉 찬 던전에 놓기, 정직한 "키워서 잇기" 안내

하나씩 빼 보면 **빈틈 걷기**와 **누적 즐거움 결재**가 가장 큰 차이를 막는다. **승진 발령**과 **본사 전근**은 특정 성향의 교착을 막는다.

> **점검 도중 바로잡은 것:** 처음에는 "시드 5개 중앙값"을 썼지만 다섯 값이 모두 같았다. 월드 규칙은 결정적이고, 난수는 모험가의 외형만 바꾼다. 그래서 시드마다 **체크인 시각을 ±90분 흔들어** 실제 변동을 만들었다. 사람은 매일 같은 시각에 들어오지 않는다. 아래 수치는 모두 이 방식으로 다시 잰 값이다.

## 2. 방법

### 2.1 봇 매니저 — "오렌 따라하기"
사람을 흉내 내는 봇 하나를 만들고(`app/src/sim/bots.ts`), 화면이 권하는 순서대로 움직이게 했다.

> 결재 도장 → 발록 배치 → 빈틈(옮기기로 되면 옮기고, 아니면 추천 계열 채용 → 초록 자리, 그래도 안 되면 던전 하나를 비워 다시 열기, 채용으로 안 닿으면 키워서 잇기) → 길을 잇는 진화 → 대기실 → 과밀(자리 확장) → 결재 ②가 모자라면 자리·던전 늘리기 → 나머지 진화 → 이벤트

체크인마다 행동 수에 상한을 둔다(표준 3). 봇은 결과 미리보기를 전부 계산하므로 사람보다 빠른 쪽으로 읽힌다.

### 2.2 성향 — 선택 한 가지만 바꾼다

| 성향 | 바꾼 선택 |
|---|---|
| std 표준 | 하루 3회(9·13·21시), 3수. 진화는 따져 보고(새 빈틈이 없거나, 생겨도 바로 메울 수 있을 때) |
| light 가벼운 | 하루 2회, 2수, 이벤트 안 씀 |
| heavy 열성 | 하루 5회, 4수 |
| hasty 진화 즉시 | ▲가 뜨면 결과를 보지 않고 누른다 |
| hoarder 진화 보류 | 길을 잇는 데 필요할 때만 진화한다 |
| stack 몰기 | 신입을 빈 슬롯이 있는 던전부터 채운다 |
| spread 펼치기 | 신입을 빈 부지부터 연다(한 던전에 한 마리) |
| night 퇴근 직전 진화 | 하루 마지막 체크인에서 진화 가능한 직원을 전부 누르고 떠난다 |

### 2.3 재는 것
시드 5개(7·11·23·42·99)의 중앙값으로 잰다. 시드는 날마다·체크인마다 시각을 −90~+90분 흔든다(`bots.ts`). 월드 규칙 자체에는 난수가 결과를 바꾸는 곳이 없다.

- 챕터별 결재한 날(D). 절반 넘게 70일 안에 못 끝내면 "—"로 적는다.
- 입구 막힘 시간
- **멈춘 월드:** 끝날 때 즐기는 모험가가 0인 시드 수
- 체크인당 행동 수, 스마일 최고치

### 2.4 이식 검증
규칙을 TypeScript로 옮긴 뒤 옛 규칙(V11)으로 굴렸다. 컨셉 프로토타입의 `pacing-check.js`와 수치가 **똑같이** 나오는지 확인했다(`tests/sim.test.ts` 첫 테스트).

- 첫 레벨업 0:25, 첫 빈틈 3:25(Lv 8)
- 10시간 뒤 첫 출근: 😊 14 · 레벨업 678 · 스마일 3,269
- 남은 달팽이를 진화시키면 Lv 1–2가 비고 4명이 갈 곳을 잃는다

그러니 아래 v1.1 결과는 봇이 아니라 규칙의 결과다. 단, 컨셉은 3장까지만 콘텐츠가 있었다. 그래서 4·5장 계열(가칭)을 같은 원칙으로 채워 굴렸다.

### 4.1 차이 줄이기 — 벌을 "멈춤"에서 "느려짐"으로

## 6. 결재 허들이 플레이를 막지 않게

사용자가 짚은 "결재 허들"은 v1.1에서 실제로 벽이었다. 조건 ②(동시 N명)는 자리를 늘리면 금방 차고, 인원이 모자라면 영영 닿지 않았다. 결재 전에는 새 지역·계열·부지가 열리지 않으니, 벽 앞에서는 할 일도 사라졌다.

v1.2는 이렇게 푼다.

1. **조건 ②를 누적으로.** 월드가 도는 한 막대는 줄지 않고 차오른다. 서툰 월드는 느리게 찰 뿐 멈추지 않는다.
2. **"언제 차는지"를 보여 준다.** 결재함과 리포트에 "지금 😊 N명이면 약 X일, 줄지 않아요". 오렌은 할 일이 없을 때 결재 진행률을 말한다.
3. **조건 ①(구간 연결)에는 늘 다음 수가 있다.** 채용 추천, 채용으로 안 닿으면 키워서 잇기, 둘 곳이 없으면 자리를 사서 놓기, 부지가 없으면 본사 전근. 봇 8성향 × 체크인 시각을 흔든 5번 = 40번 굴려 **40번 모두 엔딩**에 닿았다.
4. **서류는 올라와 기다린다.** 떠나 있는 동안 조건이 차도 도장은 매니저가 찍는다. 늦게 찍어도 잃는 것이 없다. ② 누적은 새 장부터 다시 센다.
