# 방향 제어 권고 — 2026-10-15

이번 변경에서는 조작 체계를 바꾸지 않았다. 추천은 **PC는 마우스로 원하는 낙점, 모바일은 코트의 좌·중·우를 탭하는 현재 방식을 유지하고, 코스 안내와 탭 피드백을 먼저 보강**하는 것이다. 좌우 드래그를 필수 조작으로 추가하지 않는다.

## 현재 동작과 확인 결과

- PC: 마우스를 가리키는 곳을 코트 평면으로 투영해 실제 x/z 목표를 정한다. 기존 금색 조준 링이 그 위치를 표시한다. 클릭/우클릭/Shift 또는 기존 샷 버튼이 타구 의도를 정한다.
- 모바일: 누르는 순간의 코트 좌표로 코스를 예약한다. 손을 움직여도 그 시작 목표는 유지된다. 세로 이동22px 이상은 기존 CLEAR/DROP 선택이다. 수평 이동은 현재 코스 제어에 쓰이지 않는다.
- 실제 네이티브 에뮬레이션에서 좌·우 탭은 약-1.8m /+1.8m의 서로 다른 실제 목표와 발사 속도로 이어졌다. 수평42px 이동은 시작한 중앙 코스를 유지했다.
- 수평42px+세로26px 대각선은 수평 성분이 더 커도 DROP으로 분류됐다. LOW 검사에서는 실제 드롭이 나왔다. MEDIUM 검사에서는 분류 제출이 준비 마감 뒤 도착해 `accepted:false`, 실제 타구는 예약된 CLEAR였다. 이미 활성화한 타구를 뒤늦게 바꾸지 않는 기존 보호 규칙과 일치한다. 초기에 분류/타구가 다르다는 실패도 그대로 보존했다; 뒤의 계측 재생은 이 마감 조건을 드러낸다. 기존 표준 세로 스와이프 검사도 현재 MEDIUM 소프트웨어 환경에서 같은 마감 실패가 났다. 격리해 빌드한 수정 전 bff2778에서도 동일 조건 실패가 재현돼 이번 AI 수정만의 회귀로 판단하지 않는다. 기본 탭 회귀와 LOW의 실제4입력 검증은 통과했다. 실기기 지연으로 일반화하지 않는다.

## 구체적인 다음 소규모 안

1. PC에서는 현재 연속 좌표 조준을 유지한다. 상대 코트에 좌·중·우 영역을 연하게 표시하고, 금색 링과 같은 위치의 짧은 안내로 “가리킨 곳으로 보냅니다”를 보여준다. 필수 키나 버튼을 추가하지 않는다.
2. 모바일에서는 코트 좌·중·우의 넓은 탭 영역과 누른 코스의 짧은 강조를 우선 시제품으로 비교한다. 손가락 아래의 정밀한3D 점을 겨냥하는 부담을 줄이는 목적이다. 실제 매핑을 바꾸는 소프트 스냅은 연속 조준과 비교해 검증한 뒤 결정한다. 깊이는 기존 샷 의도와 합법적 상황별 기술 전환을 계속 활용한다.
3. 기존 세로 스와이프는 선택 기능으로 남긴다. 초심자는 기존 샷 버튼과 탭만으로 랠리를 이어갈 수 있어야 한다.

| 안 | 조작 부담/충돌 | 권고 |
|---|---|---|
| 현재 클릭·탭 낙점 + 코스 가이드/피드백 | 새 제스처가 없고, 현 세로 샷 선택과 분리된다 | 우선 적용 후보 |
| 모바일 좌·중·우 소프트 스냅 | 작은3D 코트의 정밀 탭 부담을 줄일 수 있으나 기존 자유 조준이 바뀐다 | 작은 비교 시제품 후 결정 |
| 짧은 좌우 드래그 조준 | 현재 세로22px 분류와 대각선에서 충돌하며, 준비 시간도 추가로 소비한다 | 이번 단계에서는 비추천 |
| 별도 방향 키/방향 버튼/복잡 조합 | UI와 필수 학습을 늘린다 | 추가하지 않음 |

추후 좌우 드래그를 실험한다면 주축 판정과 축 잠금, 대각선 경계, 이미 예약된 타점/시간 보존, 늦은 변경의 시각 피드백을 먼저 검증해야 한다. 축 잠금조차 손동작 학습을 요구하므로 현재 요청의 “쉽고 직관적” 목표에서는 탭 안내보다 우선하지 않는다. 사람의 초심자 이해도와 실기기 성능은 별도 검증이 필요하다.

## 모바일 입력 후속 수정

위 MEDIUM 실패 기록은 당시 번들의 역사적 결과다. [입력 후속 검증](../verification/mobile-input-20261015/README.md)에서는 raw 이동 이벤트와 pointermove 대체 경로를 같은 예약에 한 번만 적용하고, 예측 접촉45ms 전이라는 조기 마감을 첫 실제 hit-frame/판정 시점까지 열었다. 시작 조준·입력 시간·스윙 시계는 유지한다. 첫 판정 이후 분류·취소는 기존 타격을 바꾸지 않는다. 보조 손가락은 예약을 덮어쓰거나 취소하지 않는다. 추가로 프레임당 따라잡기를120Hz4스텝(약33ms)으로 제한해 저프레임에서 입력 사이 준비 시간이 한꺼번에 소진되는 문제를 줄였다.30fps 미만에서는 시뮬레이션이 느려지는 절충이 있다. 방향 매핑·22px 세로 임계값·기존 세 버튼은 그대로다. 실제 접촉보다 늦게 도착한 이벤트를 소급 반영하지 않으므로 임의의 브라우저 정지는 복구 보장 대상이 아니다. 실기기·Safari·실청음은 여전히 미검증이다.
