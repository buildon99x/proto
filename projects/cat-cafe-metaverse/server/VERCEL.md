# Vercel 공개 실시간 베타 운영 안내

## 현재 상태
0.3.0은 이전 구현 후보입니다. 로컬 테스트와 실제 Redis/Lua, 실제 배포 WebSocket, 실제 화면·소리 검증은 별도 단계입니다. 실제 공급자 진단 및 공개 두 방문자 검증 결과가 기록되기 전에는 서비스가 완성되었다고 표현하지 않습니다.

## 구성
- 기존 Next launcher의 `/api/cat-cafe-metaverse/status`, `/ws` 경로만 추가합니다. 실제 WS URL은 `/api/cat-cafe-metaverse/ws`입니다.
- 새 두 함수는 `hnd1`, 기존 telemetry 및 다른 프로젝트 지역은 변경하지 않습니다.
- Next 함수는 로컬 소켓·전송 델타 기준만 보관합니다. 방·고양이·좌석·예약·중복 결과는 승인된 공유 Redis의 단일 fenced authority가 소유합니다.
- 전역 6석은 연결 중인 방문자와20초 재접속 예약을 합산합니다. 기존3개 방과18마리씩의 고양이, 모델상 방당100석은 유지합니다.
- 요청 수명에 묶인 게이트웨이만 작업합니다. 마지막 연결 종료 후 disconnect를 전송하고 lease를 해제하며, 빈 카페의 주기 작업은 없습니다. 예약 만료는 다음 입장에서 정리합니다.
- 100ms 간격을 목표로 durable batch를 처리하며, 정상 지연 구간은50ms 물리 하위 단계를 최대4회 통합합니다. 250ms 초과 중단 뒤에는 최대1단계만 처리합니다. 이는 실제20Hz 보장이 아니며 공급자 왕복 지연과 관측된 속도를 별도로 보고해야 합니다.
- 함수 종료 전에270초 경과 소켓을1012로 닫습니다. 클라이언트는 지터 포함 최대8회 재접속하며, 일시적 SESSION_EXPIRED/TOKEN_IN_USE에서 토큰을 유지합니다. 방문자의120초 사용 제한은 없습니다.

## 서버 전용 변수 — 정확한 작업 브랜치 Preview만
`codex/cat-cafe-metaverse`의 Preview에만 아래를 설정합니다. main/Production/다른 브랜치에는 설정하지 않습니다.
- `CAT_CAFE_REDIS_REST_URL`
- `CAT_CAFE_REDIS_REST_TOKEN` (Sensitive)
- `CAT_CAFE_REDIS_DIAGNOSTIC=bootstrap-once` — 아래 초기 진단 빌드에만 잠시 사용 후 제거.
- `CAT_CAFE_REALTIME_ENABLED=1` — 실제 공급자 진단과 코드 검토가 끝난 후에만 설정. 없으면 공개 실시간 경로는 비활성.

자격증명은 브라우저 코드·VITE 변수·로그·소스·로컬 파일에 넣지 않습니다. 현재 권한은 무료 DB와 이 브랜치의 서버 자격증명 연결이며 유료 전환·main 병합·새 보안 설정은 포함하지 않습니다.

## 최초 초기화와 공급자 시험
루트 `build:vercel`의 조건부 진단은 정확한 Preview/브랜치/flag가 모두 맞을 때만 프로젝트의 `distributed/diagnostic.mjs`를 호출합니다. 그 외 빌드는 Redis를 가져오거나 접속하지 않습니다. 공개 관리자 API는 없습니다.

1. 공유 상태를 먼저 확인합니다. 완전히 새 상태일 때만 NX 방식으로 두 키를 초기화합니다. 이미 존재하는 상태/예산을 덮어쓰거나 리셋하지 않습니다. 충돌은 중단합니다.
2. 실제 Lua로 두 방문자, follower의 미커밋 ack 금지, 동일 명령 재전송,5.1초 lease 종료 뒤 takeover와 stale commit 거부, 방 분리, 새 연결 세대 재접속, 늦은 예전 세대 무효화를 검사합니다.
3. 짧은 실제 이동 구간의 wall time/World step/이동량과 요청·응답 바이트를 기록합니다. 자동 시험 성공은 실제 GPU·청음·휴대전화 검증이 아닙니다.
4. 진단 종료 시 좌석을 반환하고 lease를 해제합니다. 진단 flag를 제거합니다. 비용 카운터는 남겨 사용자에게 남은 시험 가능량을 알립니다.
5. 공개 활성화 뒤 배포된 동일 출처 WS에 독립 두 방문자로 접속해 상태 공유와 재접속을 확인합니다. 해당 결과 없이 공개 서버 성공을 주장하지 않습니다.

## 예산과 실패 동작
- 공유 기본 한도: 일100,000 / 월350,000 보수적 명령 수, 일256MiB / 월1GiB 애플리케이션 페이로드, 일30분 카페 활성시간. 실제 가장 먼저 소진되는 한도를 적용합니다. 일·월 기준은 Redis의 UTC 시간입니다.
- 활성시간은 방문자 수를 곱한 시간이 아니라 카페에 방문자가 있는 시간입니다. Redis 스크립트 내부 명령, 재시도/초기화 및 요청·응답 비용을 보수적으로 계상합니다. 커밋 시6명에게 full snapshot을 보낼 수 있는 비용을 예약하므로 실제 델타 전송보다 과대 계상할 수 있습니다.
- 예산 키는 배포/authority namespace가 바뀌어도 같은 리소스 전역 키이며 TTL로 삭제하지 않습니다. 현재 카운터나 초기화 marker가 사라지면 일반 런타임은 새 한도를 만들어내지 않습니다.
- 상태 API의 공급자 확인은 함수 인스턴스당15초 single-flight cache입니다. 인스턴스가 여러 개 생기면 확인 호출도 늘어납니다. 공개 트래픽과 Vercel 요청은 애플리케이션 거부 전에 비용을 일으킬 수 있습니다. 따라서 이 카운터는 공급자 청구 상한이나 DDoS 방어가 아닙니다.
- Free DB의 실제 쿼터/지원 조건이 우선합니다. 유료 업그레이드는 하지 않습니다. 할당량 소진·저장소 오류는 live 입장 중단으로 표시하고 솔로 모드를 유지합니다. 자동으로 가짜 멀티플레이로 바꾸거나 무한 재시도하지 않습니다.
- 50–100명/방의 실제 공급자 부하 시험은 별도 자원 예산 승인 후에 실시합니다. 초기 공개6석 테스트로 그 용량을 검증했다고 말하지 않습니다.

## 로컬 검사
```sh
npm --prefix projects/cat-cafe-metaverse/server test
npm --prefix projects/cat-cafe-metaverse/app test
corepack pnpm --filter launcher test
corepack pnpm build:vercel
```
로컬 `next dev`는 Vercel `upgradeWebSocket` 검증 수단이 아닙니다. 공식 API의 로컬 개발은 Vercel CLI54.14.2 이상 `vc dev`가 필요합니다. 기존 독립 Node/ws 서버는 계속 별도로 실행할 수 있습니다. 원격 build-only Redis 진단은 로컬 비밀정보 반출 없이 수행합니다.
