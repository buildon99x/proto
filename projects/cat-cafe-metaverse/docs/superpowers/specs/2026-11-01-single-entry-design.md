# Single in-flight entry

The user requests continued real-use quality improvement, not additional features. Actual production-main traces reproduce repeated settings → entry replacing a CONNECTING socket or an OPEN socket awaiting welcome. The server may already have accepted an unacknowledged join; that possibility is not a measured provider incident.

## Approach
Keep one same-endpoint in-flight entry and its existing 6-second transport / 15-second welcome deadlines. Repeated entry closes the dialog and explains the wait instead of creating another socket. Temporarily block room selection during initial admission, with explicit feedback; manual Leave cancels, and established live room switching remains unchanged. Replacing every pending socket is rejected because it loses the admission outcome. Adding server deduplication/schema changes is unnecessary for this client defect.

## Limits
No server, budget, credentials, dependencies, authority migration, main promotion or live test traffic. Preserve renderer failure gating, background cancellation and retries. Automated main execution is not actual 3D play.
