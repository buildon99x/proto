# Safari R3: observed interaction defects

## Evidence and bounded scope
Actual authorized MacBook Safari R2 confirmed room-switch selection reset and position disclosure. Help is visually present and Return/Escape/focus restore work, but its contents and close button are absent from Safari accessibility output. Action notices exist in the accessibility tree but are visually behind the expanded bottom card. Ball is not identifiable in immediate/later close-up captures.

The ball hypothesis was reproduced in the actual solo/server simulation: valid default cat-14 action, 80 ticks over 4 seconds; solo center separation remained zero, server separation stayed below 0.10m. This is less than the cat body footprint, so increasing radius/contrast did not address the underlying overlap. This is source/simulation evidence, not an additional pixel observation.

## Plan
1. Replace fixed notice bottom offsets with measured card/footer layout, responding to panel and viewport resize; retain safe-area spacing. Add regression tests.
2. Test a help-only, body-level non-top-layer accessible dialog overlay with explicit inert background, focus trap, Escape and focus restoration. Preserve native welcome dialog. Actual Safari AX is the acceptance test, not DOM assertions alone.
3. Preserve the active 20-minute soak server baseline until its terminal cleanup. Then implement shared solo/server ball placement and movement clearance, keeping lifetime, authority, ownership, cooldown and idempotence. Check placement before changing leases. Cover walls, furniture and bouncing/contact cases; no renderer-only fictional position.
4. Run focused unit/integration/build checks and independent review, publish working-branch candidate, request same-device Safari R3.

## Evidence boundaries
The ongoing 20-minute soak applies to the pre-ball-physics server revision. Any later changed simulation receives separate tests and a bounded integration smoke; do not claim the final physics revision was soaked for 20 minutes. Public realtime hosting/budget, actual listening, physical mobile touch and rendered crowd FPS remain independent open gates.
