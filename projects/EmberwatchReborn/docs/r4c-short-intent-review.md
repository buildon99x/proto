# R4c 짧은 입력 예약과 의도 취소 검토

2026-10-09 UTC. R4a의 정상 입력에서 공격 회수 중 기술이 유실되는 문제를 확인해 R4b0.55초안을 만들었으나 실제 화면에 게시하기 전 검토로 중단했다. R4b 소스 `af46091a452acba4ff36303050941358f428c3cb`는 Library `libfile_f441846158808191ab179e42fd963897`, 빌드는 `libfile_e44425108618819199f0980987236b2d`에 실험 기록으로 보존됐다. 승인 거절이나 게시 실패가 아니라 게시 입력 전 자체 중단이다. 공개 후보는 R4a로 남았다.

## 이유와 수정

철퇴 기본 동작0.52초(현재 캐릭터 속도에 따라 단축)에서0.55초 대기는 거의 전체 동작을 넘긴다. 사용자가 방향/방어 의도를 바꾼 뒤 과거 돌진이 튀어나올 가능성이 있다. R4c는 **마지막 남은 회수0.18초 이하에서만**, 최대0.18초 단발 예약을 허용한다. 준비/접촉을 임의 취소하지 않고 너무 이른 입력은 화면 안내로 거부한다. 자원/CD가 아직 부족한 입력도 예약하지 않는다.

- 실제 실행 시1회 비용. 버퍼가 홀드 기본 공격보다 우선.
- 입력 시 조준은 고정. 이후 조준90도 이상 전환, 원래 이동벡터에 반대되는 새 이동, 가드, 다른 기술 입력에서 과거 의도를 취소/교체.
- 상호작용/물약/메뉴/blur/숨김/리바인딩/저장 차단/pointercancel/사망/지역 전환에 큐를 비움. 저장에는 넣지 않음.
- 짧은 예약은 기술 버튼/하단 안내에 표시. 조기 거부는 '현재 동작 진행 중 · 회수 마지막 구간에서 다시 누르세요'를 표시.
- 정확한0.18초 경계에서 기존 동작이 끝났다면 같은 프레임 끝에 예약 시작을 허용하지만 새 동작의 접촉/이동 시간은 다음 프레임부터 흐른다. 기한을 넘겨 새 행동을 실행하지 않는다.

R4b의 커서 몸→발 타깃, 근거리 통로/플레이어 겹침 표시, 휴식 동기화와 완료 안내는 함께 유지한다. 키 배치/공격 CD/피해/기력 비용은 변경하지 않는다.

## 검증과 비교 한계

0.55안은 runtime 자동검사까지만 수행했으며 실제 플레이 결과가 없다. 실제 입력 비교는 R4a의 무버퍼 기록과 R4c의 짧은 버퍼 후보 사이에서 수행한다. 자동검사는0.12/0.18/0.20/0.55 잔여 회수 경계 및 여러 프레임 dt에서 실행/거부/취소·자원1회 소비를 확인한다. 이 문서 작성 시 R4c 화면 QA는 아직 미실시다. 전체 검사 결과는 별도 r4c-tests.txt를 참조한다.

최종 자동 회귀: 334/334 통과, 문법 검사 및 정적 빌드 성공. 원본167파일의 Git blob/SHA256 일치 유지. 자동검사와 브라우저 체감/청취는 별도이며 현재 새 화면 검증 전이다.
