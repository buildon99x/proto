# R14a3 실제 입력 QA — 진행 기록

2026-10-10 23:26–23:34 UTC, dot cloud Chrome, 공개 Site v57 /qa-r14/, app R14a3. 공개 루트는 R11b6.1 유지.

## 정상 획득 프로필과 설정
- 제목 UI에서 qa-r12 / qa-r12a2-replay-20261010을 비어 있는 qa-r14 / qa-r14a3-expert-20261010으로 복사. XP/레벨/기술/장비 주입 없음.
- L16 전문가, XP685.5/780(누적6905.5), 1404G(수입1596/지출192), 기술점수33, 능력치점수60, 처치122/사망1. 동쪽 적 6명은 이전 플레이에서 처치했고 장치 보고는 미완, 서쪽은 남음.
- 기존 키 보존을 본 뒤 명시적으로 권장 POE WASD/회피홀드질주 프리셋 선택, 이어 8개 전체 기술 배치를 켬.
- 8개 기술 모두 이미 획득한 프로필. 중복 배치 버튼 비활성 확인. 이 단계에서는 기술 재배치/삭제 미실시.
- flash0, 흔들림0.5, 음량0.7. 음향 이벤트 전달 시각은 읽었으나 실제 청취 판단은 하지 않음.

## 현재 실제 관찰
- A 이동과 오른쪽 커서 RMB 망치를 함께 입력: 화면의 지형/장치가 우측으로 이동(플레이어는 카메라 중심), MP25 소비. 사진은 접촉 종료 후이므로 방향과 접촉 FX 동시 장면 증거는 불충분.
- J 8ms 요청 탭: 철퇴 시작/원호 FX 확인. 도구 요청 duration이 실제 물리 키다운-업 간격이라는 실측은 아님. 60Hz 한 프레임 이하의 실제 물리 탭 검증으로 표현하지 않는다.
- UI 입력 관측: 위 철퇴 handler→시작0.80ms, 첫 renderer 호출74.70ms, sound dispatch1.10ms, 실제 contact354.70ms. 망치 시작1.90ms/render74.80ms/sound2.30ms/contact373.60ms. 모니터/스피커 물리 지연이나 POE2 수치가 아님. 첫 화면 반응74ms대는 후속 성능 검토 대상.
- Space+J 1500ms 홀드: 구르기 시작0.80ms, 렌더63.90ms. 최초 철퇴 입력은 recovery-too-early로 거절되지만 이후 별도 홀드 반복 2회가 UI에 남음. 반복 관측5/6의 첫 렌더4.90/4.80ms, 접촉264.00/299.60ms. 유령 입력이 아니라 당시 키 유지에 따른 재개. 기존 v56 관측 UI 누락은 v57에서 해소.
- Q 8ms 요청 돌진: 기력98→85.5, 2.9초 HUD, 위치 이동·벽에서 멈춤/기존 모션 확인. 준비 단계 프레임은 별도 미확보.
- B 2000ms 유지 후 R8ms 요청: 방패 해제 후 회복 실행. MP30 소비, HP81→132. 캡처 시점은 준비선/접촉 이전이며 최종 UI에서 회복 확인.
- 회복 직후 G900ms는 회수 잠금으로 거절되고 자원 미소모. 다음 새 G900ms는 진격 실행, 기력 소비·9초대 CD. 키를 놓은 후 캡처에서는 진격 접촉 잔향이 없음. 채널 도중 프레임 자체는 미확보이므로 준비선 잔류의 실제 시각 재현으로 단정하지 않음.
