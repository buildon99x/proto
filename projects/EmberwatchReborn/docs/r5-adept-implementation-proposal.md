# R5 숙련 승급·기술 분기 연결 제안

작성: 2026-10-09 UTC. **문서 설계 제안이며 게임 코드는 변경하지 않았다.** 읽은 기준은 앱 `e1158e4`, 문서 `6d3be0c`다. 부모의 후속 보고에 따르면 동일 R4c는 공개 루트 Site v11로 승격되었고 L4 이행/후보 L6 장착/죽음 재시도를 확인했다. 이 문서 작성자가 게시본을 재검수한 것은 아니다. R4c 자동검사 334개와 정상 입력 결과는 기존 증거이며 이 문서 작성자가 다시 실행한 결과가 아니다. 브라우저·Godot·원격·Library 작업은 하지 않았다.

## 1. 결론과 이번에 먼저 닫을 경로

**XP 상금을 추가하기 전에, 이미 가진 위임장이 실제 숙련 훈련과 새로운 행동으로 이어지게 한다.**

1. 수문핵 회수 → 촌장 보고 → 기존 `adept_commission` 보존.
2. 훈련관 브란에게 **L5 + 입문 훈련 완료 + 위임장 + 대면/시야 + 첫 승급 0G** 조건으로 승급.
3. 승급만으로 기술이나 포인트를 주지 않는다. 보유 기술점수로 새 능동/패시브/분기를 구입하고 실제 입력에서 사용한다.
4. **이번 R5a의 완료 범위는 승급과 숙련 16노드 전체**다. 공통 지속효과/분기 저장 계약을 먼저 세우고 망치의 번개/균열 선택을 구매·저장·실제 피해에서 같은 규칙으로 연결한다.
5. **새 지역/후속 XP 경로는 다음 묶음**으로 분리한다. 이미 정리한 수문소 적을 부활시키거나 보고 보상을 다시 주지 않는다. 이번 작업이 L15/중반 콘텐츠 완주를 뜻하지 않음을 표시한다.

새 훈련 금화·능력치·기술 선행요구는 추가하지 않는다. 첫 승급 0G는 [R4 제안](./r4-first-dungeon-route-proposal.md)의 **첫 의뢰 후원이라는 Emberwatch 조정 제안**을 유지한 것이다. 원작의 미확인 승급 비용을 무료라고 판정한 것이 아니다. 본 문서에서 새로 제시한 공간·시간·효과 처리·중반 예산 역시 구현 전 조정안이다.

승급만 넣고 숙련 기술이 모두 잠긴 상태는 내부 중간 체크포인트일 수 있으나 사용자에게 “숙련 성장 완료”라고 공개할 완성점은 아니다. 기능 검수의 최소 수직 구간은 **승급 → 포인트 구매 → 실제 기술 사용 → 저장 재진입**이고, 이번 R5a 완료는16개 모두의 구현을 별도로 요구한다. 두 액티브만 연결한 상태는 내부 중간 단계다.

## 2. 확인한 현재 상태와 정확한 끊김

### 2.1 정상 입력의 실제 자산

[R4c 정상 입력 QA](./r4c-normal-input-qa.md)는 다음을 기록한다.

- 정상 획득한 L4/누적492XP에서 첫 2층 던전과 선택 창고·보스·핵·촌장 보고를 완료했다.
- 최종 **L6, 누적1025.5XP, 현재25.5/340XP**, 37처치/1사망이다.
- 대장장이 보급 후 집중 목걸이를 제작·장착하여 **295G**, 힘 추가2/지능 추가2/남은 능력점21, **기술점16**이다. 철퇴 rank2에 이미 1점을 썼으므로 L6 총획득17점과 일치한다.
- 목걸이에 쓴 잿불 조각 때문에 방패 +2는 재료 부족이다. 이 선택은 유지한다. 승급이 두 제작품을 무료로 보충하지 않는다.
- 저장된 위임장과 L6에도 **캐릭터 실제 티어는 입문**이다. 대장장이 보급과 촌장의 위임장은 별개이며 보급 수령이 승급 선행조건은 아니다.

기록된 L6은 현재37적을 전부 처치했다. 이 저장으로 승급·구매·자기치유·장비/수치·저장 호환을 확인할 수 있지만, 이미 없는 적에게 새 기술 피해가 발생했다고 주장할 수 없다. 별도 정상획득 최소 경로 프로필은 숙련 뒤에도 잿길19적과 선택 창고3적을 남길 수 있으므로 실제 전투 검수에 사용한다. 적 부활/HP 조작/레벨 주입을 하지 않는다.

최소 경로의 별도 명령 정산 근거는 [R4a 던전 모듈](./r4-dungeon-module.md)이다. 선택 창고와 잿길 추가19적을 생략한 Easy/Normal 누적791XP, Hard/Serious 709.5XP로 모두 L5다. Hard 최소 경로는 핵 회수 때619.5XP이고 **촌장 보고90XP로 L5**가 된다. 따라서 보고에 L5를 요구하거나 승급을 보고의 선행조건으로 두면 안 된다.

이는 보관된 약2.3년 전 위키 캐시 및 공식 역사 문서에 근거한다. 현재 원작 실측이나 새 웹 검증은 하지 않았다.

### 유지할 Emberwatch 결정

- XP곡선, 장비 가격/요구 능력치, 기본 재생/파생 환산, 현재 모션·충돌·방패 규칙, 던전·고유 처치·분산 목표 보상.
- 무료 기본4기술은 브란의 명시적 첫 훈련에서만 rank1로 받는다.
- 증강의 최소 기반랭크1은 현재 채택한 Emberwatch 보완이다. 원본 `requires.rank:null`을 고치지 않는다.
- 기존 첫 숙련0G안, 후속 Expert120G/Master300G 및 위임장 조건은 원작 확인 사실이 아니다. 후자의 근거는 기존 [전사 요구 체크리스트](./requirements/warrior-completion-checklist.md) §1.3/§2이며 현재 실행되지 않는다.

### 아직 확인할 수 없는 부분

- 기획서 v1.1/Library v2 원문 로컬 확보는 기존 HTTP403 상태다. [source status](./requirements/requirements-source-status.json)에 따르면 이전 담당자가623줄을 읽었으나 실제 로컬 SHA 대조는 미완이다. 이번 작업은 전송을 재시도하거나 우회 전사하지 않았다.
- 원작 승급 NPC·수수료·퀘스트·추가 능력치/기술 선행요구는 `UNKNOWN`/`null`이다. “원작은 힘X/지능Y/기술rankZ가 필요하다”는 조건을 발명하지 않는다.
- `battering_ram`, `crushing_might`, `superb_constitution`은 Adept 섹션 배치만 근거다. 훈련 허용 시 별도 Emberwatch 해금 정책으로 명시한다.
- 범위, 캐스트시간, 약기절 지속시간, 방어감소 수치/시간, 틱 첫 발생 시점, 중첩/갱신, Thorns 기력 샘플 시점, 재분배 가격은 별도 개발값이 필요하다.
- 원기획서의 모든 세부 문장을 이번 작업에서 직접 재독한 것은 아니다. 기존 요구 체크리스트·보존 카탈로그로 확인되지 않는 항목은 미확인으로 남긴다.

## 4. 첫 숙련 승급 계약

### 조건과 비용

`quotePromotion(state, 'adept')`의 단일 판정을 NPC 화면과 `promoteTier` 명령이 공유한다.

1. 유효한 저장·전사·기본4기술 전체 훈련, 생존 상태.
2. 현재 티어 `apprentice`; `expert`/`master` 건너뛰기 불가.
3. 레벨5 이상. 승급하지 않은 L6도 허용한다.
4. `adept_commission=1`과 유효한 `r4:report`; 보스 처치/핵만으로 대체 불가.
5. 현재 마을의 실제 `trainer` 브란 가까이, 벽 너머가 아닌 시야, 현재 생명 ID와 유효한 자원/위치 보고.
6. 첫 승급 고정0G. 화면은 “첫 숙련 훈련: 촌장 후원 · 0G”라고 표시한다. 클라이언트가 임의 비용/보상/티어 조건을 보내지 못하게 한다.

추가 힘·민첩·지능 배분이나 입문 기술 rank2/최대랭크는 요구하지 않는다. 그런 원작 근거가 없고, 이미 서로 다른 배분·장비를 택한 저장을 막기 때문이다. 능력치와 기술 요구는 **각 장비/기술의 실제 조건**으로 유지한다.

### 성공과 실패

- 성공은 `character.tier='adept'`와 `r5:promote:adept` 같은 단일 승급 영수증을 동일 transaction에 저장한다.
- 위임장·핵·기존 보상 영수증·장비·능력치·미사용 포인트·기술 랭크·XP·금화를 그대로 보존한다. 숙련 기술을 공짜로 주거나 포인트를 재추정해 보충하지 않는다.
- 수수료0이므로 금화/지출은0 변화다. 향후 유료 티어도 고정 quote를 검증하고 `spentGold`와 잔액을 함께 변경하는 같은 원자적 계약을 사용한다.
- HP/MP/기력 최대치가 변하지 않는 승급 자체는 회복 효과가 없다. 기술/패시브 구매로 최대치가 바뀌어도 현재 자원은 기존 수치에 새 최대치 clamp만 한다.
- 동일/동시/재로드 후 반복 승급은 `ALREADY_PROMOTED` 등의 무변경 결과다. 영수증 한도에서는 옛 기록을 지우지 않고 거부한다.
- 위임장 소모, 촌장 보고 재지급, 던전 초기화, 승급 전용 XP 지급은 하지 않는다.

### 가이드 우선순위

위임장 없음 → 촌장 보고. 위임장 있음/미승급 → 브란·현재L/필요L5·0G. 승급 후 신규기술 미구매 → 기술점수와 두 액티브 소개. 던전 보급 미수령 → 오린 안내. 그 뒤 → 실제 열린 후속 지역, 선택 창고는 부목표로 표시한다.

제작/보급을 이미 마친 R4c 저장은 바로 브란으로 이어져야 한다. 훈련 후에야 보급이 생기도록 기존 조건을 바꾸지 않는다. 후속 지역이 아직 없다면 그 한계를 정확히 표시하며 존재하지 않는 목적지를 안내하지 않는다.

## 5. 기술 53개 대조와 구현 순서

전체 카탈로그는 **입문9 + 숙련16 + 전문15 + 달인13 =53**, 기본16/증강37이다. R4c는 입문9만 실행한다. R5a 내부 첫 수직구간은 입문9+신규2=11개이지만 R5a 전체 종료 목표는 입문9+숙련16=25개다. 그때도 상위28개는 잠겨 있다. 전사53개 완료로 표시하면 안 된다.

### 구매·배타·능력치 원장

- `runtimeSkillIds`와 tier별 지원 상태를 별도 권위 데이터로 둔다. 카탈로그에 있다는 이유로 `runtimeValues`를 만든 것으로 간주하지 않는다.
- 승급된 티어 + 해당 노드 실제 구현 + 기반rank1 + 정확한 다음 비용 + 배타 조건을 모두 확인한다. 레벨5만으로 숙련 구매를 허용하지 않는다.
- `exclusiveBranches.righteous_hammer_damage_type`는 실제 습득 노드와 정확히 일치해야 한다. 양쪽 습득, 선택만 있고 노드 없음, 노드만 있고 선택 없음, 미구현 그룹 모두 거부한다.
- `trial_by_fire`와 `shackles`에 임의 배타 관계를 추가하지 않는다. 원본의 `exclusiveGroup:null`을 원작에서 모든 조합 허용이라는 주장으로 바꾸지도 않는다. 플레이용 동시 적용은 별도 개발 정책으로 명시한다.
- 총 지출은 원본 비용의 rank까지 합계다. **지출+미사용=해당 레벨 총획득**을 계속 정확히 검사한다. 전체 숙련16개 최대랭크 비용의 단순 합은141점이지만 망치 두 분기를 동시에 살 수 없으므로 합법적 전체최대는132점이다. 입문까지 합하면211점이며 L15의54점으로 전부 살 수 없다.
- 장착 요구는 현재처럼 **기본18/12/10 + 실제 배분**만 사용하도록 권고한다. 장비/거목의 힘/임시 버프는 제외한다. 패시브를 포함해야 한다는 원작 근거는 확인하지 못했으므로 이 제외 정책은 Emberwatch 규칙이다. 집중 목걸이 INT12 요구는 그대로다.
- 같은 화면에서 서로 다른 “힘”이 설명 없이 보이지 않게 한다. **장착용 영구 힘=18+배분**, **전투 유효 힘=장착용 영구 힘+패시브+장비/임시 보너스**를 이름과 분해값으로 표시한다. 예를 들어 배분2+거목rank1이면 장착용20/전투25이며, 새 STR25 장비는 여전히 장착 불가다. 아이템 비교/훈련 preview/캐릭터 화면이 같은 헬퍼를 읽게 한다.
- 이 정책에서는 거목 재훈련이 착용을 무효화하지 않는다. 나중에 패시브를 장착 조건에 포함하기로 변경한다면, 재분배/버프 만료 전에 모든 장착물 재검증과 원자적 해제·자원 clamp를 설계해야 한다. 그 변경을 이번 deriveStats 작업에 끼워 넣지 않는다.
- 숙련 패시브를 넣기 전에 능력치 계층을 분리한다: 원본 기본, 영구 배분, 패시브, 장비, 임시 효과. 전투용 힘/지능 계수는 계산 순서를 고정한다. 거목의 힘의 일반 HP/물리 환산까지 적용한다면 `배분+패시브 증가량`을 사용하는 **새 환산 결정**으로 별도 명시하고 기본18을 이중 가산하지 않는다. 기존 장비 보너스의 환산을 몰래 바꾸지 않는다.
- 별도 원작 근거가 없는 주문 최소INT/기술 최소STR를 발명하지 않는다. 최대MP보다 비싼 랭크는 구매 전 “현재 최대마나로 시전 불가” 경고를 표시하되 원본 비용을 할인하거나 가짜 능력치 선행조건으로 대체하지 않는다.

## 6. 숫자 상승보다 먼저 검증할 행동 차이

### R5a 내부 첫 단계: 회복할지, 공격할지

L5 무투자 기준 MP최대48이다. 치유rank1 MP30과 단죄rank1 MP30을 연속 사용하기엔 부족하다. “지금 회복/짧은 안전창에 범위 공격/마나를 아끼고 방패+철퇴”의 실제 결정을 만들 수 있다. 승급 때 MP를 채우면 이 선택이 왜곡되므로 별도 휴식만 회복한다.

- **치유 제안:** 현재 솔로 범위는 자신을 중심으로 반경96, 시전0.52초/접촉44%, HP최대 clamp. 자기 자신만 존재하는 현재 전투에서는 자신만 회복한다. 이는 솔로 타깃 정책이며 아군/협동 범위 치유 전체 구현이라고 하지 않는다. 움직임/가드/다른 행동은 기존 캐스트 회수 규칙을 따른다. 피해량 배율이나 주문 공격 증폭을 회복량에 자동 적용하지 않는다.
- **단죄 제안:** 전방 반경128/부채꼴120도, 시전0.60초/접촉45%. 시전 때 고정한 방향, 실제 접촉에서 LOS·범위·생존 확인. 한 action당 적별1회. 힘/장비로 계산한 주무기 피해에 원본 배율을 적용하고 철퇴rank 배율을 다시 곱하지 않는다.
- 위 범위/시간은 모두 초기 Emberwatch 조정안이다. 기존16–24프레임 표현에 준비/접촉/회수를 맞추되 수치만 있다고 시각 합격으로 하지 않는다.
- 주무기12인 L5에서 단죄rank1 raw36은 망치rank1 raw38보다 작다. MP30/CD4만 보면 단죄가 열세다. **원본 배율을 올려 해결하지 말고 넓은 전방 동시타격·철퇴 장비/힘 빌드·후속 장판/족쇄의 차이를 실제 군집에서 검증**한다. 단일 적만 놓고 신기술이 무조건 강하다고 안내하지 않는다.

### R5a 전체: 같은 기술점수로 다른 전투

L5 총13점으로 가능한 예시다. 무료 기본4기술은 기존 훈련에서 받은 상태이며 아래는 자동 추천 구매나 강제 빌드가 아니다.

- **전열 접근/반격형13점:** 관통돌진2 + 반격철편2 + 강철파수꾼1 + 강철걸음1 + 방패보법1 + 강철충돌1 + 철퇴rank2 비용1 + 치유2 + 단죄2. 궁수에게 접근하며 근접 압박은 방패로 받는 선택.
- **마나/지역제어형13점:** 치유2 + 단죄2 + 뇌광망치2 + 불길자국2 + 재생치유증강2 + 망치rank2 비용2 + 방패보법1. 군집이 모인 순간과 마나 회복창을 다루는 선택. 뇌광2 대신 균열2를 택하면 장갑 대상 이후 물리 공격의 가치를 시험한다.

기록된 L6 세이브는 철퇴rank2 지출1과 남은16점을 보존한다. 새 예시를 맞추려고 기존 랭크를 초기화하거나 보유점을13으로 덮어쓰지 않는다.

불길자국rank1은 가만히5초 맞는 적에게 **20×10=200 raw화염**이다. 수문 심장지기HP220은 입문 첫 보스이므로 숙련으로 강해진 뒤 빠르게 이기는 것 자체는 문제가 아니다. 이를 막으려고 원본20/0.5/5를 낮추거나 기존 보스HP를 올리지 않는다. 후속 지역의 새로운 위협은 별도 설계한다. 번개는 물리방어를 쓰면 안 되며, 원소저항과 물리 관통을 구별하는 피해 계약이 선행된다.

장판 수치의 정지 최대치와 실제 기대치는 분리한다. 첫 틱0.5초/총10틱 정책에서 rank별 정지 raw 상한은200/300/450/650이다. 실제 대상별 피해는 **해당 시각에 살아 있고 장판 범위 안이며 LOS가 열린 틱 수 × 원본 틱 피해**에 저항/증폭을 적용한 값이다. rank1에서1.2초 뒤 이탈하면0.5/1.0초 두 틱으로40,2.1초 뒤 이탈하면 네 틱으로80이다. 중간에 벽 뒤로 이동하거나 범위에서 벗어난 틱은0이다. 이 계산은 일관된 속도/표적을 둔 모델 예시이며 실제 플레이 피해 관측이 아니다.

동일 시전자 장판1개 정책에서는 새 장판이 옛 source를 종료하므로 겹친 두 장판의 틱 피해를 합산하지 않는다. 교체 접촉과 옛 틱이 정확히 같은 시각일 때의 처리 순서를 고정하고 이중 타격을 검사한다. 새 장판의 새 틱이 정당하게 발생하는 것과 같은 source/틱의 복제를 구별한다.

뇌광도 “전체 투사체 틱 수”와 “한 적이 맞는 틱 수”를 구별한다. 현재 속도560/거리460이면 수명약0.821초여서0.25/0.50/0.75초 총3번 방출할 수 있다. 제안 반경64와 적 중심 판정에서는 연속 방출 중심 간 거리140가 지름128보다 커서, 직선상에 가만히 있는 한 적이 반드시3틱을 모두 맞는 것은 아니며 최대1틱이다. 이동 표적/벽 충돌/범위 경계는 실제 handler로 별도 계산한다. 초기 반경/중심 판정이 바뀌면 이 산술도 다시 산출한다.

배타 선택 UI에는 반대 분기가 막힌다는 점과 현재 재분배 지원 여부를 구매 전에 보여 준다. 재분배 가격은 원작 미확인이다. 재분배가 아직 없다면 있다고 표시하지 않고 다른 분기 검수는 별도 정상 새 세이브로 한다. 전체 요구사항의 유료 재분배는 별도 미완 항목으로 유지한다.

## 7. 저장·조작 호환과 중복 방지

### R5a 호환 이행

- 새 상태 버전을3으로 올릴 경우, **v1/v2를 각 구버전 계약으로 먼저 검증**하고 순수 이행으로 v3 메모리 상태를 만든다. 다음 성공한 저장에서만 새 형식을 기록한다. 읽기만으로 디스크를 다시 쓰지 않는다.
- v1의 기존 장비 제한·v2의 R3/R4 정합성을 느슨하게 만들지 않는다. 잘못된 옛 숙련 기록/상위 기술을 “이행”이라는 이유로 수용하지 않는다.
- 레벨/XP/포인트/능력치/돈/아이템ID/퀘스트/영수증/처치/기존 조작을 그대로 유지한다. 빈 승급 이력은 미승급 뜻이며 위임장 소유를 실제 승급으로 바꾸지 않는다.
- 새 성장 검증은 티어와 승급 영수증/위임장의 양방향 일치를 state 수준에서 검사한다. 순수 character 함수의 tier 허용만으로 저장의 승급 정당성을 증명하지 않는다.
- 신규 코드가 옛 저장을 읽을 수 있다는 것과 R4 코드가 새 저장을 읽을 수 있다는 것은 다르다. 후자는 보장하지 않는다. 기존 후보/release 격리와 명시적 복사 정책을 유지하며 무단 원본 저장 승격을 하지 않는다.

### 조작

- 신규 `heal`, `judgement`를 one-shot으로 추가한다. **신규 추천 프리셋만 E=단죄/T=온기**를 기본으로 제공한다. 기존 E상호작용/1물약/Z망치, 가드 hold/toggle, 돌진 방향과 다른 모든 v1 바인딩을 그대로 보존한다.
- 옛 v1 조작은 Controls v2로 이행하며 새 두 슬롯만 **빈 배열(미지정)**로 둔다. v2 validator는 새 두 액션에 한해서0~3키를 허용하고 기존 액션은 계속1~3키를 요구한다. 기존 저장에 자동 미사용 키를 배정하거나 기존 키를 이동하지 않는다.
- 새 기술 학습 전에는 작동하지 않는 빈 핫바 버튼을 늘리지 않는다. 학습 뒤 미지정이면 “단죄 · 키 미지정” 등의 경고, 키 설정 바로가기와 사용 가능한 화면 버튼을 제공한다. 키보드 지정 전에도 접근 가능한 실제 행동 경로가 있어야 한다.
- `controlsFor`/`actionLabel`/HUD가 빈 새 배열을 처리하도록 하고, validator/설정 화면이 미지정을 오류나 undefined로 렌더링하지 않게 한다. 새 프로필의 E가 기존 legacy 프로필의 상호작용E와 다른 것은 프로필별 설정으로 명확히 표시한다.
- 키보드/마우스/touch 핫바, 조작설정, HUD의 표시, 접근성 라벨, router snapshot, `awaitingAdvance` 해제, 0.18초 짧은 입력 예약을 함께 연결한다.
- 입력 프레임 분할 재호출에서 새 one-shot도 소비 완료로 전달해야 한다. 현재 `stepBattle` 분할의 `hammer:false,charge:false` 두 항목만 유지하면 새 주문이 두 번 시도될 수 있다.
- 가드/반대 조준·이동/새 입력/상호작용/메뉴/blur/사망/지역 이동의 예약 취소를 두 새 행동에 똑같이 검증한다. 자기중심 치유의 조준 취소 정책은 명시적으로 선택한다.

### R5a 지속효과 보존/취소 정책과 한계

현재 저장은 자원·cooldown·회수만 담고 투사체/적 상태를 직렬화하지 않는다. R5a는 이 전투 취소 계약을 유지하면서 **4초 재생 버프만 recovery에 남은시간/배율을 저장**하는 것으로 범위를 정한다.

- 메뉴에서는 투사체·장판·적 상태·재생 버프의 시간이 모두 정지한다. 메뉴를 여는 checkpoint나 닫는 동작이 지속시간을 다시 시작하지 않는다.
- 지역 이동/새로고침/죽음에는 투사체·피해 장판·적 디버프를 취소한다. 자원/CD 환불은 하지 않는다. 단, 이 보장은 **마지막 성공한 확정 저장**에 기록된 자원/CD를 기준으로 한다.
- 재생 버프는 `recovery.regenBuff: null | {remaining, multiplier}` 형태를 제안한다. 남은시간은0초 초과4초 이하, 배율은 원본1.25/1.5/2 중 학습한 랭크로 가능한 값만 허용한다. 동일 시전자 한 개만 존재하며 재시전은 갱신이다. 죽음/휴식/재분배 때는 취소하며 지역 이동/정상 저장 재진입에는 남은시간만 이어간다.
- 실행 중인 피해 효과는 생명/지역/단조 action sequence로 구분한 source ID, 시전 시 수치 snapshot, 남은시간, 틱 실행횟수와 적별 타격 기록을 갖는다. 장식 FX와 피해 source는 분리한다. 저장하지 않는다고 실행 중 중복타격 검사를 생략하지 않는다.
- 저장형에는 지원하지 않는 projectile/area/debuff payload를 받아들였다가 조용히 버리지 않는다. 알 수 없는 효과 필드는 거부하거나 해당 버전의 명시 이행 규칙으로 처리한다. 재생만 직렬화하는 사실을 UI/QA 문서에 기록한다.
- 무기/기술 변경이 날아가는 투사체의 피해를 소급 변경하지 않도록 시전 snapshot을 사용한다. 미구현 재분배를 통해 버프를 유지하는 우회는 열지 않는다.
- 저장 실패/충돌/불확실한 head 쓰기 후에는 기존 controller의 차단·명시적 reload 정책을 유지한다. 새 UI가 먼저 승급/무료회복/지속효과를 적용하지 않는다.

부모가 제안한 R5 이벤트 저장 계약을 다음과 같이 반영한다. 이는 아직 구현/검증 결과가 아니다.

- combat은 실제 비용을 지불한 `actionStarted`, 실제 피격/블록 비용을 적용한 `heroHurt`, 회복/재생 버프를 적용한 `healApplied` 사건을 낸다. 피해0의 성공 블록도 기력 비용이 있으면 자원 변화 사건이 필요하다.
- main은 이 사건이 있는 **프레임 끝의 단일 snapshot**에서 비용·회수·HP·MP·기력·재생 버프를 checkpoint한다. actionStarted와 healApplied가 같은 프레임이어도 두 번 저장하지 않는다.
- 같은 프레임에 처치/사망이 있으면 별도 checkpoint 대신 `settleCombat` 하나에 모든 변화를 합친다. 새 반격/장판 처치도 이 정산으로 보상 영수증과 함께 저장한다.
- 확정 중에는 busy로 다음 시뮬레이션을 막는다. 확정되지 않은 다음 피해/버프/틱이 앞선 snapshot을 추월하지 않게 하고, 성공한 저장만 live/state 동기화에 사용한다.
- 활성 플레이 중1초 간격의 보조 checkpoint로 경과 cooldown·회복·위치를 보존한다. 메뉴는 시뮬레이션 시간을 정지하므로 보조 저장이 게임 시간을 진행시키지 않는다.
- 자동 결산 실패는 사유를 표시하고 명시적인 reload까지 진행을 차단한다. commit 전/후 예외, 프레임 사건 중복, periodic과 사건 저장의 겹침을 검사한다.
- 이 방식도 디스크 확정 전 전원손실/강제 종료까지 없앨 수는 없다. 마지막 확정 snapshot으로 돌아갈 수 있음을 명시하고 정상 브라우저 새로고침에서 비용/CD 보존을 실제 관찰한다.1초 보조 간격 안의 버프 잔여시간/자원 rollback 역시 마지막 확정 기준의 한계다.

**진행 보존 판정:** 이 정책은 퀘스트·열린 문·고유 처치·보상·위임장·티어·포인트·장비의 영속 진행을 보존할 수 있다. 하지만 요구 체크리스트의 투사체/장판/적 상태를 포함한 전투 순간 완전복원과는 다르므로 해당 항목을 완전히 통과했다고 표시할 수 없다. 자동 영속 세계라고 주장하지 않는다.

위험은 다음과 같이 나눈다.

1. **높음: 시전 직후 강제 새로고침.** 현재 `main.js`는 처치/사망·메뉴·이동·명시 저장 등에 보고하며 모든 시전 시작을 즉시 커밋하지 않는다. 저장되지 않은 비용/CD는 새로고침 때 옛 값으로 돌아갈 수 있으므로 “모든 새로고침에서 환불 없음”은 아직 보장되지 않는다. 위 이벤트 checkpoint와1초 보조 저장 계약으로 이 간극을 줄이며, 마지막 확정 저장으로 돌아가는 한계는 계속 명시한다. 비동기 `beforeunload` 하나로 보장이 생기지 않는다.
2. **중간: 시간과 재생 복제.** 남은 버프시간/현재 자원/CD를 같은 snapshot으로 저장하지 않으면 HP만 회복된 뒤4초 버프가 되살아날 수 있다. 저장 전후의 frame 정지와 원자적 report, 만료/재시전/실패/재로드 검사를 묶는다.
3. **중간: 전투 재시도 차이.** 미처치 적의 HP/위치/디버프가 복원되지 않고 장판도 사라진다. 저장-로드 전술과 계속 플레이의 결과가 다르다. 기존 동작이더라도 이번 스킬에서 체감이 커질 수 있으며 완전한 전투 중단/재개를 완료 처리하지 않는다.
4. **낮음~중간: 정상 지역 이동에서 잔여 피해 손실.** 비용은 사용했지만 떠난 장판은 취소된다. 명시 정책이고 보상 중복보다 안전하지만 화면 안내와 실제 이동 후 무잔류 검사가 필요하다.

## 8. L15와 후반으로 이어지는 성장 경로

### 지금 곡선이 요구하는 실제 예산

현재 `progression-balance.js`의 저작된 곡선으로 순수 산술을 하면 다음과 같다. 이는 게임 실행/플레이 시간 계산이 아니다.

| 경계 | L1부터 누적 필요XP | 의미 |
|---|---:|---|
| L5 | 700 | 현재 첫 던전 최소 경로가 충족 |
| L6 | 1000 | 기록된 R4c1025.5XP는 여기 |
| L15 | 5500 | 현재 R4c 끝점에서 추가4474.5XP 필요 |
| L18 | 7840 | Expert 뒤 실제 콘텐츠의 가능한 계획 경계 |
| L30 | 22600 | L18에서 추가14760XP 필요 |

최소 Hard/Serious709.5XP 시작점에서 L15까지 **4790.5XP**가 필요하다. 이 차이를 기존 수문소 최종 보고 한 번에 지급하는 안은 사용하지 않는다. 현재 레벨/XP를 리셋하거나 뒤늦게 이전 보상의 차액을 지급하지 않는다.

L5–14에서 계속 입문 적만 놓으면 Normal50%, Hard37.5%로 줄어든다. 다음 지역은 **실제 역할/위험에 맞는 숙련 적**으로 설계하고 그 티어를 명시한다. 기존 입문 적을 이름만 바꿔 XP 회복 수단으로 만들지 않는다. L15 이후 숙련 적도50%(Hard37.5%)가 되므로 다음 Expert 전장으로 자연히 옮겨야 한다. 훈련을 미뤄 XP감쇠를 피하는 우회는 없어야 한다.

### 제안하는 다섯 성장 구간

이 순서는 기존 전사 체크리스트의 후속 제작 범위를 바탕으로 한 **새 구현 순서**다. 유실된 맵·보상 원문 복구본이 아니다.

| 구간 | 플레이어의 새 판단 | 다음으로 남는 결과 |
|---|---|---|
| 숙련 훈련 뒤 채석장 | 무료 도구/구조 경로와 재료 소모 우회, 가까운 장갑 적/떨어진 사수. 관통 접근·회복 MP 선택 | 도구와 단서, 장로 보고, 빠른 귀환 |
| 고갯길·신호 문서 | 단서 얻고 다른 길을 다시 방문, 분산 사수와 이동 근접 적. 번개 군집/균열 집중 선택 | 해독 자료와 신호 연결 |
| 신호 복원 전장 | 장치 두 곳의 우선순위, 수리 중 짧은 방어창, 단죄/족쇄의 위치 선택 | 대장장이의 용광로 의뢰 |
| 용광로 | 냉각/배기·점화 교전 또는 명시 재료 우회. 화염 장판에 머무르지 않는 적 | 렌즈를 별도 회수, 대장장이 보고 |
| 신호 묘실 | 렌즈+해독, 순서 봉인, 역할 다른 호위/보스, 서약 회수 | **장로 보고**로 Expert 위임장, 그 뒤 브란 훈련 |

필수 승급 경로에서 STR/INT 장비나 특정 망치 분기를 강제하지 않는다. 도구/우회와 기술 선택이 이동·위험·자원 사용을 바꾸되 메인 완료를 영구 봉쇄하지 않게 한다. 각 구간은 새로운 문제를 적어도 하나 제공하고 귀환은 보고/정비를 위한 짧은 경로로 연결한다.

### 사전 예산의 크기 확인용 예시

새 콘텐츠의 전투/오브젝트 수를 결정하기 위한 계산 예시는 **필수 숙련 처치 기본XP 합3600 + 의미 있는 일회성 목표 합2100 = Hard 수령4800**이다. 최소 Hard709.5에서5509.5로 L15를 조금 넘는다. 예를 들어 고유 적80명은 평균 기본45XP, 목표35개는 평균60XP에 해당한다. 이는80마리/35개를 무조건 채우거나 전부 동일한 보상을 찍어내라는 명세가 아니다. 다섯 구간의 실제 전투·발견·구조·수리·회수·보고를 먼저 작성하고 공급을 검증할 규모다.

- 마지막90XP 보고 전까지 최저 경로가 L15에 닿지 않는 순서를 만족할 때만 위 최소 산술이 성립한다. 마지막 보고에 L15를 요구하지 않는다.
- 전체/선택 경로와 Normal은 더 일찍 L15를 넘을 수 있어 이후 숙련 처치 감쇠가 달라진다. 모든 처치를 최종레벨 배율로 일괄 계산하지 않고 실제 `settleCombat`의 **각 처치 직전 레벨**로 재계산한다.
- 선택 보상은 필수4790.5XP 보장에 넣지 않는다. 대체 도구/재료 길은 서로 다른 receipt를 악용해 양쪽 필수 보상을 중복 수령하지 못하게 한다.
- 보고90 같은 개별 보상의 상한/비율은 아직 확정하지 않는다. 최종 보고가 대부분을 차지하지 않도록 목표를 실제 행동에 분산한다.
- 이 정도 콘텐츠를 만들었는데 지루하다면 XP곡선·목표 수·적 역할/행동창을 함께 재검토한다. HP·왕복거리·기다림만 늘려 목표시간을 채우지 않는다. 곡선을 바꾸는 경우 기존 누적XP/레벨 이행을 별도 설계하며 여기서 변경하지 않는다.

### L15 뒤와 L30의 의미

Expert는 깃발의 수호/격려 선택, 진격 채널과 중단 판단, 상태이상 응징이 실제 전장에 쓰인 뒤 중반 마지막 봉화/장로 보고로 후반을 연다. 후반은 황야 조사 → 도구/렌즈 수리 시설 → 기록 보관소 → 주조소 → 서약 첨탑 → **교관 보고**의 Master 위임장 순서를 기능 목표로 보존한다.

Master는 L30+순차훈련+위임장+별도300G 조건 이후에도 새 범위피해·상태면역·스택을 사용할 전장과 최종 장로 보고가 남아야 한다. L30 달성 직후 엔딩이면 성장 보상의 사용 기회가 없다. 현재 L6에서22,600XP까지 숫자만 뿌리는 안은 계획이 아니며, 후반 예산은 숙련/Expert 실제 플레이 끝점이 확인된 뒤 다시 산출한다.

유료 Expert/Master를 넣을 때는 선택구매·제작·사망 뒤 금화 부족이 복구 가능한지 먼저 검증한다. 현재처럼 유한 보상/유한 상점만 있는 상태에서 필수 수수료를 더하면 영구 금화 소프트락이 가능하다. 회복 경로 없이 잔액295G 사례 하나로 경제가 충분하다고 결론 내리지 않는다.

## 11. 병렬 구현용 deriveStats/런타임 계약 초안

최종 소유권은 **성장 담당: `warrior-growth.js`/`warrior-balance.js`/전용 성장 검사**, **전투 담당: `combat.js`/실제 handler 검사**, **부모 통합: controls/state/campaign/main/save 이행·표현**으로 정한다. 아래는 구현 시작 전에 서로 맞출 작은 인터페이스 표다. 새 source 참조 파일은 수정하지 않는다.

| 생산 필드 | 의미/단위 | 소비 규칙 |
|---|---|---|
| `stats`의 기존 HP/MP/기력/속도/armor/regen/crit 키 | 기존 계약 보존, 유한 숫자 | 기본+패시브+장비를 적용한 정적 최종값. active 재생 버프는 여기 다시 넣지 않음 |
| `stats.strength/dexterity/intelligence` | 전투 유효 능력치 | STR/INT 비례 기술에 사용. 장착 요구 판정에 직접 사용하지 않음 |
| `stats.equipmentAttributes` | `{strength,dexterity,intelligence}` = 기본+배분 | “장착용 영구 능력치” 표시. 기존 equipment 요구 판정과 동일 결과를 검사 |
| `stats.attributeBreakdown` | 속성별 `{base,allocated,passive,equipment,temporary}` | 표시용 분해. 현재 temporary는0, 임시 효과를 발명하지 않음 |
| `stats.actions[id].learned` | 기존4+신규2 액티브의 학습 여부 | 미학습은 실행 불가. ID 매핑은 `heal→lay_on_hands`, `judgement→judgement` |
| 각 학습 action의 `manaCost/staminaCost/cooldown/duration/contact/range` | 비용/초/월드단위, 모든 적용 증강 포함 | 전투는 비용/시간을 다시 계산하지 않고 한 번 지불·접촉 처리 |
| 물리 action의 `damage/damageType/armorPenetration` | 대상 방어/치명타 이전 최종 물리값과 관통 | Crushing Might/전역 관통은 성장 계산에서 한 번 반영. combat에서 다시 곱하거나 더하지 않음 |
| `actions.shield_charge.passesThroughEnemies/stunSeconds` | 관통 여부/기절초 | 기존 거리·벽 제한 유지. 약기절은 대체 |
| `actions.shield_block.thorns` | `null` 또는 `{coefficient,damageMultiplier,armorPenetration}` | 실제 근접 블록 비용 후 현재 기력×coefficient×damageMultiplier. 공격자 한 명에게1회 |
| `actions.righteous_hammer.lightning` | `null` 또는 `{damage,tickSeconds,radius}` | damage는 최종 번개 raw값. 물리 망치 접촉과 다른 틱 source. 물리 armor 계산 금지 |
| `actions.righteous_hammer.armorBreak` | `null` 또는 `{amount,duration}` | 추가 STR 물리는 위 `damage`에 이미 포함. 접촉 피해 뒤 방어감소 적용 |
| `actions.lay_on_hands.heal/radius/regenBuff` | 최종 회복량/반경/`null` 또는 `{duration,multiplier}` | 회복량은 HP clamp, regenBuff는 실제 적용 순간 live에 한 개. 원본 회복량에 공격 증폭을 재적용하지 않음 |
| `actions.judgement.arcRadians/fireArea/shackles` | 전방각/`null` 또는 `{damage,tickSeconds,duration}`/`null` 또는 `{moveMultiplier,damageTakenMultiplier,duration}` | 실제 접촉에 영역/상태 생성. area shape는 단죄의 고정 범위/방향을 상속. 새 조정 반경이 필요하면 별도 필드 추가 |
| `recovery.regenBuff` | `null` 또는 `{remaining,multiplier}` | state/save가 검증·보존, combat이 시뮬레이션시간만 차감. base regen에 한 번만 적용 |

공통 수치 계약: 시간은 초, 확률/배율은0–1 또는 명시 multiplier, 저항은 기존 퍼센트포인트, 각 damage는 적 방어/저항 전 값이다. action의 damage에는 적용할 전역 물리/주문 보정이 이미 들어 있으므로 전투 담당이 source 계수를 다시 읽지 않는다. 번개/불길자국의 공격 주문 보정 적용 여부와 순서는 성장 balance에 명시하고 preview와 같은 계산을 사용한다. 치유량은 현재 제안에서 원본60/120/200/300 그대로다.

`invigorating_touch`가 살아 있을 때의 실제 HP/MP/기력 재생은 combat이 `stats`의 정적 regen에 live multiplier를 한 번 적용한다. 상태/HUD가 해당 live 값을 표시할 때도 같은 helper를 사용한다. `deriveStats` 자체는 시간을 진행하거나 recovery를 수정하지 않는다.

최소 합의할 실패코드는 `TIER_REQUIRED`, `DATA_ONLY`, `BASE_SKILL`, `SKILL_POINTS`, `EXCLUSIVE`, `ALREADY_PROMOTED`, `COMMISSION_REQUIRED`, `TRAINER_REQUIRED`, `INVALID_RECOVERY`이며 이름은 기존 계약과 충돌하지 않게 최종 정한다. 실패에서 부분 character/state를 반환하지 않고 성공 결과만 부모 controller가 저장한다.
