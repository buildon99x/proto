# R2d 입력 체계와 검증

작성 2026-10-09. 이는 새 Reborn 재구현의 변경이며 소실된 전사 완성본의 복구가 아니다.

## 근거와 자체 결정

부모 작업자가 공식 문서를 확인해 전달한 근거:

- Hades 개발자 답변: https://steamcommunity.com/app/1145360/discussions/0/2568689796945394999/ — WASD, 재매핑, 공격 커서 조준 기본 ON / 회피 커서 조준 기본 OFF, 클릭 이동을 전투 스타일에 맞지 않아 제외했다는 설명.
- Diablo IV 공식 시즌 설명: https://news.blizzard.com/en-us/article/24053482/unearth-a-looming-threat-in-season-of-the-construct — WASD 이동 추가.
- Diablo IV 공식 접근성 설명: https://news.blizzard.com/en-gb/article/23954932/combatting-demons-with-accessibility-in-diablo-iv — 입력 재설정과 누름/토글 지원.
- Hammerwatch II의 정확한 공식 기본 키표는 확보하지 못했다. Heroes II의 키를 원작 사실로 사용하지 않는다.

다음은 Emberwatch의 자체 조작 설계다. 다른 게임의 회피를 새 전사 스킬로 추가하지 않는다.

| 행동 | 신규 추천 | 기존 저장 |
|---|---|---|
| 화면 기준 이동 | WASD / 방향키 | 동일 |
| 조준 | 마우스 | 동일 |
| 기본 공격 | 마우스 왼쪽 / J | 동일 |
| 전사 방패 | 마우스 오른쪽 / 좌·우 Shift | 동일 |
| 기존 방패 돌진 | Space | 동일 |
| 잿불 망치 | Q | 동일 |
| 상호작용 | F | E |
| 체력 물약 | R | 1 |
| 성장 / 설정 | C | 동일 |
| 일시정지 | Esc | 동일 |

신규 프로필만 추천 배치를 받는다. controls 필드가 없는 기존 저장은 조회 시 legacy로 해석하며 저장을 몰래 다시 쓰지 않는다. 사용자가 키 설정에서 명시적으로 초기화/전환할 수 있다. E 추가 스킬과 Tab 지도는 아직 구현하지 않았으므로 바인딩을 허위로 표시하지 않는다.

## 동작 계약

- `event.code`를 사용해 영문/한글 입력 상태에 키 위치가 바뀌지 않는다. 키 입력창, select, textarea, contentEditable 및 Ctrl/Alt/Meta 조합은 게임 입력으로 처리하지 않는다.
- 모든 행동은 1~3개 키. 전역 중복 키는 기존 행동을 설명하며 거절. 마지막 바인딩을 제거할 수 없다. 마우스 좌/중/우/뒤/앞 5개 버튼 지원. Esc는 항시 안전 일시정지로 남고 지정 중 Esc는 취소한다.
- 기본 공격은 누르는 동안 반복. 이동/기본 방패는 누름 유지. 망치/돌진/물약/상호작용/메뉴는 단발. 단발 기술이 실패해도 키를 놓고 다시 눌러야 하며 쿨다운 종료 후 몰래 자동 시전하지 않는다. 이는 기존 R2c의 Q/Space 누름 반복을 명시적으로 개선한 동작이다.
- 기본 방패는 기본 공격보다 우선. 선택적 토글 방패는 새 공격/망치/돌진 입력 또는 모달 진입·blur·visibility 변경으로 해제된다. 자동 공격 토글은 없다.
- 조준과 마지막 이동 방향을 별도 보관한다. 기본 돌진은 기존 조준 방향. 선택적 마지막 이동 방향은 이동 방향만 변경하며 스킬 비용, 최대 거리, 적 충돌, 무피해 기본형, 재사용/회복 시간을 바꾸지 않는다. 새 프로필/지역 로드에서는 이동 기억을 초기화한다.
- 화면에 보이는 HUD, 상호작용 안내, 도움말은 실제 프로필 설정에서 생성한다. 터치는 화면 방향 패드/기술 버튼을 사용하며 키 배치와 무관하다. 게임패드 지원은 미완이다.
- 메뉴, 설정, 키 지정, 브라우저 비활성에서는 전투가 진행하지 않는다. 키 반복은 닫기 후 공격으로 다시 활성화되지 않는다. 새로 누르는 정상 입력이 필요하다.

## 자동검사와 실제 검증의 구분

R2c 이전 105개를 유지하며 재매핑/충돌/스키마/레거시/마우스/단발/누름/토글/모달 입력 해제/동일 저장 컨트롤러 재진입/실제 전투 핸들러의 자원 지출과 방향을 추가 검사한다. DOM 이벤트와 브라우저 보조 버튼의 실제 플랫폼 동작은 자동 단위검사만으로 합격 처리하지 않는다.

실제 브라우저 R2c에서는 정상 이동·8처치·순찰 보고로 레벨2/누적XP168/52G를 획득했고, 기술점수1로 철퇴1→2를 선택했다. 메뉴 반복 재개, 2분 이상 훈련 안내 정지, 저장·새로고침·이어하기 후 강화 유지가 확인됐다. R2d 재매핑의 정상 입력 확인과 강화 후 전투 체감은 이 문서 작성 시 아직 미검증이다.

독립 코드 검토에서 마우스 버튼을 겹쳐 누르면 pointerdown/up만으로는 두 번째 버튼을 놓치는 결함을 발견했다. [W3C Pointer Events](https://www.w3.org/TR/pointerevents3/#chorded-button-interactions)의 chord 규칙에 따라 실제 마우스는 각 버튼별 mousedown/up 경로로 분리했다. 터치는 pointer 경로를 유지한다. 좌→우 및 우→좌의 중첩/순차 해제 모델 회귀를 추가했고 실제 브라우저 중첩 입력은 별도 확인한다.

검토에서 저장 불확실/충돌 패널을 Esc로 닫아 전투가 재개되는 문제도 발견했다. 시각 모달과 별도인 runtime-gate로 차단하고, 실제 저장 다시 읽기가 성공해 상태를 반환한 경우에만 해제한다. 실패/빈 복원·반복 Esc·다른 패널 이동은 해제하지 않는다. 키 지정의 취소 버튼이 Mouse0 할당으로 잡히는 문제도 캡처 대상에서 취소 버튼을 먼저 분리해 수정했다. 이 두 UI 경계의 브라우저 회귀는 별도로 기록한다.
정상 마우스 capture 해제가 키보드 W와 토글 방패까지 지우던 추가 검토 결함은 마우스 held 토큰만 해제하도록 수정했다. 비정상 pointercancel/blur/모달은 전체 해제를 유지한다.
