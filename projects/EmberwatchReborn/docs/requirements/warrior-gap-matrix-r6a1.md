작성: 2026-10-09 UTC. **판정: 입문·숙련의 일부 실제 진행을 확인한 개발판. 전사 캠페인 완결은 아니다.**

- 판정 기준 코드: `5e1124e97a253a5f113578184efb615c276c5f6f`, 앱 `0.6.0-reimplementation.2`.
- 읽은 증거 체크포인트: Git `3110039` 및 그 이전 문서. 이후 작업 중 변경은 이 판정에 포함하지 않는다.
- 현재 구현: **53개 중 25노드**(Apprentice 9 + Adept 16). Expert 15 + Master 13은 참조 데이터만 있고 구매·효과·승급은 없다. 25노드는 25개 별도 액티브가 아니며 현재 행동 입력은 기본4 + 온기 + 단죄의 6종이다.
- 동일 코드에 기록된 자동검사: **488/488**, 실패·건너뜀 0. 구문·빌드 및 원본 167파일 무변경 검사 기록이 있다. 이 문서를 작성하면서 게임 실행·테스트·빌드·브라우저·배포를 다시 수행하지 않았다.
- 실제 정상 획득의 최신 끝점: **Normal, 숙련 L8, 누적 1,845.5 XP, 426G, 49처치, 5사망**, 채석장 에다 보고 및 재로드 확인. 전체 캠페인·L15·L30·피날레 증거가 아니다.
- 공개 루트는 R5a3, `/qa-r6/`는 R6a1 공개 후보다. R6a1 수정이 루트에도 적용됐다고 간주하지 않는다.
- **현재 후속 개발 패스는 진행 중이다.** 새 코드·통합·검사·공개본 정상 입력 증거가 확인되기 전에는 아래의 계획/미구현 항목을 완료로 바꾸지 않는다.

이 파일은 날짜가 있는 후속 판정표다. [원 요구사항 체크리스트](warrior-completion-checklist.md)의 역사적 미검증 표시와 [원문 확보 상태](requirements-source-status.json)를 덮어쓰지 않는다.

### 판정 표기

- **구현:** 실행 가능한 구매/명령/파생/전투/저장 연결이 있는 범위. 카탈로그만 있으면 `참조만`이다.
- **자동:** 읽은 현재 검사와 결과 기록. 합성 상태, 좌표·처치 정산 fixture, 실제 handler를 구별한다. 488개 전체가 각 행의 모든 요구를 검사한다는 뜻이 아니다.
- **일반 입력:** 화면에서 실제 키·마우스·메뉴로 한 행동과 결과만 적는다. 예전 빌드의 관찰은 해당 버전의 역사 근거다.
- **남은 차이:** 미구현과 구현됐지만 아직 정상 입력으로 확인하지 않은 것을 함께 명시한다. 한 노드의 구입 확인을 모든 랭크/효과의 실전 통과로 확장하지 않는다.

### 배타·재분배 공통 차이

- 망치 wrath/sundering: 구입·로드·미리보기 배타 구현/자동검사, P2/P3의 별도 정상 저장에서 반대 분기 잠금 관찰. 두 분기의 같은 구간 전투 비교는 아직 없다.
- Banner protection/zeal, Pillar pulsing/heavens: 보존 참조 관계만 있다. 실제 구매/UI/저장/전투는 없음.

- `exclusiveGroup:null`인 다른 조합을 원작 동시허용 사실로 만들지 않는다. 현재 Trial/Shackles 병행은 E 정책이다.

### 무엇을 아직 말할 수 없는가

1. P4 상세기록은 광부 구조 버튼에 도달한 지점까지다. P5의 운반기 완료·최종 자산·보고/재로드는 이후 결과를 입증하지만, 빠진 광부/상부4적/닻 조작의 모든 분 단위 입력·회피·선택 순서를 복원하지 못한다. 정상 입력 경로로 기록하되 연속 영상/모든 행동 로그라고 하지 않는다.
2. R5a1→R5a2→R5a3→R6a→R6a1에 걸친 정상 획득 진행이다. 동일 최종 빌드의 처음부터 끝까지 완주는 아니다. R6a1에서는 기존 L8 복원과 별도 신규 사망창 회귀를 확인했다.
3. 도구로 캡처/판독하는 동안 메뉴가 아닌 곳의 시간이 흐른 경우, 의도적으로 회피/치유를 하지 않은 실패 시험이 있다. 5사망을 자연스러운 Normal 난이도 실패율로 환산하지 않는다.
4. 활성/교전/이동/메뉴/진입대기 값은 접속별 부분값이며 교전·이동은 겹친다. 메뉴·도구 왕복이 대부분인 벽시계 시간을 순수 플레이시간으로 쓰거나 서로 빠진 구간을 합산하지 않는다.
5. 첫5분·15–30분·60–90분, 첫90분의 의미 있는 선택3회/2종·재방문, 2–4시간·두 새 세이브 빌드 차이의 관찰창은 여전히 열린다. 콘텐츠 수/테스트 수/정지 적 계산으로 시간·재미·AAA 품질 합격을 만들지 않는다.
6. 실제 청취, 모바일 손조작, Hard 정상 경로, 전체 L1→L30→Master 피날레가 없다. 원작 동등 재미/속도/완성도나 전체 제품 완성을 주장하지 않는다.

### 6.3 경제·반복·L30에서 숨기기 쉬운 차이

1. **훈련비 보호는 아직 없다.** D1의 T 마지막 보고120G를 `reservedTrainingGold.expert=120`으로 gold에 포함해 예약하는 정책은 제안이다. 구입/판매/제작/강화/선택수리·사망이 예치금을 침범하지 않고, 승급에서 예치+gold를 함께 차감하는 단일 커밋·불변식까지 구현해야 한다. 지금의 유한 공급1,170G만으로 무제한 선택지출/사망 후 훈련비 안전을 증명하지 못한다. 최소길은 재료/G0을 보존한다.
2. **선택 원정은 현재 코드에 없다.** D1은 Q 보고 뒤 별도 `quarry_drill`의6적, 처치XP/G/재료0, 생존 귀환보고마다 XP0/12G/철1을 제안한다. 캠페인 defeated/상자/보고를 지우지 않고 별도 runId·단조 종료 watermark·한 번에 한 원정·원자 성공/포기·옛/미래 run 거절이 필요하다. 무보상 포기는 되돌릴 수 없음 안내, 동시사망/재로드/두탭·영수증한도도 확인한다. 반복을 필수 레벨 파밍으로 삼지 않는다.
3. **상위 기술의 저장 계약은 재설계가 필요하다.** 현재 recovery는6액티브·CD상한60초를 검사한다. Guardian CD120/100/80초·새 채널/깃발/기둥/스택을 추가할 때 단순 카탈로그 해금으로는 저장되지 않는다. action ID/틱/스택·피해원 별칭/복제와 로드/이동/죽음/재분배의 정책을 명시하고 검사해야 한다.
4. **L18 출발은 아직 가정이다.** 현재 E XP 곡선에서 L18 누적7,840→L30 22,600의 차이14,760XP는 산술뿐이다. 실제 Expert 이후 종료 레벨을 먼저 확인하고, 후반5지역 보상·낮은티어 감쇠·Master300G 보호·장비/제작 지출을 처음부터 따로 검증한다. 이 문서에 없는 후반 XP 분배를 구현된 설계로 꾸미지 않는다.

## 7. 다음 업데이트의 최소 증거와 완료 판정

각 변경은 정확한 코드/앱/공개 경로, C/U/E 값의 변화, 실제 handler 검사와 fixture 조작 범위, 전체검사 원문 결과, 일반 입력의 시작/종료 레벨·XP·티어·자산/지출·처치/사망·보고·저장을 기록한다. 신뢰할 수 없는 시간·누락 행동·듣지 않은 소리는 빈칸으로 남긴다.

- 후속 새 지역/원정/승급이 코드에만 생겼으면 **구현/진행 중**, 테스트만 통과했으면 **자동 확인**, 실제 입력 증거가 있는 좁은 범위만 **일반 입력 확인**으로 갱신한다.
- 현재 Q 저장을 승격/자동 이전하거나 기존 적·보상을 리셋하지 않는다. 원본·루트·각 QA 후보·일반/QA 저장의 차이를 유지한다.
- 같은 최종 빌드의 L1→L5→L15→L30→Master 이후 보고/결말, 실제 Normal/Hard·반복 빌드·시간/선택/가독성·청취·모바일까지 확인하기 전에는 전사 완결/AAA/원작 동등성을 선언하지 않는다.
- 전사 완결 뒤에도 마법사·궁사·M5 협동의 남은 범위를 따로 밝힌다. 테스트 수, 공개 URL, 참조53 ID 또는 L8 스크린샷은 전체 제품 완료 기준이 아니다.
