# R2d 공개본 입력 QA와 R2e 후속 수정

2026-10-09 dot Chrome 공개 Site v4, 기존 qa-r2-live-20261009, 실제 UI·키·마우스 입력. 저장/HP/XP 주입 없음.

확인:
- 기존 저장은 E 상호작용·1 물약과 '기존 배치 유지'로 표시됐다.
- 망치 Q 지정 창의 마우스 취소 버튼이 변경 없이 복귀했다.
- E 중복은 거절됐고 Q 유지. 다만 안내가 원래 E 소유 행동(상호작용)이 아니라 편집 중 망치 이름을 표시했다. R2e에서는 기존 소유 행동을 먼저 조회해 안내하도록 수정하고 회귀1개 추가.
- Q→Z 실제 지정 후 HUD도 Z. 기존 Q 입력은 시전하지 않고, Z 입력은 마나15·재사용시간을 지불했다. 긴 누름 자동 반복이 아닌 단발.
- 새로고침→같은 프로필 이어하기→키 설정에서 Z와 기존 E/1 및 캐릭터 성장을 그대로 확인했다. 저장된 망치 쿨다운도 전부 초기화되지 않았다.
- 방패 토글 선택 후 실제 우클릭을 놓아도 HUD active 유지, 새 왼쪽 공격 후 active 해제. 일반 마우스 release/lostcapture가 토글을 지우던 문제의 실제 회귀 통과.

발견한 정지 문제:
- 정상 계속하기 뒤 별도 빈 QA 탭을 열고 원래 탭으로 돌아왔을 때 메뉴가 열리지 않았고 마나19→29를 관찰했다. 그 사이 도구 왕복 약52초가 있어 전환 순간과 전후 포커스 시간은 분리할 수 없지만 이벤트 처리만으로 자동 일시정지를 보장할 수 없다는 실제 실패다.
- R2e는 각 프레임에서 document.hidden 또는 document.hasFocus() 실패를 별도로 검사해 메뉴를 열고, runtime gate에서도 focused=false이면 전투를 금지한다. 기존 blur/visibilitychange 리스너도 유지한다. 실제 동일 탭 전환 재검사는 배포 후 필요하다.

아직 미검증: 마우스 양버튼의 실제 중첩/별도 해제, 한글 IME 실기, 보조 마우스 버튼 플랫폼 동작, 모바일, 저장장치 의도적 실패를 주입하지 않은 실제 차단 UI, 신규 추천 프로필 정상 진입, 강화 후 적 전투 체감. 단위검사 범위를 실제 플레이로 대체하지 않는다.

R2e 실제 재검사: 강력 새로고침 뒤 새 충돌 안내 문구로 새 코드 로드를 확인했다. 그러나 native Ctrl+T/Ctrl+W 탭 전환에서도 자동 메뉴가 표시되지 않아 포커스/visibility 검사만의 실제 합격을 주장하지 않는다. R2f는500ms 초과 렌더 중단도 안전 일시정지 사유로 삼아 숨은 전투 tick 없이 명시적 재개를 요구한다. 메뉴에 빌드 ID와 실제 브라우저 표시/포커스 값을 표시해 상태를 구분한다.500ms 이상 실제 기기 성능 정체도 자동 정지하며, 이는 몰래 피격되기보다 안전하게 재개할 수 있게 하는 자체 설계다. 추가 실기 확인이 필요하다.

원인 범위 주의: 위 결과는 dot 자동화 브라우저의 이 두 경로에 한한다. 실제 일반 브라우저의 모든 수동 전환 실패라고 일반화하지 않는다. 후속 관측을 위해 R2f 메뉴에 빌드ID, 실제 visibilityState/hasFocus, 마지막 blur·visibility 이벤트 UTC 시각을 표시한다. 공개 UI에서 읽기 전용으로 확인하고 새 탭/별도 창 여부도 함께 관찰한다. 일시정지 사유와 계속하기 버튼은 모달에 명시한다.
