## Resource observations and interpretation

The successful full diagnostic used Node v24.19.0, availableParallelism 9, and default test concurrency. Every 0.5 seconds, the Python wrapper read RSS from `/proc` for the launched Node parent and descendants. The sampled peak was 1,350,748 KiB (about 1.29 GiB) across nine processes including the parent. It collected 534 samples. Conventional cgroup memory/CPU-limit and OOM-event files were not exposed. The Node probe reported about 2.07 GiB available memory at launch; this is not a proven per-process/container limit.

RSS is sampled, not a complete memory trace, and shared pages can be counted in multiple processes. No memory sample exists for the failed run. No resource exhaustion, timeout, signal or harness defect has therefore been established as the original cause. Failure did not recur in either the isolated file or the same-default-concurrency complete follow-up. A serial/limited-concurrency run was unnecessary and was not used to turn an unresolved default-concurrency failure into a pass. The record remains: initial unexplained file-process failure, then complete unchanged-source success. There is no evidence-backed source or test weakening justified by the failure.
