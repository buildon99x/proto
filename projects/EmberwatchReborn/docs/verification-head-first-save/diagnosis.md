## Code-confirmed mechanism
- `main.js` action acceptance and runtime gate stop new combat/simulation while `busy` is true. The prior accepted action can initiate a durable critical checkpoint on action start, RNG, incoming damage, healing, channel payments, status changes, defeat/death; periodic saves occur after1s simulation time.
- The router captures physical combat pulses with a wall-clock timestamp. Main explicitly expires pulses older than150ms before delivering resumed input. Utility/slot/expert queues have their own same150ms freshness contract. This differs from the skill recovery queue and the >500ms rAF safety stop.
- `reproduce-input-expiry.mjs` executes the extracted actual acceptance/flush handlers with production router/gate/input-observation code and a logical clock.149/150ms retain a roll pulse;151/300ms expire it with the exact combat toast. A held Space does not recreate the expired initial pulse. The combat delivery boundary is a probe: this is not save-duration, CPU, native-play, damage, or full combat evidence.
- Controller publication occurs only after validation and durable save success. Ordinary `syncCommittedBattle` then replaces vitals/stats/potion cooldown while preserving a running action and other recovery state. Removing busy can overwrite newly incurred damage or resource costs and silently lose later commands at the `dispatch` busy guard.

## Observation identity limitation
The input observer tracks a single pending connection, not the router’s entire set of physical pulses. `inputLatency.clear(reason)` has no expired-action/token argument. `main.js:169/731` may therefore end the currently pending dodge observation after a different old queue item expires. Fresh dodge input clears earlier skill/mobility/attack router pulses, but not all possible pulse kinds (e.g. block). The current normal-play evidence must preserve this uncertainty; no additional live instrumentation was injected. The logical-clock reproduction uses only one pending combat pulse and therefore proves the exact150ms expiry mechanism within that isolated fixture, not the identity of the live expired item.
