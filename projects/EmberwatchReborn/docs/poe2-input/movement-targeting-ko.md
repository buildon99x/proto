# POE2 PC 이동·타겟팅 이식 조사

조사일: 2026-10-10 UTC. 대상: Emberwatch Reborn의 조작 체계. 원작 실행·프레임 측정은 하지 않았다.

## 결론과 정확성 한계

공식 최신 목록에서 0.5.5e(2026-10-05)를 확인했다. 0.5.0~0.5.5 주요 패치, 0.5.5e, 그리고 관련 이전 공지를 확인했다. 모든 중간 핫픽스를 완독한 것은 아니므로 “0.5.5e 실측 완전 동일”이라고 표현하면 안 된다. 확인된 기능 계약을 이식하고, 세부 자동선택·동시입력 순서는 별도 검증해야 한다.

가장 중요한 구조: 이동 입력 모드, 조준 투영 방식, 스킬 도중 커서 추적, 자동 접근 허용, 명시적 이동 정지는 서로 다른 설정이다. 하나의 `attackInPlace` 플래그로 합치면 원작 옵션을 재현할 수 없다.

## 증거 등급

- **공식확인(O)**: GGG 직원의 패치 본문. 원작의 공개 계약으로 사용 가능.
- **공식영상관찰(V)**: 실제로 영상 장면/입력을 관찰한 경우만 해당. 이번 조사에서는 영상 URL만 확인했으며 장면을 직접 검사하지 못했다. 따라서 V 판정 없음.
- **커뮤니티보조(C)**: 이용자의 재현 보고. 공식 사이트에 게시되어도 GGG 보증이 아니며 현재 빌드의 확정 계약으로 사용하지 않는다.
- **미확인(U)**: 최신 실행 검증 또는 구체적 공식 설명이 필요하다.
- **이식설계(D)**: 구현을 위한 제안. POE2 내부 코드/알고리즘이라는 뜻이 아니다.

## 공식확인 계약

| 항목 | 확인된 계약 | 버전·근거 |
|---|---|---|
| 이동모드 | WASD와 클릭이동이 구분되어 존재한다. | O: S2/S3 |
| Aiming Mode | Cursor Targeting은 전방형 투사체·타격을 화면 커서에 맞추며 Ground Targeting은 커서가 가리키는 지면 위치 위를 지나게 한다. 지면 직접지정 스킬은 이 설정과 무관하다. 기본값: WASD=Cursor, 클릭이동=Ground. | O: S2, 0.3.0 |
| Cursor Tracking | 스킬 키를 놓은 뒤에도 실행중 스킬의 목표 위치/방향을 갱신하는 별도 옵션. 기본값: WASD=켜짐, 클릭이동=꺼짐. Rolling Slam/Whirling Assault 등에 영향. 모든 스킬을 무조건 자유회전시킨다는 의미는 아니다. | O: S3, 0.4.0 |
| 제자리공격과 WASD | `Attack in place stops movement`가 켜져 있어도 WASD에서 이동하면서 사용할 수 있는 스킬의 걷기를 막지 않는다. | O: S1, 0.1.1 |
| 스킬별 접근 설정 | `Always Attack Without Moving` 설정이 존재하며 일부 스킬에서 선택할 수 없던 버그가 수정됐다. | O: S4, 0.5.0 |
| 회피+질주 | 회피 버튼을 유지하면 구르기 뒤 질주로 전환. 질주에는 지속시간 제한이 없으며 질주중 피격 시 넘어짐. `Keep Sprinting while moving`이면 버튼 해제 후에도 정지/스킬사용 전까지 지속. | O: S2, 0.3.0 |
| 회피 전용 바인딩 | 홀드해도 질주하지 않는 별도 회피 입력을 제공. 기본 미할당이며 입력 옵션에서 지정. | O: S4, 0.5.0 |
| 예약 스킬의 목표 | 예약된 스킬도 목표 갱신이 가능해야 한다. 갱신 불가가 버그로 수정됐다. 큐 길이·시간창은 공개되지 않았다. | O: S4, 0.5.0 |
| 채널링 전환 | 다른 채널링 스킬로 기존 채널링을 중단하지 못하던 버그 수정. | O: S4, 0.5.0 |
| 스킬별 방향갱신 | Glacial Cascade 방향변경 불가 수정, Storm Wave는 스킬 시작부에서만 방향변경하도록 수정. 범용 무제한 재조준은 틀린 구현. | O: S2, 0.3.0 |

주의: S1의 “다른 스킬을 홀드중 새 스킬 불발” 수정은 **Controller Improvements** 섹션이다. 이를 PC 마우스 입력의 완전한 우선순위 근거로 확장하지 않는다.

## 클릭이동/좌클릭 상태·입력표

다음 표의 C/U 행은 구현 후보·QA 항목이며 원작과 동일하다고 보증할 수 없다.

|---|---|---|
| 클릭이동, 지면 LMB 누름 | 클릭 위치를 이동 목적지로 삼음. 커서만 옮기는 것은 새 이동명령이 아님. | C: C1 |
| 클릭이동, 이동중 이동가능 스킬 사용 | 이전 목적지를 향한 이동을 유지하며 시전/공격 가능. 공격 입력 자체가 기존 이동 취소라는 가정 금지. | C: C1/C2 |
| LMB 이동 홀드, 커서 이동 | 홀드가 계속 이동명령을 공급하는 경우 조준 변경과 이동 방향이 충돌한다는 보고. 최신 갱신시점/빈도 미확인. | C: C1; U |
| LMB 해제 | 마지막 목적지까지 이동한다는 보고. “버튼을 놓으면 즉시 정지”로 단정하지 않는다. | C: C2 |
| LMB에 스킬 바인딩, 적 클릭 | 이동/공격 문맥입력으로 동작한다는 보고. 적을 명시 선택했는지, 가까운 적 보정인지 구별 필요. | C: C3; U |
| LMB, 상자/NPC/아이템 위 | 상호작용 대상으로 접근하는 보고. WASD에서도 일부 상호작용 자동접근이 보고됨. | C: C3 |
| Shift+LMB 스킬, 상호작용물 위 | 입력이 멈추는 버그 보고가 존재. GGG는 전달하겠다고 응답했을 뿐 정상 설계로 확정하지 않음. | C: C3 |
| Move Only 바인딩 | 공격과 이동을 분리하는 후보. 최신 기본 LMB 할당, Move Only 메뉴, 상호작용 우선순위 전체는 공식자료 미확인. | U |
| 제자리공격 입력 + 사거리밖 적 | 자동접근 억제라는 의도와 기존 이동정지는 분리해야 함. 모든 스킬에서 사거리밖 공발/불발/방향발사 중 무엇인지 미확인. | C: C2/C3; U |
| 명시 정지키/옵션 | 클릭이동의 `Attack in place stops movement` 옵션 효과는 C2가 뒷받침하나 최신 기본값·재개조건은 미확인. | C: C2; U |

## WASD 상태·입력표

| 현재 상태 / 입력 | 계약 또는 검증사항 | 등급 |
|---|---|---|
| WASD 이동 + 커서 조준 | 이동 방향과 공격 방향 분리. 2023 공식 Mercenary 영상이 원출처이나 이번에 장면 직접검사는 못함. | 영상출처 S8, 상세는 U |
| WASD 이동 + 제자리공격 | 이동가능 스킬은 걷기 유지. | O: S1 |
| 이동키를 놓고 공격키 유지 | 정지/자동접근 여부는 스킬별 설정까지 조합해 검증. | U |
| 이동키+회피 | 키 이동 방향으로 회피한다는 이용자 보고. | C: C4 |
| 이동키 없음+회피 | 커서 방향으로 회피한다는 이용자 보고. | C: C4 |
| 클릭이동모드+회피 | 기존 이동 목적지보다 커서 방향을 사용한다는 보고. | C: C4 |
| 회피+질주 유지 | 질주 연속유지 옵션/회피전용 바인딩은 위 공식 계약 적용. | O: S2/S4 |

WASD의 대각속도 정규화, 상반키 동시입력, 장애물 슬라이딩, 최단경로 탐색법, 회피중 방향전환, 질주 가속시간은 이번 자료에서 확인하지 못했다.

## 목표 선택·고정·재선택

| 입력/상태 | 조사 결과 | 확정도 |
|---|---|---|
| 적 위에서 공격 시작/유지 | 적에 고정되고 커서를 옮겨도 해당 적을 공격하는 `namelock` 보고. | C: C5 |
| 지면 공격 홀드중 적이 커서 통과 | 새로 적에 고정될 수 있다는 보고. | C: C5 |
| 홀드 해제 후 다른 위치에서 재입력 | 고정을 풀고 새 목표를 선택하는 해결법 보고. 현재 모든 스킬 공통인지 미확인. | C: C5 |
| 고정 대상 사망/비대상화/화면밖 | 자동으로 다음 적을 선택하는가, 지면조준으로 되돌아가는가, 공격을 멈추는가: 공식 계약 없음. | U |
| 사거리밖 대상 | 자동접근과 스킬 내재 이동(돌진/도약)을 분리할 것. 사거리·시야·도달불가별 동작 미확인. | U |
| 타격/투사체 조준 | 화면 커서투영과 지면투영을 구분한다는 계약만 확정. 가시성 가중치·선택 반경·최근 대상 히스테리시스는 미공개. | O: S2 / U |
| 실행중 목표 갱신 | 키 홀드/해제, Cursor Tracking, 스킬의 방향갱신 허용 구간이 각각 관여. | O: S2/S3 |
| 큐에 들어간 다음 스킬 | 목표를 갱신하지 못하게 고정하면 공개 버그 수정과 어긋남. | O: S4 |

Cursor Tracking은 namelock 해제 옵션이라는 공식 설명이 아니다. Aiming Mode 역시 자동조준 on/off와 같은 기능이 아니다. C5에 나온 불편함을 복제해야 할 공식 설계로 간주하지 않는다.

## 이식용 상태 모델 (D: 독립 구현안)

입력 컨트롤러는 아래 상태를 분리해서 보관한다.

- `movementMode`: click / wasd
- `moveIntent`: none / groundDestination / keyVector / interactApproach / attackApproach
- `aimingMode`: cursor / ground
- `cursorTrackingAfterRelease`: boolean
- `skillIntent`: released / pressed / held; OS 키반복과 별도 관리
- `aimIntent`: groundPoint / entityTarget / direction; hover 상태와 지속고정을 별개로 관리
- `skillPhase`: idle / windup / active / recovery / channel; 갱신 허용 구간은 스킬 데이터
- `alwaysAttackWithoutMoving[skill]`: 접근 요청을 억제하는 정책
- `attackInPlaceStopsMovement`: 클릭 이동 목적지 정지 정책. WASD 이동가능 스킬 예외 반영
- `dodgeSprintHeld`, `dodgeOnlyPressed`, `keepSprintingWhileMoving`: 세 의미를 구분
- `queuedSkill`: 원작 큐 깊이나 밀리초를 주장하지 않는 프로젝트 고유 정책

동시입력 전역 우선순위는 공식 확인되지 않았다. 임의 `dodge > attack > interact > move` 구현은 프로젝트 정책이라고 표기하고, 원작 우선순위라고 말하지 말 것. 이동가능 공격은 이동+공격 병행이므로 단일 상태머신에서 한쪽을 무조건 없애면 안 된다.

최소 회귀검사:
1. 클릭이동 목적지를 찍고 다른 방향으로 스킬 사용: 목적지와 조준을 혼동하지 않는가.
2. 좌클릭 이동 홀드/해제/재클릭을 구분하는가.
3. 공격 중 커서 이동, 키 해제 후 커서 이동, Tracking 옵션 on/off를 각각 검사.
4. 같은 스킬에서 Cursor/Ground 조준의 높이 차이가 보이는가. 지면지정 스킬은 같아야 함.
5. WASD+제자리공격에서도 이동가능 스킬의 이동이 유지되는가.
6. 사거리밖 적/상자/아이템, 이동불가 지형, 죽은 타겟에서 무한접근·입력잠김이 없는가.
7. 공격홀드→회피→공격, 공격홀드→다른스킬, 채널링→채널링 전환 검사.
8. 일반 회피 홀드→질주, 회피전용 홀드→질주하지 않음, 질주 유지옵션+키해제 검사.
9. UI나 채팅 포커스/창 이탈 뒤 홀드 상태를 남기지 않음. 이는 안전한 구현 요구이며 원작 알고리즘 주장이 아님.

## 키바인딩 범위

Shift 제자리공격, Space 회피는 초기 이용자 보고에서 확인되지만 현재 신규 설치 기본 키 배열 전체를 검증하지 못했다. 따라서 최신 기본값으로 확정해서 복제하지 않는다. 스킬 슬롯 수/보조바/플라스크/무기교체 기본키는 다른 조사 또는 실제 설정화면 검증이 필요하다. 확정 가능한 최신 바인딩 변화는 S4의 **회피 전용 액션 기본 미할당**이다.
