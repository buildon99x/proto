# SILT 0.15.0 source candidate → jh-laptop QA

## 구현 범위와 검증 경계

지정 브랜치 `codex/dead-freight-gunplay-v1`의 `ece20bb8d57ab922dce7833ead3019df6c56689f`에서 별도 dot 작업 디렉터리를 확보해 구현했다. 기존 체크아웃과 사용자 노트북은 구현에 사용하지 않았다. `brief.md`, `spec.md`, `eval.md`를 구현 전에 갱신했고, 기존 lockfile과 일치하는 설치된 의존성/패키지 관리자 캐시를 재사용했다. 새 패키지 설치, 보안 설정 변경, main 병합, 공개 배포는 없다.

Canal Ward에 선택 교전 적 **SILT** 한 개체를 추가했다. Black Pines, 기존 보스/현상금/탈출 조건과 저장 스키마는 그대로다. 프로토타입 소스 후보이며 실제 GPU 화면, 정상 입력 전투, 실제 출력 장치 청음, 전경 상대 마우스 감각과 프레임 타임은 이번 dot 검증에 포함되지 않는다.

- `app/liquid-metal.js`: 가시선·유한 추적·고정 조준 블레이드·코어·복원 상태와 물리 시각 조회
- `app/liquid-metal-view.js`: 원본 절차형 은색 인간형, 최대6개 탄공/금속 테두리, 몸체 붕괴·재형성, 블레이드 예고, 주황 코어, 사망 웅덩이
- `app/player-projectiles.js`, `shot-resolver.js`: 실제 비행 탄환의 개체별 관통 및 접촉 순서/감쇠/중복 방지
- `core.js`, `melee.js`, `inventory-game.js`, `game.js`: 공격 취소, 수류탄·폭발·근접 재질 반응, 구분되는 피격 표시·기존 금속 녹음 연결
- `regions.js`: SILT 위치 `(-110,-28)`, 선택 폐품 경로, 기존8명에1명 추가. 보스는 기존 ID7, SILT는 ID8

## 첫 플레이 계약

- 외피 응집력100, 코어 체력80. 외피 피격은 인간 머리 배율/방어구를 적용하지 않고 응집력만 줄인다. 탄환은 같은 시뮬레이션 구간에서도 뒤 표적까지 실제로 진행하며 접촉마다 잔여 피해가70%가 된다. 일반 적/벽/배럴은 계속 탄환을 멈춘다.
- 외피 붕괴 후1.4초 + 복원1.0초 동안 코어를 맞힐 수 있다. 코어에 준 피해는 복원돼도 유지된다. 코어에 맞은 탄환은 멈춘다. 같은 시각 산탄/배럴 폭발은 최초 접촉 전 코어 노출 상태를 공유한다.
- 외피 탄공은0.6초에 닫힌다. 피·인간 사망 얼룩은 만들지 않는다. 외피 마커는 은색 마름모, 코어는 확대된 주황색, 처치는 별도 금속 처치 표시다. 실제 청각적 구별은 후속 청음 대상이다.
-3m 안에서0.75초 블레이드 예고, 마지막0.25초 조준 고정,0.16초 공격 상태,0.7초 회복. 한 공격의 피해는 한 번뿐이다. 옆 이동/X 회피/엄폐로 대응하고, 예고 중 외피를 붕괴시키면 대기 공격이 취소된다.
-120Hz 탄환 시간 순서를 유지한다. 변형 외피는 공유 historical pose를1/960초 이하 구간으로 나눠 변화하는 상자 경계를 연속 스윕한다. 이는 경량 충돌 근사이며 렌더 삼각형과의 정확한 교차를 주장하지 않는다.
- 일시정지는 AI·복원·탄공 시간을 멈춘다. 사망/탈출은 대기 블레이드와 탄공을 지운다. 이미 죽은 SILT의 붕괴 자세는 유지한다. 새 원정은 코어/외피/이펙트를 초기화한다.

## 결정적 회귀와 수정 기록

새 테스트는 `test-liquid-metal.cjs`, `test-liquid-metal-ballistics.cjs`, `test-liquid-metal-view.cjs`, `test-liquid-metal-runtime.cjs`다. rendererless 테스트는 명시적 fixture이며 일반 입력 완주나 실제 shader 컴파일 증거가 아니다.

독립 코드 검토에서 재현한 다음 경계 문제를 수정하고 회귀검사로 남겼다.
1. 외피 붕괴 뒤 재스윕이 이미 지난 시각에 코어 접촉을 만드는 문제: 후속 탄환의 시간 하한을 갱신한다.
2. 복원 종료 프레임에서 실제로는 종료 전 도착한 코어 탄환을 놓치는 문제: `[노출 시작, 종료)`의 물리 시각으로 판정한다.
3. 동시 외피/배럴 명중의 배열 순서에 따라 코어가 죽거나 생존하는 문제: 그룹 공통 노출 snapshot과 실제 충돌 시각을 폭발에 전달한다.
4. 플레이어 사망/탈출 화면에 남는 블레이드·탄공과, 이미 죽은 몸이 다시 커지는 문제: 생존/사망 자세를 구분해 정리한다.
5. 짧은 사거리 탄환을 시간 하한 이동으로 부활시켜 역방향 접촉을 기록하는 문제: 먼저 사거리 종료를 처리한다.
6. 붕괴/복원 중 프레임 끝 자세로만 판정해 생기는 실제 접촉 누락·가짜 접촉: 물리 시각의 변형 경계를 스윕한다.

최종 앱58개 명령·1072개 명명 검사(1050 PASS줄+world22), 문법38개 명령, 정적 빌드와 별도 경계 감사315건은 종료코드0이다. 독립 재검토96개 집중 검사도 통과했다. 검사 결과와 실행 차단은 `qa-evidence/liquid-metal-2026-10-16/verification.json` 및 같은 디렉터리 원시 로그에 기록한다. 기존315개 경계 감사도 별도로 실행한다.

## 검증 차단

필수 `pnpm sync:registry`는 설치된 tsx4.22.4 CLI가 임시 IPC `/tmp/tsx-1000/18.pipe`를 열 때 `listen EPERM`으로 종료했다. 동일 명령의 승인된 실행 재시도도 같은 OS 오류였다. 정책 거절 응답이나 패키지 누락으로 단정하지 않는다. 우회 실행/설정 변경은 하지 않았다. `build:vercel`도 실제 실행했으며 첫 단계의 동일 registry 동기화에서 `/tmp/tsx-1000/31.pipe` EPERM으로 종료했다. 후속 프로젝트/런처 빌드 단계는 실행되지 않았으므로 전체 빌드 통과를 주장하지 않는다. 생성 registry는 수정하지 않아 이 소스 후보 버전이 아직 반영되지 않았다. 후속 환경에서 두 필수 명령을 그대로 실행해 닫아야 한다.

## jh-laptop 실행 절차

1. 기존 작업 트리를 먼저 확인·보존한다. 원격 브랜치를 fetch하고 이번 핸드오프의 정확한 커밋을 별도 worktree에서 연다. 일반 저장/기존 QA 결과를 덮어쓰지 않는다.
2. 루트/프로젝트 AGENTS를 읽는다. 기존 의존성이 없거나 새로운 설치가 필요하면 먼저 보고한다. 기존 도구로 `pnpm --filter dead-freight test`, `pnpm --filter dead-freight lint`, `pnpm --filter dead-freight build`, `pnpm sync:registry`, `pnpm build:vercel`을 실행한다. 마지막 두 검사는 dot에서 닫지 못한 게이트다.
3. `node projects/dead-freight/tools/serve-qa.cjs 39620`으로 loopback 정적 서버를 열고, 새 임시 브라우저 사용자 디렉터리에서 `http://127.0.0.1:39620/?testProfile=workshop-qa`를 연다. 지원되지 않는 새 testProfile 이름이나 일반 프로필을 사용하지 않는다. 포트 충돌이면 확인 후 다른 loopback 포트를 쓴다.
4. `build-manifest.json`의 version0.15.0 및 두 liquid-metal 모듈 해시를 확인한다. Canal Ward, 관광객, 권총으로 시작한다. 부두 `(-112,82)`에서 서쪽 외곽 길을 따라 북상해 폐품 구역 `(-110,-28)`의 SILT 표지로 접근한다. 지형/전투는 정상 키·마우스 입력으로 진행한다.
5. 외피 명중→탄공 확대/닫힘→붕괴→주황 코어→복원 또는 처치를 캡처한다. 근거리 권총의 외피3발/코어2발은 조준이 모두 성공한 경우의 기준값이며 실제 빗나감·거리 감쇠를 성공으로 계산하지 않는다. 복원 후에도 코어 손상이 남는지 확인한다.
6. 예고·조준 고정 뒤 옆 회피와 엄폐, 피격1회, 예고 중 붕괴 취소를 정상 입력으로 확인한다. 피격/붕괴/복원/처치의 화면 구분, 화면에 코어가 드러날 때의 실제 명중, 일시정지/재개와 사망/새 원정 정리를 확인한다.
7. 일반 입력 경로와 별도로 명시적 상태 fixture를 쓴다면 그 자료를 분리한다. 외피 뒤 적/벽/배럴의 한 탄환 다중 접촉, 동시 폭발, 프레임 경계와 정확한 피해는 모델 fixture 결과와 실제 WebGL fixture 결과를 섞지 않는다.
8. 기존 Canal 서쪽 윈치/동쪽 페리, Black Pines 탈출과 치료·투척·근접 취소를 회귀 확인한다. 실제 출력 장치 청음과 전경 마우스/프레임 타임은 headless 입력/스크린샷으로 승인하지 않는다.

## 참고의 성격

사용자 원문의 T-800 명칭과 링크의 T-1000은 다른 설정이다. 이 게임은 원본 명칭 SILT를 사용한다. [Stan Winston School 제작 기록](https://www.stanwinstonschool.com/blog/t2-judgement-day-t1000-fx)과 [American Cinematographer 제작 기록](https://theasc.com/article/terminator-2-fx/)의 탄공·금속 변형·재결합 표현만 참고했다. 코어 약점·응집력·시간·피해·회피 규칙은 이 프로젝트의 자체 게임 설계이며 영화 설정의 사실로 제시하지 않는다. 영화 모델/캐릭터 외형/음원/텍스처는 포함하지 않았다.
