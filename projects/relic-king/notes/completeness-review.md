- 스크린샷: `assets/review/`(이번 조사에서 새로 찍음), `assets/screenshots/play/`(기존 `play` 산출물)

## 0. 결론

**유물왕은 시스템과 검증 체계는 1.0에 가까운데, 게임 경험은 첫 1시간짜리 수직 슬라이스에
머물러 있다.** 첫 1시간은 촘촘하다. 드랍 8초, 새 종 분당 1~2개, 제보 약 4분 간격, 첫 유일
유물은 1시간 40분에 들어온다. 그런데 플레이어가 내리는 결정은 거의 없다. 판매는 기본 설정이
자동으로 처리하고, 재투자도 자동이며, 발굴단은 자동 순회한다. 이 게임의 유일한 긴장
장치라는 제보 레이스는 **첫 10시간 동안 62회 중 62회가 누를 버튼이 없는 관전**이고
**[실측]**, 그중 84~93%는 가만히 있어도 이긴다 **[실측]**. 3시간 30분이 지나면 제보마저
끊기고, 10시간까지 자산이 한 자리도 움직이지 않는다 **[실측]**. 140시간 뒤에 오는 엔딩은
한 줄짜리 배너다 **[코드]**. 한마디로 **돌아가는 게임은 있는데, 하는 게임은 없다.**

다음에 할 일은 이 순서를 권한다.

1. **제보 레이스를 첫 분부터 "결정"으로 만든다.** 자금을 태워 적중률을 사게 하는 식으로,
   이 게임의 핵심 딜레마(팔면 강해지고 순위는 떨어진다)를 긴장의 순간에 바로 꽂는다.
   첫 원정을 가까운 거점으로 보내는 기존 처방 ①도 여기에 함께 넣는다. 비용은 작고
   효과는 가장 크다. → §5.1
2. **도감을 "세트"로 쪼개고, 세트 완성에 보상을 건다.** 3시간 30분 이후의 빈 구간에 목표를
   심고, 1,902종을 게임 안의 구조로 만든다. → §5.2
3. **절정의 순간 세 곳의 연출을 채운다.** 유일 획득, 엔딩, 복귀 화면이다. 소리도 여기서
   처음 넣는다. 코드량은 작은데, 재미 정의 ①이 지금 이 연출 부족 때문에 무너지고 있다. → §5.3

하지 말 것도 분명히 적는다. **서버 전환과 유저 간 거래소(brief 로드맵 v0.6), 유물 종 수
확대, 새 시스템 추가**는 지금 멈춘다. 30시간 운영 플레이에서 도감이 29%이고 **[실측]**,
시스템은 이미 열한 개다. 문제는 콘텐츠 양이 아니라 **결정의 밀도**다.

## 2. 현재 완성도 — 경험 기준

### 2.1 잘하고 있는 것 (근거 있는 것만)

- **소재가 진짜다.** 1,902종이 실존 개체이고, 티어가 현존 개체 수다. 신라 금관 상세
  화면(`assets/screenshots/play/02-return-24h.png`)의 "완형 금관이 현재 여섯 점뿐이라"
  같은 문장은 지어낸 등급으로는 얻을 수 없는 무게를 준다. 비교작 중 이 축에서 유물왕보다
  나은 것은 동물의 숲 박물관(실제 미술품 43점) 정도다. 그 게임은 AAA이고, 실물 수는 유물왕의
  약 1/44이다 (`notes/completeness-review-sources.md` §3.6).
- **공개된 규칙과 정직한 경고.** 30시간 화면에 "룩소르의 드랍 간격이 하한 8초에
  닿았다 — 여기서 발굴력을 더 올려도 유물이 더 나오지 않는다"가 뜬다
  (`assets/review/active-30h-a-dig.png`). 방치형에서 이렇게 말해 주는 게임은 드물다.
- **검증 체계.** 헤드리스 시뮬, UI 실조작(`play` 12종), 계측(`playlog`), 스프라이트
  QA, 마이그레이션 체인 v1→v10이 있다. 1인 프로젝트로는 이례적이고, 이 보고서의 수치도
  전부 이 도구로 얻었다.
- **첫 1시간의 밀도.** 운영 플레이 기준 첫 20분에 신규 종이 시간당 135종, 20분~1시간에
  93종이다 **[실측]**. "목록이 채워지는 것"(brief의 대상 사용자)은 이 구간에서 확실히
  전달된다.

### 2.3 화면에서 본 것

**첫 화면이 "기다려라"로 시작한다.** 새 게임 1.5초 시점의 발굴단 카드에 "쿠스코로 이동
중 · 도착 2118:59 후"가 뜬다(`assets/review/fresh-desk-00-first.png`). 35시간짜리 타이머가
분:초로 찍혀 있다(§8 버그 1). 첫 5초에 플레이어가 받는 메시지는 "네 팀은 하루 반 뒤에
도착한다"이다 **[추론]**.

**핵심 판타지가 화면 맨 아래에 있다.** 지층을 파 내려가는 도트 단면은 이 게임의 "깊이 =
연대"를 한 장에 보여주는 장치다(brief 핵심 가치). 그런데 이 단면은 "직접 발굴(레거시)"이라는
이름으로 세계지도 밑에 깔려 있다. 모바일에서는 스크롤 1,300px 아래다
(`assets/review/fresh-mob-01-20s.png`). "레거시"는 개발자 용어가 플레이어 화면으로 샌
것이다. 30시간 시점에는 단면의 대부분이 빈 남색 면이다(`active-30h-a-dig.png`).

**결정이 경험보다 먼저 온다.** 47초 만에 "본거지를 정하자" 모달이 뜬다
(`fresh-desk-02-60s.png`). 플레이어가 아는 건 유물 한 점뿐인데, 카드 세 장은 "유물이 자주
나온다 / 관람객이 많이 몰린다" 같은 결과문만 준다. 비교할 근거가 없는 선택은 결정이 아니라
관문이다 **[추론]**.

**0달러에 종합 1위로 시작한다.** 새 게임 헤더가 "종합 1위 · 자산1위 · 도감1위 · 명성1위"다.
라이벌도 0에서 시작하기 때문이다 **[코드]**(`RIVAL_SEED`, `engine.ts:61`). "1위에
오른다"는 목표가 첫 화면에서 이미 달성된 채로 시작하고, 몇 분 뒤 7위로 떨어진다. 오르는
이야기가 아니라 떨어졌다 되찾는 이야기가 된다 **[추론]**.

**소장고는 벽이다.** 30시간 소장고는 735점 아이콘 격자 한 장이다(`active-30h-b-vault.png`).
테두리 색으로 티어가 보이는 건 좋다. 하지만 개별 물건은 사라지고 "많음"만 남는다.
도감(`active-30h-e-codex.png`)도 같은 모양이라 두 화면의 역할이 겹친다 **[추론]**.

**절정이 반쯤 비어 있다.** 유일 유물을 손에 넣는 순간의 모달은 "세계에 단 하나"
배지까지는 잘 세운다. 그런데 본문이 "이름과 내력은 감정이 끝나면 공개된다"이다
(`assets/screenshots/play/01-unique-acquired.png`). T4 감정에는 감정소 Lv.4와 기본 시간의
3배가 필요하다 **[코드]**(`APPRAISAL_UNLOCK_LAB_LEVEL`, `balance.ts:357`). 게임 전체에서
가장 큰 순간이 "무엇을 가졌는지 모른다"로 끝난다.

## 3. 재미 정의 세 문장은 전달되는가

| 문장 | 판정 | 근거 |
| --- | --- | --- |
| ① "세상에 하나뿐인 것을 내가 가졌다." | **절반** | 전용 도트와 배지는 있다(v0.4). 획득 순간에 이름이 없고, 가진 뒤에 할 일(전시 말고)이 없다. 전시해도 박물관은 13시간 46분에야 선다 **[실측]** |
| ② "조금만 늦었으면 놓쳤다." | **전달 안 됨** | 첫 10시간 62회 중 누를 버튼이 있는 제보 0회. idle 10시간 48승 9패, 운영 140시간 545승 42패 **[실측]**. 실제 경험은 "가만히 있으면 대개 얻는다"다. 응답 창 중앙값도 15초로 설계(60~150초)의 1/4이다 **[실측]** |
| ③ "이게 진짜 있는 물건이라고?" | **상위 티어에서만** | T3·T4의 내력은 좋다. 그러나 드랍의 92%는 8초 간격으로 감정되자마자 자동 매각된다(idle 10시간 드랍 4,465 · 매각 4,098 **[실측]**). 플레이어가 그 물건의 이름을 읽을 틈이 없다. 생성분 내력은 "메트로폴리탄 미술관이 기원전 13~12세기로 편년한 주자다. 재질은 은." 같은 조립문이다 **[코드]** |

brief는 v0.2·v0.4에서 세 문장을 모두 "유지·강화"로 판정했다. 그 판정은 **데이터와
화면 요소가 있는가**를 봤다. **플레이 중에 그 순간이 실제로 오고, 플레이어가 무언가를
하는가**를 보면 ②는 성립하지 않는다. 구현이 부족한 것이지 정의가 틀린 것은 아니다.
②는 여전히 이 게임을 다른 방치형과 구별하는 유일한 문장이다. 그래서 첫 번째 처방이
여기로 간다.

## 4. 비교 대상 — 누구에게서 무엇을 배우나

### 4.1 고른 기준과 결과

유물왕이 기대는 축은 넷이다. **방치형 페이싱, 수집·도감의 동력, 희소성과 영구성의 긴장,
작은 규모에서 완결감을 만드는 연출**이다. 축마다 가장 잘하는 게임이 다르다고 보고, 소규모
성공작을 우선했다. 사실과 수치의 출처는 전부 `notes/completeness-review-sources.md`에 있다.
이 조사 환경에서는 원문 페이지를 직접 열 수 없어서, 근거는 검색엔진 요약이다. 결정에 쓰일
숫자는 원문으로 다시 확인할 필요가 있다.

| 게임 | 축 | 규모 | 유물왕에 가져올 것 |
| --- | --- | --- | --- |
| Universal Paperclips (2017) | 페이싱·완결 | 사실상 1인, 정적 웹 | 곡선이 평평해질 때 **게임을 바꾼다**(3단계 전환). 조작은 적고 결정은 무겁다 |
| A Dark Room / Candy Box (2013) | 첫 화면 | 1~2인, 텍스트 | **UI가 열리는 것 자체가 보상**이다. 처음엔 거의 다 숨긴다 |
| Cookie Clicker (2013) | 긴장의 층 | 1~2인, 웹 | 골든쿠키는 **저위험·고빈도** 사건(약 13초, 5~15분 간격)이다. 고위험 사건만 있으면 사이가 빈다 |
| Gnorp Apologue (2023) | 완결형 인크리멘털 | 1인 | **끝이 있다**(8~20시간). 성장이 숫자와 그림으로 동시에 보인다. 약 한 달에 10만 장, 리뷰 95% 긍정 |
| Kittens Game / Melvor Idle | 조작량 | 1인 | **잡무를 먼저 문제로 보여 주고, 자동화를 보상으로 준다** |

| 동물의 숲 박물관 | 실물 지식 | AAA(아이디어만) | **해설자 한 명의 목소리.** 위작 판별로 지식이 곧 기술이 된다 |
| Travel Frog (2017) | 귀환 이유(경고) | 소규모 | 여행과 귀환만 있고 결정이 없었다. 중국 DAU가 약 2개월 만에 2,160만에서 360만으로 줄었다 |
| Reigns / Papers, Please | 결정의 무게 | 1~10인 | **입력 하나에 결정 하나.** 실패도 기록으로 수집된다 |

경고 사례로 Clicker Heroes 2(기대 길이와 실제 길이의 불일치)와 NGU Idle 후반부(같은 빈
구간이 후반에 다시 나타남)를 봤다. 가장 비슷한 상업 선례는 **Two Point Museum**(2025)이다.
원정을 보내 유물을 가져와 박물관을 운영하는 구조가 거의 같다. 하지만 3D 중형 스튜디오
게임이고 유물이 가상이라 본문에서 뺐다. 이 밖에 Antimatter Dimensions, Balatro, Hades,
Cultist Simulator를 검토했고, 제외 이유는 원본 §6에 있다.

### 4.2 비교에서 나온 판단 네 가지

**① 유물왕에는 "중간 층" 사건이 없다.** Cookie Clicker의 긴장은 두 겹이다. 자주 오고
놓쳐도 되는 것(골든쿠키), 드물고 큰 것(시즌)이다. 유물왕의 사건은 드랍(너무 잦고 무의미,
시간당 1,350건)과 제보(드물고 크지만 행동 불가)뿐이다. 중간이 비어 있어서 1시간 이상
공백이 idle 첫 10시간의 45%다 **[실측]**. 방향은 새 사건을 만드는 것보다 **제보를 중간 층으로
끌어내리고, 유일 레이스는 그 위에 드물게 두는 것**이다. 제보 대상 대부분은 이미 T2(진귀)다.

**② 도감이 다른 무엇에도 연결되지 않는다.** Stardew는 95개짜리 도감에 해금 두 개와 세트
하나를 걸었다. 유물왕은 1,902종에 걸린 것이 순위 가중치(도감 0.35)와 엔딩 조건뿐이다.
`play-first-10h.md` §4가 이미 "고리 2의 노란 칸"으로 이걸 짚었고, 나도 같은 결론이다.
다만 그 문서는 이것을 "별도 논의"로 미뤘다. 나는 **우선순위 2위**로 올린다. 3시간 30분
이후의 빈 구간을 메울 수 있는 장치가 사실상 이것뿐이기 때문이다.

**③ 작은 게임의 완결감은 "끝"과 "목소리"에서 나온다.** Paperclips와 Gnorp는 끝이 있고,
A Dark Room과 Paperclips는 텍스트 톤 하나로 세계를 세운다. 둘 다 아트가 거의 없다.
유물왕은 끝이 140시간 뒤의 배너 한 줄이고, 목소리는 규칙 설명문뿐이다. 이 축은 3D나 AAA와
무관하게 **글과 소리로 채울 수 있다.** 그래서 한계 인정과 충돌하지 않는다.

**④ 영구 상실은 약점이 아니다. 행동할 수 없는 영구 상실이 약점이다.** 비교작 조사는 XCOM
Ironman과 다크패턴 문헌을 근거로 "영구 상실을 옵트인으로 돌리라"고 권했다(원본 §4.1, §4.4).
**나는 동의하지 않는다.** 척추 3번이 이미 가장 나쁜 형태를 막고 있다. 부재 중에는 유일을
잃지 않고, 알림이 앱 밖으로 나가지도 않는다. 그리고 영구성은 문장 ②의 원천이다. XCOM에서
배울 것은 오히려 Solomon의 다른 말이다. 실시간 패배는 "AI 탓"으로 읽히고, **준비와 공개된
확률로 결정되는 패배**라야 받아들여진다. 지금의 제보는 준비할 것도, 결정할 것도 없다.
그래서 고칠 곳은 가혹함이 아니라 **행위자성**이다.

## 5. 약점과 개선 방향 — 우선순위순

각 항목에 근거·방향·기대 효과·비용·부작용·확인 방법을 붙였다. 비용은 상대 규모다
(S = 하루 안, M = 며칠, L = 한 릴리스).

### 5.1 [1순위] 제보 레이스를 첫 분부터 결정으로 만든다

**근거.** 첫 10시간 제보에서 행동 가능한 경우가 idle 0/58, 운영 0/62다 **[실측]**. 행동
수단 두 가지가 모두 발굴단을 전제하기 때문이다. [집중 굴착]은 그 거점에 현지 작업 중인
팀이, [급파]는 유휴 팀이 있어야 쓸 수 있다(`TipBanner.tsx`, `engine.ts:1243`). 그런데 첫 팀은
35.3시간 뒤에야 페루에 도착한다. 발굴단이 도착한 뒤에는 거의 모든 제보가 [집중 굴착]
가능이 된다(140시간 운영 1,373/1,435). 그러니 그 뒤로는 "항상 누르는 버튼"이 되어 역시
결정이 아니다 **[추론]**.

**방향.**
1. **첫 원정은 왕복이 세션 안에 끝나는 곳으로 보낸다**(`play-first-10h.md` §8 ①을 그대로
   채택). `recommendSites()`에 거리 항을 넣거나, 첫 파견만 교토(도착 1.3시간)로 고정한다.
   이것만으로 1~6시간 구간에 [집중 굴착]이 생기고, 제보 풀에 거점이 하나 붙는다.
2. **직접 발굴에도 행동을 준다. 값은 자금으로 치른다.** 예를 들어 "현장 인부 임시 증원 —
   자금 $X, 적중 28%→45%"처럼, **판매로 얻은 자금을 순간의 확률로 바꾸는** 버튼 하나다.
   그러면 핵심 딜레마(자금 vs 순위)가 긴장의 순간과 직접 이어진다. 레이스를 이기려면 팔아야
   하고, 팔면 순위가 떨어진다. 값은 현재 자금의 비율로 정하고 공개한다(척추 5번).
3. **[집중 굴착]도 공짜 결정이 되지 않게 비용을 보여 준다.** 지금은 "원정비 2배"가 정산 때
   조용히 빠진다. 배너에 금액으로 쓴다.
4. **응답 창 중앙값 15초를 설계값(60~150초)으로 되돌린다**(`play-telemetry.md` §7.3에 이미
   있던 처방). 결정할 시간이 없으면 버튼도 의미가 없다.

**기대 효과.** 문장 ②가 처음으로 플레이에서 성립한다. 첫 10시간에 "사람이 내린 의미 있는
결정"이 0에서 수십 회로 늘어난다 **[추정]**.

**비용.** S~M. 1은 한 함수, 2는 엔진 함수 하나와 배너 버튼 하나, 3은 문구, 4는 상수다.

**부작용.** 2는 척추 4번("클릭은 언제나 선택")과 부딪치지 않는다. 안 눌러도 기존 28%가
그대로 적용되기 때문이다. 다만 승률이 오르면 유일 공급이 빨라져 엔딩이 앞당겨진다. 1은
먼 거점의 기대수익을 늦춰 중후반 성장을 늦출 수 있다(기존 문서의 추정). 둘 다 `sim --hours
168`의 엔딩 시각으로 확인해야 한다.

**확인.** `playlog --hours 10 --bucket 10`에 **"행동 가능 제보 비율"**과 **"결정이 들어간 제보
수"**를 새 지표로 넣는다(§9 프로브를 `playlog.ts`로 옮기면 된다). 목표는 첫 10시간 행동 가능
비율 50% 이상, 승률 60~75%다. 지금의 84~93%는 긴장이 성립하기에 너무 높다 **[추정]**.

### 5.2 [2순위] 도감을 세트로 쪼개고, 세트에 보상을 건다

**근거.** 운영 플레이의 신규 종은 6~10시간 구간에 0이다. 도감은 30시간에 29%, 140시간
엔딩에 75%다 **[실측]**. 도감이 무엇을 여는지에 대한 대답이 없다. 1,902종은 거점별 목록일
뿐이라 "다음에 무엇을 채울까"라는 중간 목표가 생기지 않는다(`active-30h-e-codex.png`) **[추론]**.

**방향.** 실제 역사로 묶이는 **소형 세트 5~8종**을 거점마다 여럿 만든다. 예를 들면 "신라
금속공예", "람세스 시대 석비", "로마 은화 한 세대" 같은 묶음이다. 데이터는 이미 있다.
각 유물에 시대·출토지·재질·형태 필드가 있다 **[코드]**(`artifacts.generated.ts`). 세트를
완성하면 명성 보너스를 주고, 박물관에 "특별전" 슬롯을 열고, 큐레이터 한 줄(§5.4)을 보여 준다.
보상은 수입이 아니라 **명성과 전시**로 준다. 척추 2번("수입은 발굴력에서만")을 건드리지
않기 위해서다.

**기대 효과.** 3.5시간 이후의 목표가 "도감 %"라는 먼 숫자에서 "이 세트 두 점 남음"으로
가까워진다. 자동 매각 대상 중에 세트 구성품이 끼면 **판매 여부가 다시 결정이 된다.**
§5.5와 맞물리는 효과다 **[추론]**.

**비용.** M. 세트 정의 데이터(빌드타임 생성 + 손 큐레이션 일부), 도감 화면에 세트 보기,
보상 연결. 1,902종 전부를 세트에 넣을 필요는 없다. 상위 티어와 초반 거점부터 시작한다.

**부작용.** **영구 상실 가능 종(T2 이상)을 세트 필수 조건에 넣으면 좌절 장치가 된다**
(Stardew에는 영구 결손이 없다). 세트를 "N종 중 M종"으로 두거나, 필수 구성은 T1 이하로 채운다.
명성 가중이 커지면 순위 균형이 흔들리므로 `sim`의 3축 순위를 다시 재야 한다.

**확인.** `playlog` 10분 격자에 "세트 진척 사건" 열을 추가한다. 목표는 **어느 1시간 구간에서도
의미 있는 사건이 0이 아닌 것**이다. 지금 idle 3.5~10시간은 6.5시간 연속으로 거의 0이다.

### 5.3 [3순위] 절정 세 곳의 연출을 채운다 — 유일 획득, 엔딩, 복귀

**근거.** 유일 획득 모달이 이름을 숨긴다(§2.3). 140시간 엔딩은 `EndingBanner` 한 줄이다
("도감을 채우고 종합 순위 1위에 올랐다 — 유물왕. 발굴은 계속된다.", `ui/Overlays.tsx`)
**[코드]**. 오프라인 복귀는 조치할 것이 없으면 "12시간 0분 동안 자금 +$2269만" 토스트
한 줄이다(`OfflineSummary.tsx`) **[코드]**. 소리는 코드베이스 전체에 없다 **[코드]**.

**방향.**
1. **레이스로 얻은 유일은 그 자리에서 감정을 끝낸다.** 아니면 감정 대기를 "봉인 해제
   의식"으로 연출한다. 둘 중 앞쪽을 권한다. 감정소 Lv.4 조건은 도감 입고에 대한 규칙이지,
   획득의 쾌감을 미룰 이유가 아니다.
2. **엔딩은 한 장짜리 기록으로 만든다.** 걸린 시간, 가진 유일 목록, **놓친 유일과 그걸
   가져간 라이벌**, 가장 오래 쥔 유물, 판매로 포기한 순위가 들어간다. 기록패(v0.5)와 같은
   형식으로 공유할 수 있게 하면 비동기 경쟁과도 이어진다.
3. **복귀 화면에 "무엇을 캤는가"를 적는다.** 자금만 보여 주지 말고 새 종 이름 3개, 이긴 제보,
   진 제보를 보여 준다. Travel Frog에서 배울 점은 귀환에 **발견**이 있어야 한다는 것이고,
   그 사례의 실패에서 배울 점은 **결정**도 있어야 한다는 것이다.
4. **소리는 Web Audio로 합성한다.** 외부 리소스 0 규칙과 충돌하지 않는다. 드랍 틱은 끄고,
   제보 시작·레이스 결과·유일 획득·세트 완성 네 곳에만 둔다. Paperclips가 5시간 동안 소리
   없이 버틴 사례가 있으니(원본 §3.1), 소리는 **절정에만** 쓰는 게 이 게임의 톤에 맞다 **[추정]**.

**기대 효과.** 문장 ①이 획득의 순간에 성립한다. 140시간을 쓴 플레이어에게 가져갈 것이 생긴다.

**비용.** S~M. 전부 UI 계층이고 밸런스는 건드리지 않는다.

**부작용.** 1은 "감정이 T4를 연다"는 감정소 업그레이드 동기를 약하게 한다. 레이스 획득분에만
예외를 둔다면 영향은 작다 **[추정]**.

**확인.** `play` 시나리오 `unique`에 "모달에 유물 이름이 보인다"는 단언을 추가한다.

### 5.4 [4순위] 목소리를 준다 — 큐레이터 한 명, 라이벌 여섯 명

**근거.** 라이벌은 이름, 발굴력 배율, 선호 거점, 매각 기준만 있다 **[코드]**. 제보 배너에서도
"같은 제보를 받은 수집가 2명"으로 익명이다(`01-tip-banner.png`). 손으로 쓴 디테일은 40종뿐이다.

**방향.** 큐레이터 NPC 한 명의 1~2문장 해설을 **세트 단위**로 쓴다(종 단위가 아니다). 세트
50개에 두 문장씩이면 100문장이다. 1,902종에 쓰는 것보다 훨씬 작고 효과는 비슷하다 **[추정]**.
라이벌 여섯 명에게는 성격 한 줄과 레이스 결과별 대사 몇 개를 준다. 제보 배너에는 경쟁자의
이름이 뜨게 한다. "이무진이 쫓고 있다"는 "수집가 2명"보다 훨씬 강하다.

**비용.** M. 대부분 글쓰기다. 사실 검증이 필요한 문장은 척추 1번 원칙대로 모르면 쓰지 않는다.

**부작용.** 라이벌에 얼굴이 생기면 "패배의 원인"이 사람으로 읽혀 좌절이 커질 수 있다.
반대로 복수의 동기도 생긴다. 놓친 유일을 가져간 라이벌을 기록패 고스트처럼 추적 대상으로
보여 주면 긍정 쪽으로 기운다 **[추정]**.

### 5.5 [5순위] 판매 결정을 필요한 곳에만 되살리고, 나머지 잡무는 없앤다

**근거.** 기본 설정이 `autoSellBelow: 1`, `autoReinvest: true`다(`engine.ts:151`) **[코드]**.
그 결과 idle 10시간에 매각 4,098회 중 플레이어가 내린 결정은 0회다 **[실측]**. brief의 첫 장치
("매 드랍마다 지금 팔 것인가")는 설정 화면의 드롭다운 하나로 줄어들었다. 반대로 운영
플레이가 첫 10시간에 치른 22회는 대부분 보관소 업그레이드(15회) 같은 잡무다 **[실측]**.
**결정은 자동화되어 있고, 잡무는 수동이다.** 방향이 거꾸로다 **[추론]**.

**방향.** 흔함·보통의 자동 매각은 그대로 둔다. **T2 이상, 또는 세트 구성품(§5.2)이 들어오면
카드 한 장으로 묻는다.** "쥔다(순위 +n) / 판다(+$m)"의 이지선다이고, Reigns처럼 입력 하나로
끝난다. 모아서 한 번에 처리하게 해도 된다. 대신 보관소·습도·복원·보안 업그레이드는 자동
재투자에 포함하거나 관장 고용의 보상으로 자동화한다(Kittens식).

**비용.** M. **부작용**: 결정 카드가 쌓이면 새로운 잡무가 된다. 하루 결정 수를 계측해 상한을
정한다. brief의 관여 예산(하루 2~3회 방문)을 기준으로 한 방문에 카드 5장 안팎이 적당하다 **[추정]**.

### 5.6 [보류] 엔딩 길이

비교작 조사는 메인 엔딩을 10~20시간으로 당기라고 권했다(Gnorp·Paperclips 근거, 원본 §3.4).
**지금 결정하지 말 것을 권한다.** 140시간이 긴 이유의 상당 부분은 3.5~10시간 같은 빈 구간이다.
§5.1과 §5.2가 그 구간을 채우고 나서 다시 재야 "길다"가 콘텐츠 문제인지 페이싱 문제인지
갈린다. 다만 **"끝이 어디에 있는지"를 첫 시간에 보여 주는 것**은 지금 해도 된다. 시즌 D-84와
엔딩 조건(종합 1위 + 도감 목표)을 헤더나 규칙 화면에서 한 줄로 알려 주는 정도다.

## 9. 재현

```bash
pnpm --filter relic-king playlog -- --hours 10 --bucket 10
pnpm --filter relic-king playlog -- --hours 168 --bucket 360
```

제보 순간의 행동 가능성 프로브다. 이번에 `app/src/sim/`에 임시 파일로 두고 `npx tsx`로
돌렸고, 커밋하지 않았다. 계측 지표로 채택하려면 `playlog.ts`의 두 정책 루프에 넣으면 된다.

```ts
import { advance, createPersistentRecord, createWorld, runAutoRoutine } from "../game/engine";
import { actExpansion, liquidateSurplus, STEP_EARLY, STEP_LATE } from "./policy";
for (const mode of ["idle", "active"] as const) for (const H of [10, 140]) {
  const w = createWorld(); const rec = createPersistentRecord(); let acc = 0; let last: string | null = null;
  let n = 0, focus = 0, idleTeam = 0;
  while (w.t < H * 3600 && !w.ended) {
    const s = w.t < 1200 ? STEP_EARLY : STEP_LATE;
    if (mode === "active") { liquidateSurplus(w); runAutoRoutine(w); actExpansion(w); }
    else { acc += s; if (acc >= 60) { acc = 0; runAutoRoutine(w); } }
    advance(w, s, false, s, rec);
    const tip = w.tip; const key = tip ? `${tip.artifactId}@${tip.layer}` : null;
    if (tip && key !== last) {
      n++;
      if (w.teams.some((t) => t.status === "on_site" && t.targetSite === tip.site)) focus++;
      else if (w.teams.some((t) => t.status === "idle")) idleTeam++;
    }
    last = key;
  }
  console.log(`${mode} ${H}h tips=${n} 집중가능=${focus} 유휴팀=${idleTeam} 버튼없음=${n - focus - idleTeam}`);
}
```

결과: idle 10시간 58/0/0/58, 140시간 1,373/1,315/0/58 · 운영 10시간 62/0/0/62,
140시간 1,435/1,373/0/62. [급파]는 압축 이동 4시간 이내라는 조건이 더 붙으므로, "유휴팀"
열은 행동 가능성의 상한이다.

화면 캡처는 빌드 산출물(`app/dist`)을 로컬 HTTP로 띄우고 Playwright로 찍었다. 시점별 세이브는
위와 같은 정책 루프로 만든 World를 `serialize()`한 뒤, 브라우저에서 `lastTickAt`을
`Date.now()`로 바꿔 `localStorage["relic-king/save/v1"]`에 넣었다. 이렇게 하면 오프라인 정산이
끼어들지 않는다.

**이 측정의 한계.** 시드 1개이고, 두 정책은 사람이 아니라 양 극단이다(`eval.md` §23.8과 같음).
행동 가능성은 시드와 무관한 구조(첫 팀의 이동 시간)가 결정하므로 한계의 영향이 작다. 승률은
시드에 따라 흔들린다.

## 10. 지시서에 대한 메모

지시서는 산출물을 진단으로 한정하고 코드 수정을 막았다. 조사해 보니 §8의 버그 1은 한 줄짜리
수정이다. 진단의 범위를 지키려고 고치지 않고 보고만 한다. 또 비교작 조사는 원문 접근이 막힌
환경에서 검색 요약에 기댔다. 지시서가 요구한 "출처를 달아라"는 지켰지만, 원문 대조는 하지
못했다. 결정에 쓸 수치(특히 판매량·DAU)는 원문으로 다시 확인할 필요가 있다.
