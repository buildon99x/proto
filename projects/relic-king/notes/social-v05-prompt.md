# 작업 지시 — 유물왕 v0.5: 플레이어 간 경쟁 (비동기 기록패 교환)

너는 `projects/relic-king`을 맡는다. 목적은 하나다 — **플레이어끼리 상태를 주고받아
경쟁이 실제로 느껴지게 만든다.** 아래 다섯 개로 쪼개고, 다섯 다 "검수 가능한 상태"로
끝내야 한다.

  S1. 내 상태를 짧은 코드 하나로 내보낸다(기록패). 카톡·디스코드에 그대로 붙는 길이여야 한다.
  S2. 남의 기록패를 붙여 넣으면 내 세계에 **고스트 라이벌**로 들어와 계속 자란다.
  S3. 순위표가 "누가 몇 위"가 아니라 **"어느 축에서 몇 시간 차이로 지고 있는가"**를 보여준다.
  S4. 제보 레이스(§8.6)에 고스트가 참가해, 경쟁이 순위 숫자가 아니라 **사건**으로 온다.
  S5. 위 넷이 척추 3번(영구 상실은 접속 중에만)과 "런타임 외부 요청 0"을 하나도 깨지 않는다.

## 1. 지금 상태 (측정된 사실 — 여기서 출발한다)

전부 이 레포에서 직접 돌려 얻은 수치다. 믿지 말고 다시 돌려 확인해도 좋다(§5에 명령이 있다).

- **경쟁 뼈대는 이미 있다.** 라이벌 6명(`RIVAL_SEED`)이 하드코딩돼 있고, `fullRanking()`이
  플레이어와 라이벌을 **같은 3축 같은 가중식**(자산 0.30 · 도감 0.35 · 명성 0.35)으로
  나란히 채점한다. 고스트를 넣는 일은 새 스키마를 만드는 게 아니라 **행을 한 줄 더 넣는
  일**이다. 이 사실을 무시하고 별도 랭킹 시스템을 새로 짜지 마라.
- **세이브 코드는 공유 코드로 쓸 수 없다.** `exportText()`는 World 전체를 base64로 굽는다.
  측정: 갓 만든 월드 **206KB**, 24시간 진행 후 직렬화 **561KB**, base64 **749KB**. 원인은
  `codex` 2,000키 + `ledger` 2,000키다 — 플레이 시간과 무관하게 처음부터 크다. 공유용
  스냅샷은 **반드시 별도 스키마**여야 한다.
- **24시간 시점에 플레이어는 7명 중 꼴찌다.** 클릭 0회 24시간 시뮬 결과 종합 점수는
  서하윤 4.46% · H. 뮐러 4.11% · A. 파리드 4.08% · L. 로시 3.35% · 이무진 3.23% ·
  박준서 2.82% · **나 1.51%**. 엔딩은 약 141시간이므로 역전은 한참 뒤에 온다.
  **이게 이번 작업의 진짜 난제다** — 경쟁 장치는 "상대가 없어서" 안 도는 게 아니라
  "첫날 내내 꼴찌만 보여줘서" 안 돈다. 상대를 한 명 더 넣는 것만으로는 악화된다.
- **시즌은 이번 판에서 끝나지 않는다.** `SEASON_LENGTH_WEEKS = 12`(= 2,016시간)인데
  엔딩은 141시간이다. **시즌 경계는 실플레이에서 한 번도 오지 않는다.** 따라서 "시즌
  리더보드"·"시즌 정산 랭킹" 설계는 지금 구조에서 죽은 기능이다. 시즌을 경쟁의 단위로
  쓰고 싶으면 `SEASON_LENGTH_WEEKS`부터 손봐야 하고, 그건 밸런스 변경이라 `sim`이 따라온다.
  **이번 범위에서는 시즌을 건드리지 마라.** 경쟁 단위는 "이번 판(런)"이다.
- **유일(T4)은 세계에 12종, 각 1점이다**(`TIER4_SPECIES_TOTAL = 12`,
  `TIER_STOCK_PER_SPECIES[4] = 1`). 명성 축의 절반이 여기서 나온다. 고스트가 이걸 건드리면
  척추 3번과 정면으로 부딪힌다 — §3-D가 그 처리를 규정한다.
- **제보 레이스는 이미 영구 상실이 허용된 유일한 자리다.** 플레이어 적중 0.28, 집중 굴착
  0.60, 라이벌 0.10. 오프라인 중에는 라이벌이 상위 티어를 못 가져간다. 경쟁을 "사건"으로
  만들 자리는 여기지 순위표가 아니다.
- 세이브 코드 입출력 UI는 이미 있다 — `SettingsModal`이 `window.prompt`로 주고받는다.
  기록패도 같은 관용구를 따라라. 새 입력 패러다임을 발명하지 마라.

## 2. 설계 결론 — 받아들이고 시작해라

**서버를 붙이지 않는다. 비동기 기록패 교환으로 간다.** 근거 셋이고, 셋 다 취향이 아니라
구조에서 나온다.

1. **런타임 외부 요청 0은 이 프로젝트의 비협상 규칙이다**(`AGENTS.md` "환경 제약").
   레포 `AGENTS.md`가 `launcher/app/api`를 서버 표면으로 허용하지만, 루트 규칙은
   "프로젝트 지침이 더 좁으면 그쪽이 이긴다"고 스스로 밝힌다. 리더보드를 붙이려면
   규칙 개정이 **선행**해야 하고, 그건 구현자가 혼자 할 판단이 아니다.
2. **서버를 붙여도 순위는 검증되지 않는다.** 이 게임은 클라이언트 권위다 — 월드가
   localStorage에 있고 세이브 가져오기가 공개 기능이다. 점수를 서버에 올려도 위조는
   자유다. **검증된 경쟁은 이 구조에서 불가능하다.** 불가능한 것을 목표로 잡으면 안 된다.
   우리가 만들 수 있는 것은 "검증된 경쟁"이 아니라 **"비교 가능한 경쟁"**이다.
3. **장르가 비동기다.** `mda.md` §0이 세션을 "무한 세션 + 1~5분 개입"으로 정의한다.
   실시간 동기 경쟁은 이 세션 모양에 들어가지 않는다.

기존 서버 표면(`launcher/app/api/telemetry/[project]/route.ts`)은 **쓰기 전용 텔레메트리**다.
읽기 경로가 없고, 허용 목록(`TELEMETRY_PROJECTS`)에 `relic-king`이 없으며, Blob 한도를
넘기면 스토어가 30일 잠긴다. 리더보드로 전용할 물건이 아니다.

**그래서 무엇을 만드나**: 내 상태를 400바이트 안쪽 코드로 굽고, 상대가 그걸 붙여 넣으면
내 세계에서 **계속 자라는 고스트 라이벌**이 된다. 실시간이 아니라 "네가 어제 저장한 너"와
싸우는 구조다(레이싱 게임의 고스트와 같다). 트레이드오프는 정직하게 적어 둔다 —
**실시간 갱신이 없고, 상대가 코드를 다시 주기 전까지는 추정치로 자란다.** 그 추정이
어디까지 사실인지 UI가 숨기지 않는 것이 척추 5번(규칙 공개)을 지키는 방법이다.

## 3. 작업

### A. 기록패 스키마와 코드 (S1)

1. `app/src/game/rivalcard.ts`를 새로 만든다. 게임 로직이므로 `ui/`가 아니라 `game/`이다.
2. 스냅샷 타입 `RelicCard`를 정의한다. **필요한 최소치만 담는다** — 담은 필드 하나하나가
   위조 표면이고 마이그레이션 부채다.

   | 필드 | 뜻 | 비고 |
   | --- | --- | --- |
   | `v` | 스키마 버전(=1) | 이게 없으면 다음 버전에서 남의 코드를 못 읽는다 |
   | `n` | 표시 이름 | 12자 상한. 플레이어가 직접 정한다(§A-5) |
   | `t` | 스냅샷 시점의 `world.t`(초) | 고스트 성장 역산의 기준점 |
   | `d` | 스냅샷 시점 발굴력 | `digPower()` 결과 |
   | `a`/`c`/`f` | 자산·도감·명성 축 점수(0~1) | `fullRanking()`의 player 행 그대로 |
   | `u` | 보유 T4 종 id 목록 | 최대 12개. **id만**, 사본 정보 없음 |
   | `h` | 본거지 site id | 지도·제보 거리 계산용 |
   | `k` | 체크섬 | §D |

3. 인코딩은 `JSON → base64url`로 충분하다. **목표: 512자 이하.** 넘으면 필드를 줄여라.
   압축 라이브러리를 새로 넣지 마라(런타임 의존성이 는다). 실제 길이를 측정해 주석에 남겨라.
4. `parseCard(text): RelicCard | null` — 실패는 예외가 아니라 `null`이다. 남이 준 문자열은
   전부 적대적 입력으로 취급해라. 길이 상한, 버전 확인, 필드별 타입·범위 검사, 모르는 키
   버리기. `route.ts`의 `normalizeEvent()`가 같은 일을 하는 좋은 본보기다 — 읽고 와라.
5. 표시 이름은 `PersistentRecord`에 `ownerName` 필드를 추가해 보관한다(계정 영구 기록이지
   시즌 한정이 아니다). 기본값은 `"이름 없는 발굴자"`. `loadRecord()`가 얕은 병합을 하므로
   기존 저장은 그대로 읽힌다 — 마이그레이션 체인은 필요 없다. 확인하고 진행해라.

### B. 고스트 라이벌 (S2)

1. `cardToRival(card: RelicCard): RivalState`를 만든다. `RivalState`를 **확장하지 말고**
   기존 필드로 채워라 — `fullRanking()`·`digRival()`·제보 레이스가 전부 그 모양을 전제한다.
   식별은 `id`로 한다: `"ghost:<해시>"` 접두사를 쓰면 기존 라이벌과 한 배열에서 구분된다.
2. **역산 규칙**: 상대의 `a`(자산 점수)에서 `vaultValue`를, `c`에서 `owned` 길이를 되돌린다.
   `owned` 배열은 정확한 종 목록을 모르므로 **T4는 `u`의 실제 id로, 나머지는 자리표시 id로
   채운다**. `fullRanking()`의 도감 축은 `owned.length`만 읽고, 명성 축은 T4 종만 센다 —
   둘 다 이 채움으로 정확히 재현된다. 이 트릭이 성립하는 이유를 주석에 적어라(다음 사람이
   "왜 가짜 id가 들어 있지?"로 한 시간을 쓴다).
3. **성장**: 고스트는 `digRival()`을 그대로 탄다. `baseDig`는 `d`(스냅샷 발굴력)에서 환산하되
   **상한을 둬라** — 남이 준 숫자가 곱해져 들어오는 경로다. 클램프 값은 `RIVAL_SEED` 최대
   `baseDig`의 몇 배로 정하고 그 근거를 `notes/decisions.md`에 남겨라.
4. **보관**: 고스트는 `World.rivals`에 들어가므로 세이브에 자동으로 실린다. 스키마 버전을
   올리고(`World.version`에 9 추가) 마이그레이션 한 칸을 붙여라 — 기존 세이브에는 고스트가
   없을 뿐이지 깨지지는 않아야 한다. `save.ts`의 체인 관용구를 그대로 따라라.
5. **상한**: 동시에 받을 수 있는 고스트는 **3명**. 넘으면 가장 오래된 것을 밀어낸다.
   순위표가 13행이 되면 읽히지 않고, `step()`마다 도는 라이벌 루프가 그만큼 무거워진다.
6. 같은 사람의 새 기록패를 받으면 **교체**한다(`ownerName` 기준이 아니라 카드 해시 기준으로
   같은 사람인지 판별하는 방법을 정하고 주석에 적어라 — 이름은 바꿀 수 있다).

### C. 경쟁이 보이는 자리 (S3·S4)

1. **순위표를 고친다**(`RankTableModal.tsx`). 지금은 7행이 퍼센트 막대로 나열될 뿐이라
   "내가 꼴찌"만 읽힌다(§1의 측정 참조). 다음 셋을 넣어라.
   - **바로 위 상대와의 축별 격차**: 어느 축에서 얼마나 지는지. 3축 중 뒤지는 축을 강조한다.
   - **추월 예상**: 현재 성장률로 그 상대를 몇 시간 뒤에 넘는가. 역전 불가면 "이 속도로는
     못 넘는다"고 그대로 적어라 — 척추 5번이다. 희망적 관측을 표시하지 마라.
   - **고스트 행은 시각적으로 구분한다**(NPC와 다른 표식 + "N시간 전 기록" 표기). 실시간이
     아니라는 사실을 숨기면 그게 곧 거짓말이 된다.
2. **제보 레이스에 고스트를 넣는다**(S4). `spawnTip()`이 같은 거점 홈의 라이벌을 `rivals[]`에
   담고, 원거리면 `tipChase`로 급파한다. 고스트도 같은 경로를 탄다 — **분기를 새로 만들지
   말고 기존 경로에 태워라**. 적중 확률은 `TIP_RIVAL_HIT`(0.10)을 그대로 쓴다. 남이 준
   데이터가 확률에 영향을 주면 안 된다.
3. **로그에 이름이 뜬다.** `LogKind`의 `"rival"`·`"lost"`·`"won"`은 이미 있다. 고스트가
   가져갔을 때 "누가"가 실제 사람 이름으로 찍히는 것이 이번 작업의 감정적 핵심이다.
   새 로그 종류를 만들지 마라.
4. **획득 경로**: ⚙ 설정·세이브 안이 아니라 **순위표 안**에 "내 기록패 복사 / 상대 기록패
   붙여넣기"를 둬라. 경쟁이 일어나는 화면과 교환이 일어나는 화면이 같아야 한다.

### D. 위조와 악용 (S5)

명시적으로 막아라. 여기를 대충 하면 "붙여 넣으면 손해"가 되어 기능 자체가 안 쓰인다.

1. **고스트는 내 원장(`ledger`)을 건드리지 않는다.** 상대가 T4를 가졌다는 정보는 순위표와
   도감 표시에만 쓰고, **내 세계의 재고를 줄이지 않는다.** 줄이면 "남의 코드를 받는 순간
   내 유일 12종이 사라지는" 게임이 되고, 아무도 붙여 넣지 않는다. 이 결정을
   `notes/decisions.md`에 반드시 남겨라 — 나중에 "고스트가 유일을 가졌는데 왜 내가 또
   캐지?"라는 질문이 반드시 온다. 답: **세계 원장은 내 판 안에서만 유효하다.**
2. **영구 상실은 제보 레이스 안에서만, 접속 중에만.** 척추 3번 그대로다. 고스트에게 이
   예외를 넓히지 마라. 오프라인 적분 중 고스트는 상위 티어를 가져가지 못한다 —
   기존 오프라인 가드를 타는지 확인해라.
3. **체크섬은 위조 방지가 아니라 오타 방지다.** 클라이언트 권위 구조에서 서명은 의미가
   없다(키가 번들에 있다). 그러니 **체크섬을 보안 장치라고 주석에 적지 마라.** 하는 일은
   "잘린 코드·오타를 거른다"뿐이다.
4. **모든 수치에 상한을 건다.** 축 점수는 0~1, `u`는 최대 12개이며 실존 T4 id만,
   `baseDig`는 §B-3 클램프, 이름은 12자에 제어문자 제거. 상한 없는 필드가 하나도 없어야 한다.

### E. 문서

1. `notes/decisions.md`에 **G70** 절을 새로 연다. 최소한 다음 다섯을 적어라 —
   서버를 안 쓰는 이유(§2), 고스트가 원장을 안 깎는 이유(§D-1), `baseDig` 클램프 근거,
   고스트 3명 상한 근거, 시즌을 경쟁 단위로 쓰지 않은 이유(§1의 2,016시간 vs 141시간).
2. `changelog.md`에 `0.5.0` 절을 연다. 기존 절의 문체를 따라라 — 기능 목록이 아니라
   **무엇이 어떻게 달라 보이는지**를 쓴다.
3. `eval.md`에 §20을 추가하고 §5의 측정값을 표로 남긴다.
4. `project.json`의 `version`을 `0.5.0`으로, `summary`를 갱신한다. 그리고
   `pnpm sync:registry`를 돌린다.
5. `spec.md`에 기록패 스키마 절을 추가한다. 필드 표 하나면 된다 — 이건 저장 포맷이고,
   저장 포맷은 문서가 없으면 다음 버전에서 깨진다.

## 4. 하지 말 것

- **서버를 붙이지 마라.** `launcher/app/api`에 엔드포인트를 만들지 말고,
  `TELEMETRY_PROJECTS`에 `relic-king`을 넣지 말고, 런타임 `fetch`를 한 줄도 쓰지 마라.
  필요하다고 판단되면 구현하지 말고 **그 판단을 보고해라**(§7).
- **세이브 전체를 공유 코드로 쓰지 마라.** 749KB다.
- **`SEASON_LENGTH_WEEKS`를 비롯한 밸런스 상수를 건드리지 마라.** 건드렸으면 `sim`을 돌리고
  `eval.md` 측정표를 갱신해야 한다(AGENTS.md).
- **`app/src/render/worldmap-raster.ts`를 손으로 고치지 마라.** 생성 파일이다.
- **실시간·동기 기능을 만들지 마라.** WebRTC·폴링·롱폴링 전부 §2에 걸린다.
- **순위표에 없는 새 화면을 만들지 마라.** 5탭 + 헤더 아이콘 2개 구조가 UX 규격이다
  (`notes/ux-v02.md` §1.4).
- **기존 라이벌 6명을 지우지 마라.** 고스트가 0명일 때 게임이 비어 보이면 안 된다.

## 5. 검증 체크리스트 (전부 통과해야 끝이다)

```
pnpm --filter relic-king build          타입체크 + 빌드
pnpm --filter relic-king sim            헤드리스 밸런스 시뮬
pnpm --filter relic-king smoke          브라우저 스모크 + 스크린샷
pnpm sync:registry                      레지스트리 동기화
pnpm build:vercel                       배포 전 빌드
```

추가로 직접 확인하고 **수치를 보고해라**:

1. **코드 길이**: 24시간 진행한 월드의 기록패가 몇 자인가. 512자 이하인가.
2. **라운드트립**: `cardToRival(parseCard(makeCard(w)))`의 3축 점수가 원본
   `fullRanking()`의 player 행과 **소수점 둘째 자리까지 일치**하는가. QA 시뮬로 단언해라
   (`app/src/sim/qa_rivalcard.ts`를 새로 만들고 `package.json`에 스크립트를 추가한다).
3. **적대적 입력**: 빈 문자열, 잘린 코드, 1MB 문자열, `v` 없는 JSON, 축 점수 999,
   존재하지 않는 T4 id, `__proto__` 키 — 전부 `null`이고 예외가 새지 않는가.
4. **엔딩 영향**: 고스트 3명을 붙인 168시간 시뮬과 안 붙인 시뮬의 **엔딩 도달 시간 차이**.
   ±1시간을 넘으면 밸런스 변경이므로 `eval.md`에 근거를 남기고, 넘지 않으면 그 사실을 적어라.
   (v0.4의 좌표 이동이 −2분이었다. 같은 잣대를 쓴다.)
5. **세이브 호환**: v8 세이브(고스트 없음)를 읽어 v9로 올린 뒤 게임이 정상 진행되는가.
   `pnpm --filter relic-king qa:migration`에 케이스를 추가해라.
6. **순위표 스크린샷**: 고스트 1명이 들어간 상태의 순위표를 데스크톱·모바일 양쪽에서 찍어
   `assets/screenshots/`에 남겨라. 축별 격차와 "N시간 전 기록" 표기가 읽히는지 눈으로 확인해라.

§1의 측정을 재현하려면:

```
cd projects/relic-king/app

npx tsx <임시 스크립트>
```
