# 유물 데이터셋 규격

> ⚠️ **이 문서의 현존 수량·소장처는 초안이며 검증 전이다.** 이 게임의 전제가 "실존"이므로,
> 구현 전에 각 항목을 1차 자료(소장 기관 공식 페이지, 국가유산청·박물관 소장품 DB)로
> 확인해야 한다. 현재 실행 환경은 외부 네트워크가 차단되어 있어 검증이 불가능했다.
> 검증 항목은 [eval.md](../eval.md) 의 "데이터 검증"에 체크리스트로 있다.

## 1. 티어 매핑 원칙

**현실의 현존 개체 수를 그대로 게임 재고로 쓴다.** 밸런스를 위해 등급을 지어내지 않는다.

| 티어 | 현실 기준 | 게임 재고 | 예 |
| --- | --- | --- | --- |
| T4 유일 | 세상에 단 하나 | 1 | 로제타 석 |
| T3 국보 | 현존 한 자릿수 | 6 | 신라 금관 (실제로 6점) |
| T2 진귀 | 현존 수십 점 | 60 | 청자 상감 매병류 |
| T1 희귀 | 현존 수백~수천 점 | 2,000 | 로마 유리 향유병 |
| T0 흔함 | 현존 수만 점 이상 | 무한 | 상평통보, 데나리우스 |

경계가 애매한 유물은 **더 흔한 쪽으로 내린다.** "유일하다"는 주장이 틀리면 게임의 전제가
무너지지만, 흔한 쪽으로 잘못 놓는 건 아무도 다치지 않는다.

## 2. 필드 규격

| 필드 | 설명 | 예 |
| --- | --- | --- |
| `id` | kebab-case 식별자 | `silla-gold-crown` |
| `name` | 한국어 표기 | 신라 금관 |
| `era` | 연대 | 5~6세기 |
| `origin` | 출토지 | 경주 천마총 |
| `holder` | **실제 현 소장처** | 국립경주박물관 |
| `note` | 한 줄 내력 (Discovery 축의 실체) | — |
| `disputed` | 반환 논쟁 사실 (있을 때만) | "이집트 정부가 반환을 요구해 왔다" |
| `tier` / `valueFactor` / `site` / `minLayer` | 게임 값 | — |
| `shape` / `palette` / `seed` | 도트 스프라이트 생성 입력 | `crown` / `gold` / 4821 |

`holder`와 `disputed`는 장식이 아니다. 개인이 유물을 캐서 금고에 넣는 구도의
윤리적 리스크를 완화하는 장치다([notes/mda.md §7.1](mda.md)).

## 4. 스프라이트 생성 입력

`shape` 10종: `jar` `sword` `crown` `mask` `scroll` `coin` `tablet` `statue` `ornament` `mechanism`
`palette` 7종: `celadon` `gold` `silver` `earthenware` `stone` `wood` `glass`

같은 `(shape, palette, seed)`는 항상 같은 32×32를 만든다(결정론). 실물 재현이 목적이 아니라
**한눈에 구분되고 팔레트가 통일된 도트**가 목적이다. 실존성은 이름·연대·소장처·내력이 담보한다.

## 5. 확장 규칙

유물을 추가할 때 지켜야 할 것.

1. 현존 수량 근거를 `note`나 커밋 메시지에 남긴다.
2. T4를 늘릴 때는 **정말 하나뿐인지** 확인한다. 티어 인플레이션이 이 게임을 가장 빠르게 죽인다.
3. 권역·층 구성과 시대가 맞는지 확인한다. 조선 유물이 원삼국 층에서 나오면 안 된다.
4. 도감 완주율 80%가 엔딩 조건이므로, T4 비중이 20%를 넘으면 엔딩이 불가능해진다.
