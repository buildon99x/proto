## 0. 관리 대상 7종 — 이 문서가 다루는 범위

`notes/decisions.md` G3이 확인한 7종: **① 거점·세계지도 ② 발굴단·스텝 ③ 감정소·보관소
④ 박물관 ⑤ 경매장 ⑥ 거래소 ⑦ 암시장.** v0.1의 "상시 4지표 헤더 + 4탭"은 이 7종을
감당하지 못한다. 아래 §1이 재설계다.

## 1. 정보 위계 재설계 — 상시 헤더 + 탭 구조

### 1.1 상시 헤더 (모든 화면에서 보인다)

v0.1: `자산 │ 자금 │ 순위 │ 발굴력` 4항목. v0.2는 순위가 3축(G4)으로 쪼개지고
발굴력이 발굴단 여러 개의 합이 되고, 시즌(G2)이 새로 생긴다. 4항목을 유지한 채
**순위만 3축 요약으로, 발굴력은 합계 숫자 하나로 압축**해서 항목 수 자체는 늘리지
않는다 — 항목이 늘면 헤더가 모바일 폭을 넘긴다.

```
데스크톱:
┌───────────────────────────────────────────────────────────────────────┐
│ 자산 12.4억 ₩ │ 자금 3,200만 ₩ │ 순위 자산4위▲1·도감2위·명성5위 │ 발굴력 842/s(3팀) │ 시즌 D-42 │
└───────────────────────────────────────────────────────────────────────┘

모바일 (두 줄로 접는다. 늘어난 정보량을 한 줄에 강제로 넣지 않는다):
┌───────────────────────────────┐
│ 자산 12.4억 ₩ │ 자금 3,200만 ₩ │
│ 순위 4·2·5위    │ 발굴력 842/s │
└───────────────────────────────┘
```

순위 3항목(자산·도감·명성)을 탭하면 순위표 상세로 1단계에 진입한다(§1.2의
"한 번의 조작" 층). 시즌 D-day는 데스크톱에만 상시 노출하고 모바일에서는 도감 탭
안에 둔다(모바일 헤더 두 줄 예산을 넘기지 않기 위한 절충 — 시즌은 급하게 확인할
정보가 아니다).

### 1.2 3단 정보 위계 (v0.1의 3단 구조를 유지, 내용만 갱신)

| 단계 | v0.1 | v0.2 |
| --- | --- | --- |
| **항상 보인다** | 자산·자금·순위·발굴력 | 위 §1.1 헤더(자산·자금·순위3축·발굴력합·시즌) |
| **한 번의 조작으로 보인다** | 소장고·순위표·도감 | 아래 §1.3의 5탭(발굴/소장고/시설/시장/도감) + 순위표 상세 |
| **요청해야 보인다** | 규칙 화면·라이벌 상세·세이브 관리 | 위 항목 + 발굴단 개별 상세·시설 개별 상세·고용 시장 |

### 1.3 탭 구조 — 4탭에서 5탭으로, 7종을 그룹핑한다

7종을 그대로 7탭으로 늘리면 "탭 이동 최소화"(spec.md §3.1) 원칙이 무너진다.
**기능이 아니라 플레이어의 질문**을 기준으로 묶는다.

| 탭 | 묶는 도메인 | 플레이어의 질문 |
| --- | --- | --- |
| **발굴** | ①거점·세계지도 + ②발굴단·스텝 | "어디로, 누구를 보낼까" |
| **소장고** | ③감정소·보관소 | "뭘 갖고 있고, 뭐가 상태가 나쁜가" |
| **시설** | ④박물관 + ⑤경매장 | "내 건물들이 잘 돌아가는가" |
| **시장** | ⑥거래소 + ⑦암시장 | "지금 팔거나 살 만한 게 있는가" |
| **도감** | (변경 없음) | "얼마나 채웠는가" |

7종 → 5탭. `spec.md` §3.1의 데스크톱 "탭 이동 최소화, 1개 화면" 원칙과
모바일 하단 탭바 둘 다 5개면 아직 한 화면·한 손가락 폭 안에 들어온다(모바일
하단 탭 5개는 일반적인 앱 탭바 상한과 같다 — 6개부터 "더보기"로 밀린다).

## 4. `spec.md` §3.1.1 원칙의 신규 화면 적용 검사

원칙: "요소가 생기고 사라져도 버튼이 손가락 아래에서 바뀌지 않는다." v0.1은 소장고
그리드에 적용했다. 7종 확장으로 생긴 화면마다 같은 위험(리스트가 실시간으로
늘고 줄어든다)이 있는지, 있다면 대응이 있는지 검사한다.

| 화면 | 위험(요소가 실시간으로 생기고 사라지는가) | 대응 |
| --- | --- | --- |
| 세계지도 거점 목록 | 낮음 — 거점 12개는 게임 중 늘지 않는다(보유 여부만 바뀜) | 고정 순서(거리순/북마크순), 보유 여부는 카드 안 배지로만 표시. 순서 자체는 안 바뀐다 |
| 발굴단 리스트 | 있음 — 파견/귀환에 따라 상태가 바뀐다 | 팀은 `id` 고정 슬롯(최대 4칸)이라 팀 자체가 늘어도 기존 칸은 밀리지 않는다. 상태 배지만 바뀐다 |
| 박물관 전시 슬롯 | 있음 — 유물 반출입 | `spec.md` §10.5: 소장고와 같은 고정 칸 그리드. 슬롯 수(`MUSEUM_SLOT_BY_GRADE`)는 등급업 때만 바뀌고 전시 교체로는 안 바뀐다 |
| 경매장 등록 목록 | 있음 — 6시간마다 낙찰 | 낙찰된 슬롯은 빈 칸으로 유지되고 다음 등록 전까지 그 자리가 비어 있다(목록이 위로 당겨지지 않는다) |
| 거래소(유저간) 목록 | 있음 — 매칭 성사 시 사라짐 | 전역 목록이라 내 화면 기준으로는 "검색 결과"이므로 애초에 개인 슬롯이 아니다. 검색 결과 재정렬은 검색을 다시 실행했을 때만 일어나고, 결과를 보는 동안에는 고정한다(자동 새로고침 금지) |
| 암시장 12슬롯 | 있음 — 2시간마다 `BLACK_MARKET_RESTOCK_INTERVAL_HOURS` 리스톡 | 고정 12칸 그리드(`BLACK_MARKET_SLOT_CAPACITY = 12`). 리스톡은 매입 성사 시점에 그 칸만 갱신되고, 리스톡 주기가 됐다고 전체 그리드가 재배열되지 않는다 |
| 스텝 고용 후보 목록 | 낮음 — `STAFF_MARKET_REFRESH_HOURS = 24`마다만 바뀜 | 24시간에 1번이라 실시간 위험이 없다. 갱신 시점에만 3칸 전체가 교체된다(교체 자체를 숨기지 않는다 — 진행 중 교체는 없다) |
| 도감 | 변경 없음(v0.1과 동일, 480종으로 칸 수만 늘어남) | 기존 격자 배치 그대로. 신규 종은 격자 끝에 추가되고 기존 칸 위치는 안 바뀐다 |

**결론**: 위험이 있는 화면(발굴단·박물관 전시·경매장·암시장) 전부가 v0.1의
"고정 칸" 패턴(개별 슬롯이 상태만 바꾸고 위치는 유지)을 그대로 물려받아 대응이
있다. 새로 발명한 완화책은 없다 — v0.1의 원칙 하나가 7종 전부에 그대로 적용된다는
것 자체가 이 검사의 결론이다.

## 5. 모바일 세계지도 조작 — 별도 설계

데스크톱 지도(마우스 휠 줌 + 드래그 팬, 3단 줌)를 그대로 축소하면 실패한다 — 손가락은
마우스보다 두껍고, 좁은 화면에서 핀치줌 3단계를 오가는 동안 목표 거점을 놓치기
쉽다. 그래서 모바일에서는 **지도가 기본 진입점이 아니다.**

```
모바일 발굴 탭 (기본 화면 — 리스트 우선):
┌───────────────────────────────┐
│ ★ 즐겨찾기 (거리순)             │
│  경주 0.1h │ 교토 1.5h         │
├───────────────────────────────┤
│ 추천 3곳                       │
│  [예루살렘] [바그다드] [쿠스코]  │
├───────────────────────────────┤
│ 🔍 검색 ________________       │
├───────────────────────────────┤
│ 전체 거점 (거리순 리스트)        │
│  경주 ......... 0.1h  [파견]   │
│  교토 ......... 1.5h  [파견]   │
│  아테네........ 22h   [파견]   │
│  ...                          │
├───────────────────────────────┤
│        [🗺 지도로 보기]         │
└───────────────────────────────┘
```

리스트의 각 행이 이미 "파견" 버튼을 갖고 있어, 세계지도의 3단계(거점 선택→
발굴단 선택→확정)에서 "거점 선택" 단계를 리스트 탭 하나로 끝낸다. 지도는
**보조 시각화**로 밀려나 하단의 "지도로 보기" 버튼을 눌러야 전체화면 모달로
뜬다 — 거리·연결 관계를 눈으로 확인하고 싶을 때만 쓰는 화면이다.

```
모바일 지도 모달 (요청 시에만):
┌───────────────────────────────┐
│  ← 닫기            [세계|권역] │
│                                │
│      (핀치줌 가능, 3단 줌)      │
│                                │
│   ●경주    ●교토               │
│         ●아테네  ●이스탄불      │
│                                │
│  탭한 거점 → 하단 시트로 상세    │
└───────────────────────────────┘
```

지도 모달 안에서는 데스크톱과 동일한 3단 줌(`MAP_ZOOM_LEVELS = 3`)을 핀치로
지원하지만, 이게 **유일한 경로가 아니므로** 실패해도(핀치가 서투르거나 오조작해도)
뒤로 가서 리스트로 돌아가면 된다 — 지도가 막다른 길이 되지 않는다. 거점을 탭하면
지도 위에서 바로 파견하지 않고 **하단 시트**(리스트 화면과 같은 카드)로 넘겨
발굴단 선택·확정을 진행한다 — 지도 화면과 파견 확정 화면을 분리해, 확대된
지도 위의 작은 탭 영역에서 손가락으로 최종 확정을 누르다 오조작하는 사고를
없앤다.
