너는 `projects/relic-king`을 맡는다. 목표는 네 가지고, 넷 다 "검수 가능한 상태"로 끝내야 한다.

  G1. 12거점을 실제 해안선이 그려진 세계지도 위에 찍는다.
  G2. 마커가 실제 도시 위치와 맞는다.
  G3. 지도 탐색이 쉽다 — 데스크톱·모바일·키보드 모두.
  G4. 플레이어가 거점을 고르는 모든 경로에서 "실제 도시"가 이름으로 등장해 몰입을 만든다.
  G5. 위 넷이 하나의 디자인 언어로 보인다(색·타이포·마커 상태·여백이 화면마다 어긋나지 않는다).

## 1. 지금 상태 (확인된 사실 — 여기서 출발한다)

- 지도는 실제 해안선이 아니다. `worldmap.ts`의 `CONTINENT_POLYGONS`는 대륙 5개를 정점 7~10개
  짜리 손글씨 다각형으로 근사하고, 6칸 간격 샘플링으로 도트를 흩뿌린다. 남극·그린란드·
  동남아 도서부·일본 열도가 아예 없고, 일본 거점 마커는 바다 위에 뜬다.
- `worldmap.ts` 상단 주석은 "외부 네트워크가 차단돼 Natural Earth 파이프라인은 범위 밖"이라고
  적혀 있다. **이 전제는 지금 틀렸다.** npm 레지스트리는 열려 있다(검증: `npm view world-atlas
  version` → 2.0.2, `npm view topojson-client version` → 3.1.0). 빌드타임 devDependency로 받아
  정적 산출물로 굽는 것은 "런타임 외부 리소스 금지"를 위반하지 않는다. 주석도 같이 고쳐라.
- 12거점의 `lat`/`lon`은 이미 대부분 실제 도시 좌표다. 그런데 `name`은 나라 단위다
  (한반도·이집트·로마·멕시코…). 지도 라벨이 "이집트"인데 점은 룩소르에 찍혀 있다.
- **알려진 좌표 결함 1건**: `id: "rome"`은 `name: "로마"`, `anchor: "폼페이 유적"`,
  좌표 `40.85 / 14.27`이다. 이 좌표는 나폴리이고 로마는 `41.90 / 12.50`, 폼페이는
  `40.75 / 14.49`다. 이름·앵커·좌표 셋이 서로 다른 곳을 가리킨다.
- 탐색은 클릭 전용 2단 줌(세계 ↔ 권역 4배)이다. 키보드 조작·ESC·팬(드래그)이 없고,
  히트 반경은 캔버스 내부 좌표 10px(= CSS 축소 후 더 작아진다). 모바일에서 지도는
  "🗺 지도로 보기" 토글 뒤에 접혀 있다.
- 검증 수단: `tests/e2e/smoke.mjs`가 미리 깔린 크로미움을 CDP로 몰아 스크린샷을 찍는다
  (`08-worldmap`, `mobile-04-worldmap`). 레포 공용 `pnpm playtest`는 쓸 수 없다.

## 2. 작업

### A. 실제 해안선 — 빌드타임 베이크 (G1)

1. `scripts/build-worldmap.mjs`를 만든다. devDependency로 `world-atlas`(110m TopoJSON,
   퍼블릭 도메인)와 `topojson-client`를 `app/package.json`의 `devDependencies`에 추가한다.
   런타임 번들에 들어가면 안 된다 — 앱 진입점에서 import 되지 않는지 확인해라.
2. 파이프라인은 `world-map.md` §6 그대로다: land 지오메트리 → 정거방형 투영 → 320×160 그리드
   → 도트별 육지 비율이 `COASTLINE_LAND_THRESHOLD`(0.5)를 넘으면 육지 → 이진 비트맵.
3. 산출물은 `app/src/render/worldmap-raster.ts`에 정적 상수로 커밋한다. 320×160 비트를
   base64 문자열(6.4KB 이하)로 굽고 모듈 로드 시 1회 언팩해라. PNG data URL도 허용하지만
   비트마스크 쪽이 작고 권역 줌에서 리샘플하기 쉽다. 무엇을 골랐든 이유를 주석에 남겨라.
4. `CONTINENT_POLYGONS`·`WORLD_LAND_DOTS`·`pointInPolygon`·`drawContinents`를 삭제한다.
   구현을 남겨 둔 채 새 코드만 얹지 마라.
5. 권역 줌(4배)에서도 해안선이 보여야 한다. 지금은 `if (!zoom)` 가드 때문에 권역 줌 배경이
   맨 바다다 — 확대 크롭을 최근접 이웃으로 리샘플해 같은 해안선을 그려라. 도트가 4배로
   커지는 픽셀아트 확대이지, 벡터 재투영이 아니다(의도적이다. 픽셀 그리드를 유지해라).
6. 색은 `palette.ts`의 기존 40색에서만 고른다. 바다 `PALETTE.sky`, 육지는 `PALETTE.rock`/
   `soil` 계열에서 골라 알파로 눌러라. 새 색상 리터럴을 파일에 적으면 안 된다.

### B. 도시 정체성 — 나라가 아니라 도시를 부른다 (G2·G4)

1. `SiteDef`에 필드를 나눈다: `city`(도시명, 예 "경주"), `country`(나라, 예 "대한민국"),
   `anchor`(유적, 예 "경주 고분군"). 기존 `name`은 제거하고 호출부를 전부 옮기거나,
   `name`을 `city`의 별칭으로 남기더라도 **단일 소스는 하나**여야 한다. 둘 다 손으로 채우지 마라.
2. 12거점 전부 좌표를 검증하고, 좌표·도시·앵커가 같은 곳을 가리키게 맞춘다. 아래는
   현재 좌표가 실제로 가리키는 도시다. 표를 그대로 믿지 말고 각 항목을 확인한 뒤 확정해라.

3. **좌표를 옮기면 `distanceKm`이 바뀌고 원정 시간이 바뀐다.** rome 좌표 이동은 거리 변화가
   30km 남짓이라 무해할 가능성이 높지만, 확인 없이 넘어가지 마라. `pnpm --filter relic-king sim`
   을 좌표 변경 전후로 돌려 엔딩 도달 시간 차이를 `eval.md` 측정표에 기록해라. 유의미하게
   바뀌면(±1시간 초과) 좌표 대신 이름을 도시에 맞추는 쪽을 택하고 그 판단을 근거와 함께 적어라.
   밸런스 상수(`balance.ts`)는 이 작업에서 건드리지 않는다.
4. 표시 규칙을 하나로 정하고 전 화면에 적용한다. 권장: **1차 = 도시명, 2차 = 앵커 유적,
   3차 = 나라**. 예) 파견 시트 제목 `룩소르 — 왕가의 계곡`, 부제 `이집트 · 편도 3,140km`.
   `name`을 쓰는 호출부는 전부 이 규칙을 따라야 한다. 최소 다음을 손봐라:
   `DispatchSheet`(제목), `WorldExplorer`(목록·검색·즐겨찾기 칩), `ExpeditionView`,
   `TeamPanel`(이동/발굴 상태줄·재파견·루틴), `Header`(다음 드랍), `CodexView`,
   `VaultView`(전시·경매), `OfflineSummary`, `OnboardingOverlay`, `RulesModal`,
   `engine.ts`의 로그 문자열 2곳. 빠뜨린 곳이 없는지 `grep -rn "\.name" app/src/ui`로 훑어라.
5. 검색은 도시명·나라명·앵커·유물 종류 넷 모두에 걸려야 한다("이집트"로 검색해도 룩소르가
   나와야 한다. 나라 이름을 지웠다고 검색어에서까지 지우면 플레이어가 길을 잃는다).
6. 조사 어미 처리에 주의해라. 기존 코드는 `josa()` 헬퍼를 쓴다. "룩소르로/이스탄불로",
   "경주에서/시안에서"가 자연스럽게 나오는지 실제 12개 문자열을 눈으로 확인해라.

### C. 네비게이션 (G3)

1. 키보드: Tab으로 마커 순회(거리순), Enter로 선택, ESC로 권역 줌 해제. 캔버스만으로는
   포커스를 못 받으니 마커마다 투명 버튼을 얹은 오버레이 레이어를 두거나,
   `role="application"` + `aria-activedescendant`로 처리해라. 스크린리더용 대체 텍스트는
   "도시명 · 상태 · 거리"를 읽어야 한다.
2. 히트 영역: CSS 표시 크기 기준 최소 44×44px. 지금은 캔버스 내부 좌표 10px 반경이라
   축소 렌더 시 실제 탭 영역이 훨씬 작다. 캔버스 스케일을 역산해서 반경을 잡아라.
3. 현재 위치 표시: 본거지·발굴단 위치·라이벌 추격을 지도 밖 범례(legend)로도 읽을 수 있게
   한다. 색만으로 구분하면 안 된다 — 모양이나 라벨을 같이 준다(색각 이상 대응).
4. 모바일: 지도가 토글 뒤에 숨은 구조는 유지하되, 펼쳤을 때 세로 화면에서 12개 마커가
   전부 보이고 탭 가능해야 한다. 가로 스크롤 금지.
5. **"거점 선택 3단계 이내" 규칙(§7)을 깨지 마라.** 줌을 추가하면서 파견까지의 클릭 수가
   늘면 그건 퇴보다. 현재는 세계 줌에서 마커 탭 → 권역 줌에서 다시 탭 → 시트다.
   이 흐름을 유지하거나 줄여라.

### D. 디자인 일관성 (G5)

1. 마커 상태는 base / visited / unvisited / selected / rival-target 다섯 가지다.
   각각의 색·크기·외곽선을 한 곳(`worldmap.ts` 상단 상수 블록)에 모으고, 지도 밖 UI의
   같은 의미 표기(목록의 "base" 뱃지 등)와 색을 맞춰라.
2. 타이포: 지도 라벨은 현재 `9px monospace`다. 앱 나머지가 쓰는 폰트 스택과 맞는지
   `styles.css`를 확인하고 어긋나면 맞춰라. 도시명이 길어졌으므로(멕시코시티) 라벨 충돌
   회피 후보 배치가 여전히 성립하는지 확인해라 — 지금 로직은 16개 후보 위치를 그리디로 고른다.
3. 라벨을 생략하는 분기(`if (!placement) continue`)가 도시명 확대 후 더 자주 터질 수 있다.
   터진다면 후보를 늘리지 말고, 권역 줌에서만 전체 라벨을 보이고 세계 줌에서는 밀집 지역을
   묶어 표시하는 쪽을 검토해라. 판단 근거를 주석에 남겨라.

## 3. 하지 말 것

- 런타임에 타일 서버·CDN·폰트 등 외부 리소스를 요청하는 것. 빌드타임 베이크만 허용된다.
- `palette.ts` 40색 밖의 새 색 추가.
- `balance.ts`의 밸런스 상수 변경. 지도 렌더 상수(`MAP_*`)는 필요하면 조정하되 이유를 남겨라.
- 게임 로직을 `app/src/ui/`에 넣는 것. 엔진은 `app/src/game/`에서 React 없이 단독으로 돈다.
- 티어·희소성 조작. 척추 1번(현실의 현존 개체 수 = 공급량)은 이 작업과 무관하니 손대지 마라.
- 구현을 남겨 둔 채 새 코드만 얹는 것. 대체한 코드는 지운다.

끝내면 이렇게 보고해라:

- 무엇이 바뀌었는지 3줄.
- 검증 체크리스트 결과(통과/실패, 실패면 왜).
- 판단이 갈렸던 지점과 고른 쪽, 트레이드오프(특히 rome 좌표, 라벨 생략 정책).
- 하지 못한 것과 이유. 조용히 빼지 마라.
