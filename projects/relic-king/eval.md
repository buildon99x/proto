# Evaluation — 유물왕

> v0.1 검증 결과. 측정은 헤드리스 시뮬(`pnpm --filter relic-king sim`)과
> 실시간 스모크(`node tests/e2e/smoke.mjs`)로 한다. 마지막 측정: 2026-09-17.

## 1. 자동 검증

| 항목 | 방법 | 결과 |
| --- | --- | --- |
| 타입체크 + 빌드 | `pnpm --filter relic-king build` | ✅ 무오류 |
| 앱이 뜨고 방치로 진행된다 | `node tests/e2e/smoke.mjs --seconds 45` | ✅ 45초 방치 후 도감 2점 |
| 네 탭이 모두 렌더된다 | 스모크 3~5단계 | ✅ 소장고·세계·도감 |
| 콘솔/페이지 오류 0건 | 스모크 CDP 로그 | ✅ 0건 |
| 세계 원장 보존 | 시뮬 종료 시 전수 검사 | ✅ `획득 합 + 잔여 == 총량`, T4 중복 소유 0 |
| 오프라인 적분이 스텝 크기와 무관 | 1초 스텝 vs 10초 스텝, 1시간 | ✅ 드랍 횟수·층·진척 완전 일치 |

진척 적분은 결정론이므로 **드랍 횟수와 층**을 비교한다. 어떤 유물이 걸리느냐는 난수라
비교 대상이 아니다 — 처음엔 자산으로 비교했다가 52% 차이가 나 측정 자체가 틀렸음을 알았다.

- [ ] 세이브 왕복(export → 초기화 → import) 자동 검증 — 현재는 수동 확인만 했다.
- [ ] 마이그레이션 체인 — v1이 유일한 버전이라 아직 검증할 대상이 없다.

## 2. 밸런스 (클릭 0회, 방치 기준선)

| 기준 | 목표 | 측정 |
| --- | --- | --- |
| 첫 유물 드랍 | 40초 이내 | **12초** |
| 초기 20분 평균 드랍 간격 | 300초 이하 | **1.2초** |
| 2권역(이집트) 해금 | — | 9분 |
| 3권역(로마) 해금 | — | 54분 |
| 첫 국보(T3) | — | 17분 |
| 엔딩(자산 1위 + 도감 75%) | 1~2시간 | **1시간 0분** |
| 클릭 최대 활용 시 진행 속도 | ×1.35 이하 | **×1.35** (상한에 정확히 물림) |
| 추격 계수 | ×2.0 이하 | 최대 ×1.27 관측 |

클릭 이득은 **자산비가 아니라 진척 속도**로 잰다. 방치형은 성장이 지수적이라 진척 1.35배가
자산비로는 2배 넘게 부풀려 보인다 — 처음 측정에서 ×2.07이 나와 기준을 잘못 잡았음을 알았다.

## 3. 상실 규칙 (설계 원칙의 방어선)

| 기준 | 결과 |
| --- | --- |
| 오프라인 12시간 시뮬에서 T3·T4 상실 | ✅ **0건** |
| 유일 유물은 제보 레이스 밖에서 라이벌에게 넘어가지 않는다 | ✅ 엔진에서 티어 상한으로 강제 |
| 제보를 무시해도 흔함~진귀는 완주 가능하다 | ✅ 제보는 드랍 가중일 뿐 진행 조건이 아니다 |

- [ ] 제보 대응 시 승률이 미대응 대비 유의하게 높은지 — 통계 측정 미구현.
      (현재는 대응 시 롤당 28%, 라이벌 10%로 구조상 우위가 보장된다)

## 4. 데이터 검증 (실존성) — **미완**

전제가 "실존 유물"이므로 이 항목이 틀리면 게임의 근거가 무너진다.
현재 실행 환경은 외부 네트워크가 차단돼 있어(박물관 오픈액세스 API 403) 1차 자료 대조를
하지 못했다. 데이터는 [notes/artifacts-dataset.md](notes/artifacts-dataset.md) 기준 초안이다.

- [ ] 60점 전체의 `holder`(현 소장처)를 소장 기관 공식 자료로 확인.
- [ ] **T4 8점 전부**가 실제로 단일 개체인지 확인.
- [x] 훈민정음 해례본은 상주본 쟁점 때문에 T4에서 **T3로 내렸다**. 애매하면 흔한 쪽으로.
- [x] 반환 논쟁 유물에 `disputed` 표기 — 로제타 석에 적용.
- [x] 도감 하단에 "평가액은 가상 단위" 문구 상시 노출.
- [ ] 연대와 권역·층 구성이 어긋나는 항목 점검.

## 5. 수동 체크리스트

- [x] 방치만으로 진행되고, 클릭은 가속으로만 작동한다.
- [x] 지층 단면이 진척에 따라 내려가고 층마다 흙 색과 연대가 바뀐다.
- [x] 유물을 팔면 자금이 오르고 순위가 내려간다(자산 = 소장 유물 평가액 합).
- [x] 미감정 매각이 추정가의 70%로 동작하고, 자금 부족 시 감정 대기를 UI가 알린다.
- [x] 제보 배너가 카운트다운과 이동 버튼을 띄운다.
- [x] 도감이 미발견(실루엣) / 소장(컬러) / 소실(회색 + 소유자)을 구분한다.
- [x] 복귀 요약이 라이벌 활동을 포함해 손실을 숨기지 않는다.
- [x] 세계 탭에서 확률표·추격 계수 공식·오프라인 규칙을 볼 수 있다.
- [x] 티어를 색만으로 구분하지 않는다(테두리 두께 + 배지 기호).
- [ ] 실제 모바일 기기에서 4탭과 지층 화면 확인 — 헤드리스 뷰포트만 확인했다.

## 6. 재미 가설 (플레이테스트 미실시)

설계가 목표한 세 문장이 실제로 발생하는지는 **사람이 플레이해야 알 수 있다.** 미검증.

- [ ] T4 획득 직후 소장고·도감을 다시 여는가.
- [ ] 제보 배너가 뜨면 방치를 깨고 개입하는가. 개입률 30% 미만이면 제보 설계 실패.
- [ ] 유물 내력을 끝까지 읽는가.
- [ ] 팔지 말지 망설이는 순간이 세션당 1회 이상 나오는가.

## 7. 알려진 한계

- 라이벌은 NPC 시뮬이다. "사람과 겨룬다"는 감각은 약하다.
- v0.3(거래) 이전까지 영구 상실은 회복 경로가 없다. 그래서 상실 경로를 레이스 하나로 좁혔다.
- 도트 스프라이트는 절차 생성이라 실물 재현도가 낮다. 실존성은 텍스트가 담보한다.
- 레포 공용 `pnpm playtest`는 puppeteer가 크롬을 내려받아야 해서 이 환경에서 쓸 수 없다.
  대신 미리 깔린 크로미움을 CDP로 직접 모는 `tests/e2e/smoke.mjs`를 썼다.
