# 유물왕 — 프로젝트 지침

Prototype Lab 개별 프로젝트. 레포 공통 규칙은 루트 `AGENTS.md`를 따르고, 아래는 이 프로젝트에만 해당한다.

## 이 게임의 척추 — 건드리기 전에 읽을 것

1. **현실의 현존 개체 수 = 게임 공급량.** 밸런스를 위해 티어를 지어내지 않는다.
   유일(T4)을 늘릴 때는 정말 하나뿐인지 확인한다. 애매하면 흔한 쪽으로 내린다.
2. **깊이는 유물의 희소성만 열고, 수입은 발굴력에서만 나온다.** 드랍 임계가 층 기대
   평가액에 묶여 있는 이유다. 이걸 풀면 `깊이 × 발굴력`이 곱해져 즉시 폭주한다.
3. **영구 상실은 플레이어가 그 자리에 있었을 때만.** 라이벌은 제보 레이스 밖에서 유일을
   뽑지 못하고, 오프라인 중에는 진귀 이하만 가져간다. 거래(v0.3)가 들어오기 전까지
   이 규칙은 협상 대상이 아니다.
4. **클릭은 언제나 선택.** 모든 밸런스는 클릭 0회 기준이고, 클릭 진척에는 상한이 있다.
   **"선택이 없다"는 뜻이 아니다** — v0.6부터 제보 레이스는 아무것도 안 누르면
   라이벌과 **반반**이고(`TIP_RIVAL_HIT` = `TIP_PLAYER_HIT` = 28%), 집중 굴착을
   누르면 60%가 된다. 져도 진척·자금·도감은 깎이지 않는다. 결정이 있다는 것과
   조작을 요구한다는 것은 다른 명제다(`notes/decisions.md` G85).
5. **규칙은 공개한다.** 확률표·추격 계수·오프라인 효율을 숨기지 않는다.
   v0.1 실코드는 세계 탭에서 이걸 보여준다(`ui/WorldView.tsx`). v0.2 설계는
   탭 구조를 5탭(발굴/소장고/시설/시장/도감) + 헤더 상시 아이콘 2개(⚙ 설정·세이브,
   📋 규칙)로 바꾸므로 규칙 공개 화면은 "📋" 아이콘 뒤로 옮겨 간다
   (`notes/ux-v02.md` §1.4). **어느 화면이든, 숫자를 바꾸면 그 화면도 같이
   맞춰야 한다는 원칙 자체는 바뀌지 않는다.**

## 명령

```
pnpm --filter relic-king dev         개발 서버
pnpm --filter relic-king build       타입체크 + 빌드
pnpm --filter relic-king sim         헤드리스 밸런스 시뮬 (--hours N [--ghosts N])
pnpm --filter relic-king smoke       실시간 브라우저 스모크 + 스크린샷
pnpm --filter relic-king play        실제 앱을 사람처럼 조작하는 UI 검사 (시나리오 12종)
pnpm --filter relic-king playlog     플레이 계측 — 이벤트 타임라인·조작 노력 (--hours N, --bucket N분)
pnpm --filter relic-king density     밀도 원장 — 첫 60초 5초 격자·첫 10분 30초 격자, 5시드 중앙/최악 (--seeds N, --tail-minutes N)

pnpm --filter relic-king qa:sprites     아이콘 중복·거점 구분력·유일 12종 분리
pnpm --filter relic-king qa:rivalcard   기록패·고스트 단위 검증(왕복·적대적 입력·격리)
pnpm --filter relic-king qa:migration   세이브 마이그레이션 v1~v11
pnpm --filter relic-king qa:bulk        소장고 다중 선택 처분(대상 선정·도감 보존·경매 자리)
pnpm --filter relic-king sheets         컨택트 시트 굽기 → assets/generated/

node scripts/build-worldmap.mjs           세계지도 해안선 베이크(생성 파일을 다시 굽는다)
node scripts/build-worldmap.mjs --check   커밋된 산출물이 최신인지만 검사
```

**작업 브랜치가 플레이를 어떻게 바꿨는지 보고할 때**는 `.claude/skills/play-delta-report`를
쓴다. 전·후 커밋을 워크트리로 꺼내 같은 계측기(12시드 `density` + `play` UI 실측)로 다시 재고
한 페이지 보고서로 굽는다. 옛 문서의 숫자를 옮기지 않기 위한 절차다.

**아이콘을 건드렸으면 `qa:sprites`를 돌리고 `sheets`로 구운 컨택트 시트를 눈으로
본다.** 스프라이트 결함은 화면에서 안 보인다 — v0.3까지 `statue` 종 1,900여 개가
"머리 + 바닥 막대"로만 그려지고 있었는데 어떤 QA도 잡지 못했고, 컨택트 시트를
처음 구운 날 드러났다(notes/decisions.md G69).

**밸런스 상수를 건드렸으면 `sim`을 돌리고 eval.md의 측정표를 갱신한다.** 방치형은
눈으로 봐서 알 수 없다 — 첫 구현은 20분 만에 발굴력 194만/s가 나왔는데 화면상으론 멀쩡했다.

**페이싱을 건드렸으면 `density`로 밀도 원장을 같이 재라.** 168시간 지표도, 첫
10시간 지표도 첫 1분을 보지 못한다 — `playlog --bucket`은 분 단위라 첫 60초가 한
칸으로 뭉개진다. 원장 다섯 축(사건 **종류** · 결정 · 긴장 · 반복:의미 · 첫 도달
시각)을 전·후로 나란히 찍고, **전 값은 그 자로 직접 재라**(옛 문서의 숫자를
옮겨 적지 마라 — v0.6에서 §1의 v0.3.4 값과 실제 v0.5.1 값이 달랐다).
**시드 1개로 판정하지 않는다** — 첫 10분은 시드 흔들림이 가장 큰 구간이라
중앙값과 최악값을 같이 적는다. **기본 5시드로도 판정하지 마라**: v0.6이 5시드로
"미달 3축"이라 적은 것을 12시드로 다시 재니 **6축**이었다. 판정은
`density --seeds 12`로 하고, 통과하면 24·48시드로 확인한다. **최악값이 시드 수에
따라 움직이면 그 축은 아직 구조가 아니다** — 확률로 맞춘 축은 시드를 늘리면
무너지고 구조로 닫은 축은 버틴다(`notes/decisions.md` G90, `eval.md` §28.5).

**곡선을 압축하면 잠복한 스텝 의존성이 깨어난다.** v0.6에서 깊이를 8배 당기자
v0.5.1에서 한 번도 발화하지 않던 결함 넷이 한꺼번에 나왔다 — 원정 귀환이 청크
끝을 파견 시각으로 쓰던 것, 드랍을 마지막 층 기준으로만 소진하던 것, 라이벌이 매
스텝 재투자하던 것, 그리고 원정비가 10배로 뛴 것. **`advance()` 안에 시각 분기나
난수 소비를 새로 만들지 마라** — `autoInvestLegacyDig`·`redeployIdleRoutineTeams`가
`advance()` 밖에 있는 이유가 그것이다. `sim`의 "오프라인 적분 스텝 무관"과
`qa:expedition`이 이 경계를 지킨다.

**UI를 건드렸으면 `play`를 돌린다.** 엔진이 옳다는 것과 플레이어가 겪는 게임이
옳다는 것은 다른 명제다. v0.3.2가 찾은 결함 6건 중 4건은 **엔진이 완벽히 정상인
채로** 일어났다 — 배경 탭에 둔 시간이 통째로 사라지고, 제보 배너가 "반응할
발굴단이 없다"고 거짓말하고, 유일 유물을 손에 넣는 순간에 아무 연출도 나지 않았다.
어떤 헤드리스 시뮬로도 잡을 수 없는 종류다(`eval.md` §22, `notes/decisions.md` G77).

**"클릭 0회"는 조작 0회가 아니다.** 척추 4번의 "클릭"은 삽질 클릭(진척 가속)을
뜻한다. 엔딩까지 가는 플레이는 v0.3.3 계측에서 **334회·879단계**의 운영 조작을
요구했고 그 64%가 경매 출품 하나였다 — v0.3.4가 그 출구를 자동화해
**143회·309단계**로 줄였다. v0.6의 압축 뒤에는 완주 기준 **약 184회**이고, 그중
**절반이 발굴단 증강**이다(G80.1이 미적용으로 남겨 둔 바로 그 항목 — 다음 패스의
1순위). 시간당으로 읽으면 압축 때문에 더 나빠 보이므로, **조작량은 "하루 몇 회"가
아니라 "완주까지 몇 회"로 적어라**(`eval.md` §27.7). 반대편 극단인 **탭만 열어 둔
플레이**는 v0.3.3에서 2일차부터 죽어 있었다(도감 125/1,902종에서 정지) — v0.3.4의
시작 발굴단·자동 순회로 살아났고, v0.6에서 첫 10시간 도감이 126 → **470종**이 됐다.
페이싱·자동화를 건드릴 때는 `pnpm playlog`·`pnpm density`로 **두 극단을 같이** 재고
`eval.md` §23·§24·§27 표를 갱신한다.

**168시간 지표가 좋아져도 첫 10시간은 따로 재라. 첫 10시간이 좋아져도 첫 1분은
또 따로 재라.** v0.3.4의 시작 발굴단·자동 순회는 168시간 스케일에서 방치 플레이를
되살렸지만, `--bucket 10`으로 첫 10시간을 보면 **그 발굴단이 35.3시간째 이동 중**
이라 첫 세션에는 없는 것과 같았다. 그리고 그 첫 10시간 지도조차 첫 1분은 못 봤다
— v0.5.1의 첫 1분에 일어나는 의미 있는 사건은 **한 종류**뿐이었고, 그건
`density`로 5초 격자를 찍고 나서야 보였다(`notes/play-first-10h-v06.md`,
`eval.md` §27). **해상도를 올릴 때마다 새 결함이 나온다.**

**테스트가 깨지면 전제부터 의심한다.** v0.3.4의 처방 하나(시작 발굴단)가
`qa_migration`·`qa_expedition`·`play` 5곳·`smoke` 1곳을 깼는데, 전부 **단언이
틀린 게 아니라 전제가 낡은** 경우였다. 단언을 느슨하게 해서 통과시키지 말고,
사람이 실제로 그 조작을 마주하는 조건을 만들어 다시 재라
(`notes/decisions.md` G80.2).

## 환경 제약

- **런타임에 외부 리소스를 받지 않는다.** 이건 협상 대상이 아니다 — 타일 서버·CDN·폰트·API
  전부. 유물 도트는 절차 생성이다.
- **빌드타임은 다르다.** "외부 네트워크가 차단돼 있다"는 기록은 박물관 오픈액세스 API
  403 하나에서 나왔는데, 실제로는 절반만 맞다: API는 막혀 있지만 `raw`/`media`
  githubusercontent와 **npm 레지스트리는 열려 있다**(`notes/decisions.md` G59·G75.1).
  이 전제를 잘못 넓게 읽어 두 번 실기했다 — 유물 데이터 확대(G59)와 세계지도
  해안선(G75.1)이 각각 "불가능"으로 미뤄져 있었다. **받아서 정적 산출물로 구워 커밋하는
  것은 허용이고, 그 경로로 들어온 산출물이 이미 둘 있다**(`artifacts.generated.ts`,
  `render/worldmap-raster.ts`). 막혔다고 적기 전에 실제로 한 번 찔러 봐라.
- 레포 공용 `pnpm playtest`는 puppeteer가 크롬을 내려받아야 해서 쓸 수 없다. 대신
  미리 깔린 크로미움을 CDP로 직접 모는 `tests/e2e/smoke.mjs`를 쓴다.

## 구조

- `app/src/game/` — 순수 TypeScript 엔진. React 없이 단독으로 돌고, 시뮬도 같은 코드를 탄다.
- `app/src/render/` — 팔레트, 절차적 스프라이트 생성기, 지층 캔버스, 세계지도.
  `worldmap-raster.ts`는 **생성 파일이다** — 손으로 고치지 말고 `scripts/build-worldmap.mjs`를
  다시 돌려라.
- `app/src/ui/` — React 셸. 게임 로직을 여기에 두지 않는다.
- `app/src/sim/` — 헤드리스 시뮬. 앱 번들에는 포함되지 않는다(진입점에서 import 하지 않음).

## 플레이어 간 경쟁(v0.5) — 건드리기 전에 읽을 것

기록패(`app/src/game/rivalcard.ts`)는 **서버 없이** 상태를 주고받는 유일한 통로다.
설계 근거는 `notes/decisions.md` G76, 규격은 `spec.md` §13.5, 실측은 `eval.md` §21.
아래 넷은 전부 "받으면 손해"를 막는 장치다 — 하나라도 풀면 아무도 기록패를 주고받지
않게 되고, 기능 자체가 죽는다.

1. **고스트는 내 원장을 비우지 않는다.** 기록패가 주장하는 유일 소장도, 고스트의
   배경 발굴(`shadowTake`)도 마찬가지다. 유물을 걸고 다투는 자리는 **제보 레이스
   하나**다.
2. **고스트는 재투자하지 않는다.** 기록된 페이스로만 자란다. NPC 재투자 루프를
   태웠더니 9,423/s가 4,243,517/s가 됐다.
3. **엔딩 판정에 고스트는 들어가지 않는다.** 순위표에는 보이고 엔딩에는 안 센다 —
   이미 완주한 친구의 기록패 하나가 내 완주를 영구히 막으면 안 된다.
4. **체크섬은 보안 장치가 아니다.** 위조는 이 구조에서 막을 수 없다. 방어선은
   모든 필드의 상한과 위 1~3의 격리다.
